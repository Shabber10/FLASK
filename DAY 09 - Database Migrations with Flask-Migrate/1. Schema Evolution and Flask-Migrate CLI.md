## 1. Initializing Flask-Migrate in Python

To enable database migrations in your Flask application, import and instantiate `Migrate`:

```python
from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate

app = Flask(__name__)
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///app.db'
app.config['SQLALCHEMY_TRACK_MODIFICATIONS'] = False

db = SQLAlchemy(app)

# Bind Flask-Migrate extension to Flask app and SQLAlchemy db
migrate = Migrate(app, db)
```

## 2. Complete `flask db` CLI Command Reference

Once `Migrate(app, db)` is initialized, Flask exposes the `flask db` command group in your terminal:

```
+───────────────────────┬─────────────────────────────────────────────────────────────+
| CLI Command           | Operation & Description                                     |
+───────────────────────┼─────────────────────────────────────────────────────────────+
| flask db init         | Initializes the `migrations/` directory structure.          |
|                       | (Run ONCE when starting a project).                         |
+───────────────────────┼─────────────────────────────────────────────────────────────+
| flask db migrate -m   | Autogenerates a revision script inside                      |
| "add_phone_field"     | `migrations/versions/` by comparing models against DB.     |
+───────────────────────┼─────────────────────────────────────────────────────────────+
| flask db upgrade      | Applies all unapplied migration scripts to the DB engine.   |
+───────────────────────┼─────────────────────────────────────────────────────────────+
| flask db downgrade    | Reverts the single most recent migration step on the DB.    |
+───────────────────────┼─────────────────────────────────────────────────────────────+
| flask db current      | Displays the active migration revision hash on the DB.      |
+───────────────────────┼─────────────────────────────────────────────────────────────+
| flask db heads        | Displays the latest migration script revision hash in code. |
+───────────────────────┼─────────────────────────────────────────────────────────────+
| flask db history      | Shows chronological list of all migration revisions.        |
+───────────────────────┼─────────────────────────────────────────────────────────────+
| flask db stamp <hash> | Forces the database version table to point to a specific    |
|                       | revision hash without executing migration scripts.          |
+───────────────────────┴─────────────────────────────────────────────────────────────+
```

## 3. Standard Migration Lifecycle Workflow

Follow this step-by-step developer workflow whenever you modify a model class:

```
 ┌────────────────────────────────────────────────────────┐
 │ 1. Edit Python model code in your Flask application.  │
 │    (e.g., add bio = db.Column(db.String(200)))         │
 └───────────────────────────┬────────────────────────────┘
                             │
                             v
 ┌────────────────────────────────────────────────────────┐
 │ 2. Run: `flask db migrate -m "Add bio to User model"`  │
 │    (Generates new script in `migrations/versions/`)    │
 └───────────────────────────┬────────────────────────────┘
                             │
                             v
 ┌────────────────────────────────────────────────────────┐
 │ 3. Inspect generated script in `migrations/versions/`. │
 │    Verify upgrade() and downgrade() functions.         │
 └───────────────────────────┬────────────────────────────┘
                             │
                             v
 ┌────────────────────────────────────────────────────────┐
 │ 4. Run: `flask db upgrade`                             │
 │    (Executes SQL ALTER TABLE on database).             │
 └────────────────────────────────────────────────────────┘
```
