## 1. What is a Database Migration in Plain English?

A **Database Migration** is like **Git version control** for your database tables.

Just like Git records commits (`v1`, `v2`, `v3`) for your source code, a migration tool records version checkpoints (`rev_001`, `rev_002`) for your database structure!

```
+─────────────────+         Migration 001         +─────────────────+
| Table: users    | ────────────────────────────> | Table: users    |
|  - id           |     Add `phone_number`        |  - id           |
|  - username     |       (Keeps live data!)      |  - username     |
|  - email        |                               |  - email        |
+─────────────────+                               |  - phone_number |
                                                  +─────────────────+
```

## 2. Why `db.create_all()` Fails in Production Apps

When starting out with Flask, `db.create_all()` seems easy. But here is the major problem:

> ⚠️ **The `db.create_all()` Limitation**:
> `db.create_all()` only creates tables if they **do not exist yet**. 
> If the `users` table already exists in your database and you add a `phone_number` column to your Python model, `db.create_all()` will **do absolutely nothing**!
>
> The only way to force `db.create_all()` to add the new column is to drop the existing `users` table—which **wipes out all your real user data forever**! 😱

Database migrations solve this by modifying existing tables live using SQL `ALTER TABLE` statements!

---

## 3. What are Alembic and Flask-Migrate?

*   **Alembic**: The official database migration engine built for SQLAlchemy. It compares your Python model classes against your live SQL database tables and autogenerates migration scripts.
*   **Flask-Migrate**: A lightweight Flask extension that connects Alembic into your Flask application and gives you easy command-line interface (CLI) tools under `flask db`.

---

## 4. The 4 Essential Migration Commands (`I-M-U-D`)

Managing database migrations involves 4 standard CLI commands:

```
1. flask db init
   Run ONCE per project to create the `migrations/` folder.

2. flask db migrate -m "Add phone number to users"
   Compares models vs DB and creates a new migration script inside `migrations/versions/`.

3. flask db upgrade
   Applies pending migration scripts to your active database (upgrades DB schema).

4. flask db downgrade
   Rolls back the last applied migration step (downgrades DB schema if something breaks).
```
