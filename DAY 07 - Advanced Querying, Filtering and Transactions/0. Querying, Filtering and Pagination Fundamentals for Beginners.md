## 1. What is Database Querying & Filtering in Plain English?

In web applications with millions of items (like Amazon or Netflix), users rarely want to view *every single item* at once. They want to filter items by specific criteria:
*   *"Show products under $50"* (`filter(Product.price < 50)`)
*   *"Find users whose name starts with 'Alex'"* (`filter(User.name.like('Alex%'))`)
*   *"List orders placed in the last 7 days"* (`filter(Order.created_at >= week_ago)`)

**Querying** is the process of asking the database questions, and **Filtering** is narrowing down the results based on strict conditions.

---

## 2. Common SQLAlchemy Filter Operators Table

| Operator | Meaning | SQLAlchemy Syntax Example | SQL Equivalent |
| :--- | :--- | :--- | :--- |
| **`==`** | Equals | `User.query.filter(User.role == 'admin')` | `WHERE role = 'admin'` |
| **`!=`** | Not Equals | `User.query.filter(User.status != 'banned')` | `WHERE status != 'banned'` |
| **`>` / `<`** | Greater / Less than | `Product.query.filter(Product.price < 50)` | `WHERE price < 50` |
| **`like()`** | Pattern matching (case-sensitive) | `User.query.filter(User.email.like('%@gmail.com'))` | `WHERE email LIKE '%@gmail.com'` |
| **`ilike()`** | Pattern matching (case-insensitive) | `User.query.filter(User.name.ilike('%shabber%'))` | `WHERE name ILIKE '%shabber%'` |
| **`in_()`** | Value matches item in list | `User.query.filter(User.id.in_([1, 2, 3]))` | `WHERE id IN (1, 2, 3)` |
| **`between()`** | Range check | `Product.query.filter(Product.price.between(10, 100))` | `WHERE price BETWEEN 10 AND 100` |

## 3. Combining Logical Filters (`and_`, `or_`, `not_`)

When filtering by multiple conditions:

```python
from sqlalchemy import and_, or_, not_

# Find Active Users who are EITHER Admins OR Editors
users = User.query.filter(
    and_(
        User.is_active == True,
        or_(User.role == 'admin', User.role == 'editor')
    )
).all()
```

## 4. Why Pagination is Crucial for Performance

If your database contains 500,000 products, fetching all records with `.all()` will freeze your server, exhaust RAM, and crash browser tabs! 💥

**Pagination** splits large query result sets into small, manageable chunks (pages):

```python
# Fetches Page #2 with 20 items per page
paginated_products = Product.query.paginate(page=2, per_page=20, error_out=False)

# Pagination Metadata:
print(paginated_products.items)       # List of 20 products for current page
print(paginated_products.total)       # Total count (e.g. 500,000)
print(paginated_products.pages)       # Total pages (e.g. 25,000)
print(paginated_products.has_next)    # True if next page exists
```

## 5. Database Transactions & Rollbacks (`db.session.rollback()`)

A **Database Transaction** is a sequence of database operations treated as a single atomic unit. All operations must succeed together, or NONE of them take effect!

> 🏦 **Bank Transfer Analogy**: Imagine transferring $100 from Account A to Account B:
> 1. Deduct $100 from Account A.
> 2. Add $100 to Account B.
> If step 2 fails due to a server crash, step 1 must be **rolled back** (`db.session.rollback()`), otherwise $100 vanishes into nowhere!
