### Q1: What is the difference between `like()` and `ilike()` in SQLAlchemy query expressions?
**Answer**:
- `like()`: Executes a case-sensitive SQL `LIKE` operator search. Pattern `'python'` will match `'python'`, but will NOT match `'Python'` or `'PYTHON'`.
- `ilike()`: Executes a **case-insensitive** SQL search (wrapping column in `LOWER()` where needed). Pattern `'%python%'` will match `'Python'`, `'PYTHON'`, and `'PyThOn'`.

### Q2: How does `db.paginate()` calculate the total page count under the hood?
**Answer**:
`db.paginate(stmt, page, per_page)` executes two SQL queries:
1. It modifies `stmt` by adding `LIMIT per_page OFFSET (page - 1) * per_page` to retrieve the current page items.
2. It constructs a secondary `SELECT COUNT(*)` query based on `stmt` to count the total matching rows in the table. 

Using total items $T$ and per-page size $P$, total pages is computed as $\lceil T / P \rceil$.

### Q3: What is the difference between `WHERE` and `HAVING` clauses in SQL queries?
**Answer**:
- `WHERE`: Filters individual table rows **before** any grouping or aggregation takes place.
- `HAVING`: Filters aggregated groups **after** `GROUP BY` has collapsed rows.

```python
# Select categories with average price > 100 where stock > 0
stmt = db.select(
    Product.category,
    func.avg(Product.price)
).where(Product.stock > 0).group_by(Product.category).having(func.avg(Product.price) > 100)
```

### Q4: How do you perform multi-column ordering in SQLAlchemy 2.0?
**Answer**:
Pass multiple column expressions to `.order_by()`:

```python
stmt = db.select(Product).order_by(
    Product.category.asc(),
    Product.price.desc()
)
```

This orders results by Category alphabetically, and within each category, orders products from highest price to lowest.

### Q5: What is a Savepoint in database transaction management and how is it used in SQLAlchemy?
**Answer**:
A Savepoint allows creating a nested transaction boundary inside an existing database transaction. If an error occurs within the savepoint, you can issue `savepoint.rollback()` to undo operations back to the savepoint without invalidating or rolling back the parent transaction.

In SQLAlchemy, create savepoints using `savepoint = db.session.begin_nested()`.

### Q6: How do you search for NULL or non-NULL values using SQLAlchemy filter expressions?
**Answer**:
Use `.is_(None)` and `.is_not(None)` methods:

```python
# Find products without a assigned category
stmt = db.select(Product).where(Product.category.is_(None))

# Find products with a valid category
stmt = db.select(Product).where(Product.category.is_not(None))
```

### Q7: What is the difference between `func.count(1)` and `func.count(Model.column_name)`?
**Answer**:
- `func.count(1)` (or `func.count(*)`): Counts total rows matching the query criteria, including rows where some columns are NULL.
- `func.count(Model.column_name)`: Counts only rows where `column_name` contains a non-NULL value.

---

### Q8: How do `and_()` and comma-separated arguments inside `where()` differ?
**Answer**:
In SQLAlchemy, passing multiple comma-separated expressions to `.where(cond1, cond2, cond3)` is functionally identical to `.where(and_(cond1, cond2, cond3))`. Both emit SQL `AND` operators joining the conditions.

---

### Q9: How do you perform case-insensitive exact matching in SQLAlchemy?
**Answer**:
Use `func.lower()`:

```python
stmt = db.select(User).where(func.lower(User.email) == email_input.lower())
```

### Q10: How do you retrieve a distinct list of values for a specific column?
**Answer**:
Call `.distinct()` on the select statement:

```python
stmt = db.select(Product.category).distinct()
categories = db.session.execute(stmt).scalars().all()
```
