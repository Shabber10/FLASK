## 1. Flask-SQLAlchemy Pagination Architecture

Hand-crafting `LIMIT` and `OFFSET` queries requires executing a separate `COUNT(*)` query to calculate total pages. Flask-SQLAlchemy automates pagination via **`db.paginate()`**:

```python
from flask import request

page = request.args.get('page', 1, type=int)
per_page = request.args.get('per_page', 10, type=int)

# Create Paginated Query Statement
stmt = db.select(Product).order_by(Product.id)
pagination = db.paginate(stmt, page=page, per_page=per_page, error_out=False)
```

### The `Pagination` Helper Object Attributes

| Attribute | Description | Example Output |
| :--- | :--- | :--- |
| `pagination.items` | Model instances for current active page | `[<Product 1>, <Product 2>]` |
| `pagination.total` | Total matching records across all pages | `154` |
| `pagination.page` | Active page number | `2` |
| `pagination.pages` | Total computed pages count | `16` |
| `pagination.per_page` | Items displayed per page | `10` |
| `pagination.has_next` | `True` if a subsequent page exists | `True` |
| `pagination.has_prev` | `True` if a preceding page exists | `True` |
| `pagination.next_num` | Next page number integer | `3` |
| `pagination.prev_num` | Previous page number integer | `1` |

## 2. SQL Aggregations (`func`) & `group_by`

Use `sqlalchemy.func` to execute SQL aggregate functions across table columns:

```python
from sqlalchemy import func

# 1. Basic Aggregation (Average Price across all products)
stmt = db.select(func.avg(Product.price))
avg_price = db.session.execute(stmt).scalar()

# 2. Grouped Aggregation with HAVING clause
# Get Category, Product Count, and Avg Price WHERE Product Count > 2
stmt = db.select(
    Product.category,
    func.count(Product.id).label('product_count'),
    func.avg(Product.price).label('avg_price')
).group_by(Product.category).having(func.count(Product.id) > 2)

results = db.session.execute(stmt).all()
for row in results:
    print(f"Category: {row.category} | Count: {row.product_count} | Avg Price: ${row.avg_price:.2f}")
```

> **Difference between `WHERE` and `HAVING`**:
> *   `WHERE`: Filters individual table rows **before** grouping occurs.
> *   `HAVING`: Filters aggregated group results **after** `GROUP BY` completes.

## 3. Nested Transactions & Savepoints (`begin_nested()`)

In complex enterprise workflows, you may need to attempt a sub-operation inside a larger transaction, rolling back **only that sub-operation** if it fails without invalidating the entire parent transaction.

SQLAlchemy implements savepoints using **`db.session.begin_nested()`**:

```python
try:
    # Outer Transaction: Create Order
    order = Order(user_id=10, total_amount=150.00)
    db.session.add(order)
    db.session.flush() # Flushes order to generate order.id
    
    # Savepoint (Nested Transaction Checkpoint)
    savepoint = db.session.begin_nested()
    try:
        # Sub-operation: Add bonus gift item
        gift = OrderItem(order_id=order.id, product_id=99, price=0.00)
        db.session.add(gift)
        db.session.flush()
    except Exception:
        # Rollback ONLY to savepoint; parent 'order' remains safe!
        savepoint.rollback()
        print("Failed to attach free gift, proceeding with standard order...")

    # Commit full parent transaction
    db.session.commit()
except Exception as e:
    db.session.rollback()
    print("Full order creation failed!")
```
