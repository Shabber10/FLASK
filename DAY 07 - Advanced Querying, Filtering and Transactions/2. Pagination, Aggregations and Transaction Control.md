# Day 07: Pagination, Aggregations & Transaction Control

In this section, we examine Flask-SQLAlchemy `Pagination` objects, SQL aggregate functions (`func.count`, `func.avg`, `func.sum`), `group_by`, `having` clauses, and nested transaction savepoints (`begin_nested()`).

---

## 1. Flask-SQLAlchemy Pagination Architecture

Hand-crafting `LIMIT` and `OFFSET` queries requires separate `COUNT(*)` queries to calculate total pages. Flask-SQLAlchemy provides `db.paginate()` to automate pagination:

```python
from flask import request

page = request.args.get('page', 1, type=int)
per_page = request.args.get('per_page', 10, type=int)

# Create Paginated Statement
stmt = db.select(Product).order_by(Product.id)
pagination = db.paginate(stmt, page=page, per_page=per_page, error_out=False)
```

### The `Pagination` Helper Object Attributes

| Attribute | Description | Example Output |
| :--- | :--- | :--- |
| `pagination.items` | List of model instances for current page | `[<Product 1>, <Product 2>]` |
| `pagination.total` | Total record count across all pages | `154` |
| `pagination.page` | Active page number | `2` |
| `pagination.pages` | Total computed pages count | `16` |
| `pagination.per_page` | Number of items per page | `10` |
| `pagination.has_next` | `True` if a subsequent page exists | `True` |
| `pagination.has_prev` | `True` if a preceding page exists | `True` |
| `pagination.next_num` | Next page number integer | `3` |
| `pagination.prev_num` | Previous page number integer | `1` |

## 2. SQL Aggregations (`func`) & `group_by`

Use `sqlalchemy.func` to execute SQL aggregate functions:

```python
from sqlalchemy import func

# 1. Basic Aggregation (Average Price across all products)
stmt = db.select(func.avg(Product.price))
avg_price = db.session.execute(stmt).scalar()

# 2. Grouped Aggregation with HAVING clause
# Get Category, Product Count, and Average Price WHERE Product Count > 2
stmt = db.select(
    Product.category,
    func.count(Product.id).label('product_count'),
    func.avg(Product.price).label('avg_price')
).group_by(Product.category).having(func.count(Product.id) > 2)

results = db.session.execute(stmt).all()
for row in results:
    print(f"Category: {row.category} | Count: {row.product_count} | Avg Price: ${row.avg_price:.2f}")
```

## 3. Nested Transactions & Savepoints (`begin_nested`)

In complex enterprise workflows, you may need to attempt an operation within a larger transaction, rolling back **only that operation** if it fails without invalidating the entire parent transaction.

SQLAlchemy implements savepoints using `db.session.begin_nested()`:

```python
try:
    # Outer Transaction
    user = User(username='johndoe', email='john@example.com')
    db.session.add(user)
    db.session.flush() # Generates user.id
    
    # Savepoint (Nested Transaction)
    savepoint = db.session.begin_nested()
    try:
        profile = Profile(user_id=user.id, bio="Developer")
        db.session.add(profile)
        db.session.flush()
    except Exception:
        # Rollback ONLY to savepoint; 'user' remains staged in session!
        savepoint.rollback()
        print("Profile creation failed, continuing without profile...")

    # Commit parent transaction
    db.session.commit()
except Exception as e:
    db.session.rollback()
    print("Full transaction failed!")
```
