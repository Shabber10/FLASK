## 1. Core Architectural Definitions

### 📖 Key Terms & Concepts:

| Term | Plain-English Definition | Real-World Role |
| :--- | :--- | :--- |
| **`jti` (JWT ID)** | A unique 128-bit UUID string assigned to every generated token payload. | Acts as the serial number of a digital passport; enables tracking and revoking individual tokens. |
| **Token Revocation** | Invalidation of a token before its natural expiration timestamp (`exp`). | Used when a user clicks "Logout", changes their password, or reports a lost device. |
| **Blocklist / Blacklist** | A high-speed cache storing revoked `jti` strings to reject future requests. | Checked automatically by `@jwt.token_in_blocklist_loader`. |
| **TTL (Time-To-Live)** | An expiration duration in seconds set on Redis keys. | Automatically cleans up revoked JTIs from memory when the token reaches its natural `exp`. |
| **Refresh Token Rotation** | A security policy where using a Refresh Token immediately invalidates it and issues a brand-new token pair. | Prevents replay attacks from stolen refresh tokens. |

## 2. Why In-Memory Sets Fail in Production

A naive implementation might store revoked tokens in a Python global variable:

```python
# ❌ DANGEROUS ANTI-PATTERN: DO NOT USE IN PRODUCTION
jwt_blocklist = set()
```

### 💥 Architectural Failure Modes:
1. **Multi-Worker Process Isolation (Gunicorn)**: When running under Gunicorn (`--workers=4`), each worker is an independent OS process with its own private memory. If a user logs out on Worker #1, the JTI is added only to Worker #1's set. When their next request hits Worker #2, the revoked token is accepted!
2. **Container Restarts & Auto-Scaling**: Any deployment, crash, or scale-down event destroys the in-memory set, resurrecting all revoked tokens.
3. **Memory Leaks**: A Python `set()` never automatically purges old tokens unless a custom background thread is written.

## 3. Production Redis Blocklisting (`redis-py`)

Redis solves multi-worker synchronization with shared in-memory storage and automatic TTL expiration.

### 💻 Code Example: Initializing Redis & Setting Up Revocation

```python
import os
import redis
from datetime import datetime, timezone
from flask import jsonify
from flask_jwt_extended import jwt_required, get_jwt

# Connect to Redis using environment URL (e.g. redis://localhost:6379/0)
redis_client = redis.Redis.from_url(
    os.environ.get("REDIS_URL", "redis://localhost:6379/0"),
    decode_responses=True,
    socket_connect_timeout=2
)

@app.route('/api/v1/auth/logout', methods=['POST'])
@jwt_required(verify_type=False)  # Allows revoking either Access OR Refresh tokens
def logout():
    """
    1. Extract JTI and expiration timestamp from JWT.
    2. Calculate remaining TTL in seconds.
    3. Store JTI in Redis with automatic TTL expiration.
    """
    jwt_data = get_jwt()
    jti = jwt_data['jti']
    token_type = jwt_data['type']
    exp_timestamp = jwt_data['exp']

    # Calculate remaining seconds until natural expiration
    now_timestamp = datetime.now(timezone.utc).timestamp()
    ttl_seconds = max(int(exp_timestamp - now_timestamp), 1)

    # Store key in Redis: "jwt:revoked:<jti>" -> "true" (Auto-deletes after TTL!)
    redis_client.setex(f"jwt:revoked:{jti}", ttl_seconds, "true")

    return jsonify({
        "status": "success",
        "message": f"{token_type.capitalize()} token successfully revoked. Session ended."
    }), 200
```

## 4. The Blocklist Verification Callback

Register a callback with **`@jwt.token_in_blocklist_loader`**. `Flask-JWT-Extended` executes this function on every protected request:

```python
@jwt.token_in_blocklist_loader
def check_if_token_revoked(_jwt_header, jwt_payload: dict) -> bool:
    """
    Executed on every @jwt_required() request.
    Queries Redis to check if this token's JTI is revoked.
    Returns:
        True  -> Token IS revoked (Reject with 401 Unauthorized)
        False -> Token is clean (Allow request to proceed)
    """
    jti = jwt_payload['jti']
    # If the key exists in Redis, the token was revoked!
    return redis_client.get(f"jwt:revoked:{jti}") is not None
```

## 5. Single-Use Refresh Token Rotation

### 📖 Definition:
**Refresh Token Rotation** is a security pattern where presenting a Refresh Token to `/auth/refresh` immediately revokes that Refresh Token and mints a brand-new Access + Refresh token pair.

### ❓ The Problem It Solves:
If an attacker steals a long-lived 7-day Refresh Token, they could indefinitely generate access tokens. With Single-Use Rotation, as soon as the legitimate user's client rotates the token, the stolen token's JTI is revoked in Redis. If the attacker tries to use the old token, the server detects token reuse!

### 💻 Code Example: Single-Use Rotation

```python
from flask_jwt_extended import create_access_token, create_refresh_token, get_jwt_identity

@app.route('/api/v1/auth/refresh', methods=['POST'])
@jwt_required(refresh=True)  # Requires valid Refresh Token in Authorization header
def refresh_token():
    """
    1. Revoke the old refresh token immediately.
    2. Mint a new access token and a new refresh token.
    """
    jwt_data = get_jwt()
    old_jti = jwt_data['jti']
    exp_timestamp = jwt_data['exp']
    user_identity = get_jwt_identity()

    # Step 1: Revoke old Refresh Token in Redis
    now_timestamp = datetime.now(timezone.utc).timestamp()
    ttl_seconds = max(int(exp_timestamp - now_timestamp), 1)
    redis_client.setex(f"jwt:revoked:{old_jti}", ttl_seconds, "true")

    # Step 2: Mint brand-new token pair
    new_access_token = create_access_token(identity=user_identity)
    new_refresh_token = create_refresh_token(identity=user_identity)

    return jsonify({
        "status": "success",
        "message": "Token pair rotated successfully",
        "access_token": new_access_token,
        "refresh_token": new_refresh_token,
        "token_type": "Bearer"
    }), 200
```

## 7. Standardized Custom Error Response Handlers

Customize the JSON error payloads returned to API consumers for different authentication failure conditions:

```python
@jwt.expired_token_loader
def expired_token_callback(jwt_header, jwt_payload):
    """Triggered when a token's 'exp' timestamp is in the past."""
    return jsonify({
        "error": {
            "code": 401,
            "type": "TOKEN_EXPIRED",
            "message": "The access token has expired. Please refresh your session via /api/v1/auth/refresh."
        }
    }), 401


@jwt.revoked_token_loader
def revoked_token_callback(jwt_header, jwt_payload):
    """Triggered when token JTI is found in the Redis blocklist."""
    return jsonify({
        "error": {
            "code": 401,
            "type": "TOKEN_REVOKED",
            "message": "This token has been revoked. Please log in again."
        }
    }), 401


@jwt.invalid_token_loader
def invalid_token_callback(error):
    """Triggered when cryptographic signature verification fails."""
    return jsonify({
        "error": {
            "code": 401,
            "type": "INVALID_TOKEN",
            "message": f"Signature verification failed: {error}"
        }
    }), 401


@jwt.unauthorized_loader
def missing_token_callback(error):
    """Triggered when request lacks 'Authorization: Bearer <token>' header."""
    return jsonify({
        "error": {
            "code": 401,
            "type": "AUTHORIZATION_HEADER_MISSING",
            "message": "Request does not contain a Bearer access token."
        }
    }), 401
```
