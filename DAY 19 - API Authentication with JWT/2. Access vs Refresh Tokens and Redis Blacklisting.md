## 1. Dual-Token Architecture (Access + Refresh Pair)

Relying on a single long-lived access token is dangerous: if intercepted by a hacker, they have permanent access!

Enterprise APIs issue two distinct tokens upon login:

```python
from datetime import timedelta
from flask_jwt_extended import create_access_token, create_refresh_token

app.config['JWT_ACCESS_TOKEN_EXPIRES'] = timedelta(minutes=15) # Short lifespan
app.config['JWT_REFRESH_TOKEN_EXPIRES'] = timedelta(days=7)    # Long lifespan

@app.route('/api/v1/auth/login', methods=['POST'])
def login():
    # ... validate credentials ...
    access_token = create_access_token(identity=user.id)
    refresh_token = create_refresh_token(identity=user.id)
    
    return jsonify({
        "access_token": access_token,
        "refresh_token": refresh_token
    }), 200
```

## 2. Implementing the `/auth/refresh` Endpoint

When an access token expires after 15 minutes, the client app calls the `/auth/refresh` endpoint presenting its long-lived Refresh Token:

```python
from flask_jwt_extended import jwt_required, get_jwt_identity, create_access_token

@app.route('/api/v1/auth/refresh', methods=['POST'])
@jwt_required(refresh=True)  # Requires valid Refresh Token in Bearer header!
def refresh_access_token():
    current_user_id = get_jwt_identity()
    
    # Generate a brand new 15-minute Access Token without re-asking for password!
    new_access_token = create_access_token(identity=current_user_id)
    return jsonify({"access_token": new_access_token}), 200
```

## 3. Token Blacklisting / Revocation (`JTI` Tracking)

Every JWT contains a unique UUID string called `jti` (JWT ID).

To log out a user or revoke a stolen token, extract its `jti` string and store it inside a Redis key with an expiration TTL matching the token's lifetime:

```python
from flask_jwt_extended import jwt_required, get_jwt

# In-Memory or Redis blocklist storage set
jwt_blocklist = set()

@app.route('/api/v1/auth/logout', methods=['POST'])
@jwt_required()  # Can revoke access OR refresh tokens
def logout():
    jti = get_jwt()['jti']
    jwt_blocklist.add(jti)  # Add JTI to blocklist!
    return jsonify({"message": "Token successfully revoked. Logged out."}), 200
```

### Registering Blocklist Callback (`@jwt.token_in_blocklist_loader`)
Register a callback function that `Flask-JWT-Extended` executes automatically on every request to check if the incoming `jti` is revoked:

```python
@jwt.token_in_blocklist_loader
def check_if_token_revoked(jwt_header, jwt_payload):
    jti = jwt_payload['jti']
    return jti in jwt_blocklist  # Returns True if token is revoked!
```

## 4. Custom Error Response Handlers

Customize the JSON error responses returned when tokens expire or are missing:

```python
@jwt.expired_token_loader
def expired_token_callback(jwt_header, jwt_payload):
    return jsonify({
        "error": {"code": 401, "type": "TOKEN_EXPIRED", "message": "The access token has expired."}
    }), 401

@jwt.invalid_token_loader
def invalid_token_callback(error):
    return jsonify({
        "error": {"code": 401, "type": "INVALID_TOKEN", "message": "Signature verification failed."}
    }), 401

@jwt.unauthorized_loader
def missing_token_callback(error):
    return jsonify({
        "error": {"code": 401, "type": "AUTHORIZATION_HEADER_MISSING", "message": "Request does not contain a Bearer token."}
    }), 401
```
