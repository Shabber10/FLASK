# Day 16: Flask Test Client, Fixtures & Database Isolation

In this section, we examine Pytest `@pytest.fixture` dependency injection, `app.test_client()`, in-memory SQLite database isolation, and simulating HTTP requests.

## 1. Pytest Fixture Architecture

Pytest **Fixtures** provide a modular mechanism to set up application state before a test executes and clean up resources after the test completes.

```python
import pytest
from app import create_app, db

@pytest.fixture(scope='function')
def app():
    """Fixture providing a fresh, isolated Flask app instance per test function."""
    app = create_app('testing')
    
    with app.app_context():
        db.create_all()
        yield app         # Test executes while app fixture is suspended here
        db.session.remove()
        db.drop_all()       # Cleanup runs after test finishes!
```

### Fixture Scope Hierarchy

- `scope='function'` (Default): Executed freshly before every individual test function. Guarantees complete test isolation.
- `scope='class'`: Executed once per test class.
- `scope='module'`: Executed once per test module file.
- `scope='session'`: Executed once for the entire test suite run (ideal for setting up slow external services).

## 2. Using `app.test_client()`

Flask provides `app.test_client()`, allowing tests to simulate incoming HTTP requests (GET, POST, PUT, DELETE) against view functions **without running a live HTTP server**:

```python
@pytest.fixture
def client(app):
    """Fixture supplying a Flask WSGI test client."""
    return app.test_client()

def test_login_validation(client):
    # Simulate POST request sending JSON payload
    response = client.post('/api/login', json={
        "username": "invalid_user",
        "password": "wrong_password"
    })
    
    # Assert HTTP status code and response payload
    assert response.status_code == 401
    assert response.json['error'] == "Unauthorized"
```

## 3. Simulating Authenticated Requests

To test routes protected by authentication decorators (`@login_required` or `@jwt_required()`), pass authorization headers or login sessions inside test fixtures:

### 1. Authenticating JWT Requests in Tests
```python
@pytest.fixture
def auth_headers(client):
    """Fixture producing valid JWT Authorization headers."""
    # 1. Register test user
    client.post('/api/register', json={"username": "testuser", "password": "Password123!"})
    
    # 2. Login to acquire token
    res = client.post('/api/login', json={"username": "testuser", "password": "Password123!"})
    token = res.json['access_token']
    
    return {"Authorization": f"Bearer {token}"}

def test_protected_profile(client, auth_headers):
    # Execute request with Bearer header attached
    response = client.get('/api/profile', headers=auth_headers)
    assert response.status_code == 200
    assert response.json['username'] == "testuser"
```

## 4. Database Isolation Strategies

To ensure tests remain fast, reproducible, and side-effect free:
1. Use an **In-Memory SQLite Database** (`sqlite:///:memory:`) in `TestingConfig`.
2. Wrap each test inside a `db.create_all()` and `db.drop_all()` block using a function-scoped fixture.
