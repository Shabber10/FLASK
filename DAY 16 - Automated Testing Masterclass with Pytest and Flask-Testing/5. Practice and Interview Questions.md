# Day 16: Practice & Technical Interview Questions

---

### Q1: What is the difference between `app.test_client()` and running tests against a live HTTP server?
**Answer**:
- `app.test_client()`: Simulates HTTP requests directly against Flask's internal WSGI dispatch pipeline (`app.wsgi_app`). It requires no network socket bindings or live server processes, making tests execute in milliseconds.
- **Live HTTP Server Testing**: Spawns a real background web server and sends real TCP network requests via libraries like `requests` or `selenium`. Useful for full End-to-End (E2E) testing, but much slower and prone to port conflicts.

### Q2: Why is Pytest preferred over standard Python `unittest` for Flask applications?
**Answer**:
1. Plain function test definitions without requiring subclassing `unittest.TestCase`.
2. Clean native Python `assert a == b` statements with detailed diff failure introspection.
3. Modular `@pytest.fixture` dependency injection replacing rigid `setUp()` and `tearDown()` methods.
4. Powerful plugin support (`pytest-flask`, `pytest-cov`, `pytest-xdist`).

---

### Q3: What is Pytest Fixture Scoping and how do `function` and `session` scopes differ?
**Answer**:
- `scope='function'` (default): Executes setup before every individual test function and teardown after it. Ensures total test isolation.
- `scope='session'`: Executes setup once at the beginning of the entire test suite run and teardown after all tests finish. Used for expensive resources like initializing global test database schemas or launching Docker containers.

---

### Q4: How do you achieve complete database isolation during automated testing?
**Answer**:
1. Configure `TestingConfig` to use an **In-Memory SQLite Database** (`sqlite:///:memory:`).
2. Create a function-scoped `@pytest.fixture` that calls `db.create_all()` before yielding control to the test function, followed by `db.session.remove()` and `db.drop_all()` during teardown.

---

### Q5: How do `yield` and `return` differ inside a Pytest fixture function?
**Answer**:
- `return value`: Supplies the value to the test function, but cannot perform post-test teardown actions.
- `yield value`: Suspends execution of the fixture function, supplying `value` to the test. Once the test function completes, execution resumes immediately after the `yield` statement, allowing teardown cleanup code to run.

### Q6: How do you simulate sending JSON payloads in `client.post()`?
**Answer**:
Pass a Python dictionary to the `json` keyword argument of `client.post()`:

```python
response = client.post('/api/items', json={"name": "Widget", "price": 9.99})
```

Flask's test client automatically sets the `Content-Type` header to `application/json` and serializes the dictionary to a JSON string.

### Q7: How do you test routes protected by `@jwt_required()` using Pytest?
**Answer**:
Generate a valid JWT access token using `create_access_token()` inside an `app_context()` block and pass it in the `headers` dictionary of `client.get()`:

```python
token = create_access_token(identity="testuser")
headers = {"Authorization": f"Bearer {token}"}
response = client.get('/api/protected', headers=headers)
assert response.status_code == 200
```

### Q8: What does `pytest --cov=app --cov-report=term-missing` do?
**Answer**:
It measures statement code coverage across the `app` package during test execution. It outputs a summary table showing overall coverage percentage and highlights specific un-tested line numbers (`term-missing`).

---

### Q9: What is the purpose of `db.session.remove()` inside test fixture teardown?
**Answer**:
`db.session.remove()` disposes of the thread-local scoped session, closing open database transactions and returning connections to the pool. This prevents stale transactions or uncommitted changes from bleeding across test boundaries.

### Q10: How do you test custom CLI commands (e.g. `@app.cli.command('seed_db')`) in Flask?
**Answer**:
Use `app.test_cli_runner()`:

```python
def test_seed_cli(app):
    runner = app.test_cli_runner()
    result = runner.invoke(args=['seed_db'])
    assert result.exit_code == 0
    assert "Database seeded" in result.output
```
