## 1. The Software Testing Pyramid

Enterprise software reliability relies on a layered testing strategy:

```
                  / \
                 / E2E \           <- System / End-to-End Tests (Slowest, Most Expensive)
                /-------\
               /  Integration \    <- Integration Tests (API + DB Interaction)
              /-----------------\
             /     Unit Tests     \  <- Unit Tests (Fastest, High Coverage, Isolated)
            /---------------------\
```

- **Unit Tests**: Test small, isolated code units (individual functions, models, utility methods) without external network dependencies.
- **Integration Tests**: Verify interactions between multiple decoupled modules (e.g. Flask routes + SQLAlchemy ORM + Database).
- **End-to-End (E2E) Tests**: Validate full end-to-end user workflows against a live running server environment.

## 2. Why Pytest over Standard `unittest`?

While Python includes the built-in `unittest` module, modern Python development favors **Pytest** for several key reasons:

| Feature | Python `unittest` | Pytest |
| :--- | :--- | :--- |
| **Test Declaration** | Requires subclassing `unittest.TestCase` | Plain functions named `test_*()` |
| **Assertions** | Verbose methods (`self.assertEqual(a, b)`) | Native Python `assert a == b` statements |
| **Setup & Teardown** | Rigid `setUp()` / `tearDown()` methods | Powerful, modular `@pytest.fixture` dependency injection |
| **Plugin Ecosystem** | Limited | Extensive (`pytest-flask`, `pytest-cov`, `pytest-asyncio`) |

---

## 3. Pytest Test Discovery Rules

When running the `pytest` command, Pytest automatically searches the project directory following these conventions:
1. Scans files named `test_*.py` or `*_test.py`.
2. Locates classes named `Test*` (without `__init__` constructors).
3. Executes functions prefixed with `test_*()`.

---

## 4. Pytest Execution Flags

Commonly used Pytest command-line options:

```bash
# 1. Run tests with verbose output
pytest -v

# 2. Run a specific test file
pytest tests/test_auth.py

# 3. Filter and run tests matching a keyword pattern
pytest -k "login or register"

# 4. Stop execution immediately on the first test failure
pytest -x

# 5. Measure test code coverage with pytest-cov
pytest --cov=app --cov-report=term-missing
```
