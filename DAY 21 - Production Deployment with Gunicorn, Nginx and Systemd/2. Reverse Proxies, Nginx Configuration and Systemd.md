# Day 21: Reverse Proxies, Nginx & Systemd Supervision

In this section, we examine Nginx reverse proxy architecture, static file offloading, TLS/SSL termination, Systemd unit service configuration, and Unix domain sockets.

---

## 1. Why Place Nginx in Front of Gunicorn?

While Gunicorn is a fast WSGI server, it should **never be exposed directly to the public internet**. Enterprise deployments place **Nginx** as a reverse proxy in front of Gunicorn:

```
Clients ---> [ Nginx (Port 80/443) ] ---> Unix Socket (/tmp/gunicorn.sock) ---> Gunicorn Workers
```

### Key Responsibilities of Nginx
1. **Static File Offloading**: Nginx serves static CSS, JS, images, and uploaded files directly from disk at near-zero CPU cost, bypassing Gunicorn completely.
2. **TLS/SSL Termination**: Handles HTTPS encryption/decryption, SSL certificates (Let's Encrypt), and HTTP/2 protocol negotiation.
3. **Slow Client Protection**: Buffers slow incoming request payloads and outgoing responses, shielding Gunicorn workers from Slowloris attacks.
4. **Load Balancing**: Distributes traffic across multiple Gunicorn application servers.

---

## 2. Unix Domain Sockets vs. TCP Sockets

Connecting Nginx to Gunicorn can use either TCP ports or Unix Domain Sockets:

- **TCP Port (`127.0.0.1:8000`)**: Crosses the local network stack loopback interface. Requires TCP packet encapsulation overhead.
- **Unix Domain Socket (`unix:/tmp/gunicorn.sock`)**: Inter-process communication (IPC) managed directly by the Linux kernel file system. **20-30% faster** than TCP loopback!

---

## 3. Sample Nginx Configuration File (`/etc/nginx/sites-available/flaskapp`)

```nginx
server {
    listen 80;
    server_name example.com www.example.com;

    # 1. Direct Static File Offloading (Bypasses Gunicorn)
    location /static/ {
        alias /var/www/flaskapp/static/;
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }

    # 2. Reverse Proxy to Gunicorn Unix Domain Socket
    location / {
        proxy_pass http://unix:/tmp/gunicorn.sock;
        
        # Forward Client Headers to Flask (Parsed by ProxyFix)
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # Buffer Timeouts
        proxy_connect_timeout 60s;
        proxy_read_timeout 60s;
    }
}
```

## 4. Systemd Service Management (`/etc/systemd/system/flaskapp.service`)

**Systemd** supervises the Gunicorn process daemon, ensuring Gunicorn automatically starts on server boot and restarts immediately if a crash occurs:

```ini
[Unit]
Description=Gunicorn Application Server Instance for Flask App
After=network.target

[Service]
User=www-data
Group=www-data
WorkingDirectory=/var/www/flaskapp
Environment="PATH=/var/www/flaskapp/venv/bin"
ExecStart=/var/www/flaskapp/venv/bin/gunicorn --config gunicorn.conf.py wsgi:app

Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

### Systemd Management Commands

```bash
# Reload Systemd daemon after editing service file
sudo systemctl daemon-reload

# Start and enable service on boot
sudo systemctl start flaskapp
sudo systemctl enable flaskapp

# Check live service status and logs
sudo systemctl status flaskapp
```
