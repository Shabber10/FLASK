## 1. What is the Same-Origin Policy (SOP)?

Web browsers enforce a strict security rule called the **Same-Origin Policy (SOP)**.

> **Rule**: By default, a web page hosted on `Domain A` (e.g. `http://localhost:3000`) is **BLOCKED** by the browser from making JavaScript HTTP requests to `Domain B` (e.g. `http://localhost:5000`) unless `Domain B` explicitly permits it!
>
> **Why?**: Imagine visiting a sketchy website (`malicious-site.com`). Without SOP, a script on that site could secretly send requests to `your-bank.com` in the background and steal your account balance! 🛡️

An **Origin** is defined by 3 components: **Protocol + Domain + Port**.

```
http://localhost:3000   vs   http://localhost:5000  ──> DIFFERENT ORIGINS! (Ports differ)
http://app.company.com  vs   https://app.company.com ──> DIFFERENT ORIGINS! (Protocols differ)
```

---

## 2. What is CORS (Cross-Origin Resource Sharing)?

**CORS (Cross-Origin Resource Sharing)** is a mechanism where a web server sends special HTTP headers (`Access-Control-Allow-Origin`) telling the user's browser: *"Hey browser! It is safe to allow JavaScript from `http://localhost:3000` to access my API endpoints!"*

```
[ Frontend: React on localhost:3000 ] ──────> [ GET /api/v1/products ] ──────> [ Flask API on localhost:5000 ]
                                                                                   │ Returns Header:
                                     <────── [ 200 OK + Allowed Origin Header ] <──┘
                                             `Access-Control-Allow-Origin: http://localhost:3000`
```

---

## 3. What is a Preflight Request (`OPTIONS`)?

For complex requests (like `POST` with JSON bodies, `PUT`, `DELETE`, or custom `Authorization: Bearer` headers), the browser sends an automatic preliminary request using the **`OPTIONS`** HTTP method before sending the actual request!

> **Analogy**: A preflight request is like calling ahead to a restaurant: *"Hello, do you accept credit cards and are you open right now?"* 
> If the restaurant says *"Yes!"*, the browser sends the actual customer request!

---

## 4. What is API Rate Limiting?

What happens if a malicious hacker writes a script making 10,000 requests per second to your login endpoint to guess passwords or crash your server?

**API Rate Limiting** caps the maximum number of requests a client can make in a given time window (e.g. *"Max 10 requests per minute"* or *"Max 1,000 per day"*).

If a client exceeds their limit, the server immediately returns **`HTTP 429 Too Many Requests`**!

```
Request 1..10  ──> 200 OK
Request 11     ──> 429 Too Many Requests (Blocked!) 🚫
```
