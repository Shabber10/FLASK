# Day 20: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from CORS & Rate Limiting basics up to preflight OPTIONS requests, sliding window algorithms, and Redis multi-worker rate-limit storage.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is the Same-Origin Policy (SOP)?
**Answer**:
The Same-Origin Policy (SOP) is a core web browser security rule that prevents JavaScript running on one domain (e.g. `http://malicious-site.com`) from reading data or making unauthorized background HTTP requests to a different domain (e.g. `http://your-bank.com`).

---

### Q2: What is CORS?
**Answer**:
CORS (Cross-Origin Resource Sharing) is a HTTP-header-based mechanism that allows a server to explicitly whitelist trusted external domain origins (e.g. `http://localhost:3000`), permitting browsers to execute cross-domain API calls safely.

---

### Q3: What is API Rate Limiting?
**Answer**:
Rate Limiting is a security and traffic management technique that restricts the maximum number of HTTP requests a client can send to an API within a specified time window (e.g. 10 requests per minute).

---

### Q4: What HTTP status code is returned when a client exceeds their rate limit?
**Answer**:
`HTTP 429 Too Many Requests`.

---

### Q5: What is `get_remote_address` in Flask-Limiter?
**Answer**:
It is a default key function provided by `flask_limiter.util` that extracts the client's IP address from incoming request headers (`request.remote_addr`) to track rate limit counts per IP.

---

## 🟡 Level 2: Intermediate Questions

### Q6: What is a Preflight `OPTIONS` Request in CORS?
**Answer**:
A Preflight Request is an automatic preliminary HTTP `OPTIONS` request sent by a web browser prior to making a non-simple cross-origin request (e.g. requests with `PUT`, `DELETE` methods or custom `Authorization: Bearer` headers). The browser asks the server if the cross-origin call is permitted before sending the actual payload.

---

### Q7: What does `supports_credentials=True` do in `Flask-CORS`?
**Answer**:
It instructs Flask to include the `Access-Control-Allow-Credentials: true` response header, allowing cross-origin requests to transmit cookies, authorization headers, or TLS client certificates.

---

### Q8: What header specifies how long a browser can cache a CORS preflight response?
**Answer**:
`Access-Control-Max-Age` (e.g. `max_age=600` caches preflight checks for 10 minutes so the browser doesn't spam `OPTIONS` calls before every single API request).

---

### Q9: How do you exempt a specific route from global rate limits in `Flask-Limiter`?
**Answer**:
Decorate the view function with `@limiter.exempt`:

```python
@app.route('/health')
@limiter.exempt
def health():
    return jsonify({"status": "healthy"})
```

---

### Q10: How can you limit requests based on a custom `X-API-KEY` header instead of IP address?
**Answer**:
Pass a custom key function to `Limiter`:

```python
def get_api_key_or_ip():
    return request.headers.get("X-API-KEY", get_remote_address())

limiter = Limiter(key_func=get_api_key_or_ip, app=app)
```

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: Why does in-memory rate limiting fail on multi-worker Gunicorn server deployments?
**Answer**:
In multi-worker WSGI deployments (e.g., Gunicorn with 4 worker processes), each worker process maintains an isolated in-memory Python dictionary. Clients can bypass rate limits by distributing requests across workers. Centralized storage (like Redis via `storage_uri="redis://localhost:6379"`) is required so all workers share a single counter.

---

### Q12: What is the difference between Fixed Window and Sliding Window (Moving Window) rate limiting algorithms?
**Answer**:
*   **Fixed Window**: Resets counters at fixed clock intervals (e.g., top of the minute). Allows a burst of double the limit if requests arrive right before and right after the window reset boundary.
*   **Sliding Window (Moving Window)**: Calculates trailing request counts continuously over the past 60 seconds, preventing boundary traffic spikes.

---

### Q13: How do you implement dynamic rate limits based on User Tiers (Free vs Premium)?
**Answer**:
Pass a callable function returning limit strings into `@limiter.limit()`:

```python
def dynamic_tier_limit():
    if current_user.is_premium:
        return "100 per minute"
    return "10 per minute"

@app.route('/data')
@limiter.limit(dynamic_tier_limit)
def get_data():
    return jsonify({"data": "payload"})
```

---

### Q14: How should rate limit headers be communicated back to API clients?
**Answer**:
Send standard HTTP rate limit headers in API responses:
*   `X-RateLimit-Limit`: Maximum allowed requests in window (e.g. 100).
*   `X-RateLimit-Remaining`: Remaining allowed requests (e.g. 42).
*   `X-RateLimit-Reset`: UNIX timestamp when the counter resets.

---

### Q15: Why is setting `Access-Control-Allow-Origin: *` dangerous when `supports_credentials=True` is enabled?
**Answer**:
Browsers explicitly block `Access-Control-Allow-Origin: *` when `Access-Control-Allow-Credentials: true` is set. Allowing wildcard origins with credentials enables any website on the internet to make authenticated cross-domain requests on behalf of logged-in users, leading to catastrophic CSRF vulnerabilities.
