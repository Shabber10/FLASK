## 1. Why In-Memory Rate Limiting Fails in Production

In multi-process WSGI deployments (like Gunicorn or uWSGI with 4 worker processes), default in-memory rate counters fail:

```
                      ┌───────────────────┐
                      │ Gunicorn Worker 1 │ ──> In-Memory Counter: 3 reqs
                      ├───────────────────┤
  Incoming Requests ─>│ Gunicorn Worker 2 │ ──> In-Memory Counter: 2 reqs
                      ├───────────────────┤
                      │ Gunicorn Worker 3 │ ──> In-Memory Counter: 4 reqs
                      └───────────────────┘
```

Because each worker process maintains its own isolated memory RAM, a client can bypass a "5 per minute" limit by sending requests across different worker processes!

### The Solution: Shared Redis Storage
Connect `Flask-Limiter` to a centralized **Redis** instance shared across all WSGI worker processes:

```python
from flask_limiter import Limiter
from flask_limiter.util import get_remote_address

limiter = Limiter(
    key_func=get_remote_address,
    app=app,
    storage_uri="redis://localhost:6379/0",  # Centralized Redis Rate Limit Store!
    strategy="moving-window"                 # Accurate Sliding Window Algorithm
)
```

## 2. Rate Limiting Algorithms Compared

`Flask-Limiter` supports multiple mathematical counting algorithms:

| Algorithm | Mechanism | Pros | Cons |
| :--- | :--- | :--- | :--- |
| **Fixed Window** (`fixed-window`) | Resets counter at strict clock boundaries (e.g. 12:00, 12:01) | Fast & low memory | Traffic spike vulnerability at window reset boundaries |
| **Sliding Window** (`moving-window`) | Calculates request counts over a continuous trailing window | **Accurate & prevents boundary spikes** | Requires slightly higher Redis memory |
| **Token Bucket** | Tokens replenished continuously into a bucket; each request consumes 1 token | Smooths traffic bursts | Complex configuration |

## 3. Dynamic User-Tier Rate Limits

Scale rate limits based on user account tiers (e.g. Free Tier vs Premium Tier) or custom API Keys:

```python
from flask import request
from flask_jwt_extended import get_jwt

def custom_rate_limit_key():
    """Custom key function tracking API Key header or falling back to Client IP."""
    api_key = request.headers.get("X-API-KEY")
    if api_key:
        return f"api_key:{api_key}"
    return get_remote_address()

def dynamic_tier_limit():
    """Dynamic rate limit function evaluating active user subscription tier."""
    # Read user role or tier from JWT claim / API key
    user_tier = request.headers.get("X-User-Tier", "free")
    if user_tier == "premium":
        return "100 per minute"
    return "10 per minute"  # Default Free Tier Limit

@app.route('/api/v1/data')
@limiter.limit(dynamic_tier_limit, key_func=custom_rate_limit_key)
def get_data():
    return jsonify({"message": "Data payload"})
```
