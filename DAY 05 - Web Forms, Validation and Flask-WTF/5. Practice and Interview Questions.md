# Day 05: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from absolute web form basics up to CSRF cryptography and file upload security.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is an HTML Web Form and what is its purpose?
**Answer**:
A Web Form is an interactive section of a webpage containing input boxes, dropdowns, checkboxes, and buttons. Its purpose is to capture data entered by web visitors and send it to a web server via HTTP requests (such as POST).

---

### Q2: What is Form Validation and why is it necessary?
**Answer**:
Form Validation is the process of checking user input to ensure it meets required rules (e.g. checking that an email contains `@`, a password is at least 8 characters long, or required fields are not blank). It prevents invalid or corrupted data from entering databases.

---

### Q3: What does CSRF stand for and what is a CSRF attack in simple terms?
**Answer**:
CSRF stands for **Cross-Site Request Forgery**.
In simple terms, a CSRF attack occurs when a malicious website tricks a user's browser into sending an unauthorized command (like transferring money or changing a password) to a trusted website where the user is currently logged in.

---

### Q4: Why is using raw `request.form.get()` inefficient compared to Flask-WTF?
**Answer**:
Raw `request.form.get()` requires writing repetitive manual `if` checks for every field, manually building error messages, manually converting data types, and manually implementing anti-CSRF security tokens. Flask-WTF automates all of these into clean Python classes.

---

### Q5: How do you display a hidden anti-CSRF security token inside a Jinja template?
**Answer**:
Include `{{ form.csrf_token }}` inside your `<form>` element:
```html
<form method="POST">
    {{ form.csrf_token }}
    ...
</form>
```

## 🟡 Level 2: Intermediate Questions

### Q6: What does `form.validate_on_submit()` check under the hood?
**Answer**:
`form.validate_on_submit()` performs two checks:
1.  Verifies that `request.method` is an HTTP verb that submits data (`POST`, `PUT`, `PATCH`, or `DELETE`).
2.  Calls `form.validate()`, which triggers all field validators and validates the hidden anti-CSRF token signature.

It returns `True` only if both conditions pass.

---

### Q7: How do you implement an in-line custom validator method inside a `FlaskForm` class?
**Answer**:
Define a method following the naming pattern `validate_<field_name>(self, field)`. WTForms automatically detects and executes this method when validating that field:

```python
class ProfileForm(FlaskForm):
    username = StringField('Username')

    def validate_username(self, field):
        if field.data and field.data.lower() == 'admin':
            raise ValidationError("The username 'admin' is reserved by system.")
```

---

### Q8: Why is `secure_filename()` necessary when saving user-uploaded files?
**Answer**:
User-provided filenames can contain path traversal characters (such as `../../../etc/passwd` or `C:\Windows\System32\malicious.exe`). Saving files with unsanitized filenames allows attackers to overwrite critical system files or upload executable scripts into web directories. `secure_filename()` strips all path separators, leading slashes, and non-ASCII characters, leaving only a safe relative filename.

---

### Q9: How do you restrict the maximum file upload size in a Flask application?
**Answer**:
Set `MAX_CONTENT_LENGTH` on the Flask application configuration:
```python
# Limit upload size to 16 Megabytes
app.config['MAX_CONTENT_LENGTH'] = 16 * 1024 * 1024
```
If a client attempts to upload a file exceeding this limit, Werkzeug aborts the request automatically and returns an HTTP `413 Payload Too Large` error response.

---

### Q10: What HTML attribute is required on `<form>` elements to support file uploads?
**Answer**:
The `enctype` attribute must be set to `multipart/form-data`:
```html
<form method="POST" enctype="multipart/form-data">
    {{ form.csrf_token }}
    {{ form.avatar() }}
</form>
```
Without `enctype="multipart/form-data"`, the browser sends only the filename string as plain text rather than transmitting binary file bytes.

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: How does Flask-WTF generate and verify anti-CSRF tokens cryptographically?
**Answer**:
Flask-WTF generates a token using a combination of the application's `SECRET_KEY`, the user's session ID, and an expiration timestamp, signed using HMAC SHA-256. When a form is submitted, Flask-WTF reconstructs and verifies the signature against the active session. Because third-party sites cannot read or forge this secret token under the Same-Origin Policy, cross-site forged submissions are rejected.

---

### Q12: How do you pass custom parameters into a standalone WTForms validator function?
**Answer**:
Use a validator factory function that returns a closure accepting `(form, field)` arguments:

```python
def MaxWords(max_count):
    def _validator(form, field):
        words = (field.data or '').split()
        if len(words) > max_count:
            raise ValidationError(f"Field cannot contain more than {max_count} words.")
    return _validator

class ArticleForm(FlaskForm):
    body = TextAreaField('Article Body', validators=[MaxWords(500)])
```

### Q13: How can you enable CSRF protection for non-HTML form requests, such as AJAX or Fetch API calls?
**Answer**:
Initialize `CSRFProtect(app)` globally:
```python
from flask_wtf.csrf import CSRFProtect

csrf = CSRFProtect(app)
```
In client JavaScript, send the CSRF token in an HTTP header (e.g. `X-CSRFToken`):
```javascript
fetch('/api/data', {
    method: 'POST',
    headers: {
        'X-CSRFToken': csrf_token_value,
        'Content-Type': 'application/json'
    },
    body: JSON.stringify(payload)
});
```

### Q14: How do categorized flash messages work in Flask, and how are they rendered in Jinja2 templates?
**Answer**:
`flash(message, category)` stores temporary feedback strings in the user's session cookie under a specific category name (e.g. `'success'`, `'danger'`, `'warning'`). 

In Jinja2 templates, calling `get_flashed_messages(with_categories=True)` retrieves and clears all pending messages:

```jinja2
{% with messages = get_flashed_messages(with_categories=true) %}
  {% for category, msg in messages %}
    <div class="alert alert-{{ category }}">{{ msg }}</div>
  {% endfor %}
{% endwith %}
```

### Q15: How do `FileRequired()` and `FileAllowed()` validators work in Flask-WTF?
**Answer**:
*   `FileRequired()`: Validates that the uploaded field contains a non-empty `FileStorage` object.
*   `FileAllowed(allowed_extensions, message)`: Inspects the filename extension of the uploaded `FileStorage` object and raises a `ValidationError` if the extension is not in the whitelist (e.g. `['jpg', 'png']`).
