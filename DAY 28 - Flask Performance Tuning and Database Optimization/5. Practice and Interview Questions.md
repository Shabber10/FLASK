# Day 28: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from performance optimization basics up to N+1 query traps, SQLAlchemy eager loading, Gzip compression, CPU profiling, and memory leak audits.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is the N+1 Query Problem in ORM frameworks?
**Answer**:
The N+1 Query Problem occurs when fetching a list of N parent records causes the ORM to execute 1 query to retrieve the parents, followed by N separate queries inside a loop to fetch related child objects, resulting in N+1 database roundtrips that destroy application performance.

---

### Q2: How do you fix the N+1 Query Problem in SQLAlchemy?
**Answer**:
Use **Eager Loading** with `.options(joinedload(Parent.children))` or `.options(selectinload(Parent.children))`, which instructs SQLAlchemy to fetch parent and child objects together in a single SQL query.

---

### Q3: What is Gzip response payload compression and why is it used?
**Answer**:
Gzip compression compresses text-based HTTP response payloads (JSON, HTML, CSS) on the fly before transmission over the network. It reduces payload sizes by 70–80%, significantly reducing network latency over mobile and WAN connections.

---

### Q4: What extension enables Gzip compression in Flask?
**Answer**:
`Flask-Compress` (`Compress(app)`).

---

### Q5: What is Code Profiling?
**Answer**:
Code Profiling measures the exact execution time, call frequency, and memory consumption of Python functions during a request, allowing developers to identify specific CPU bottlenecks and slow functions.

---

## 🟡 Level 2: Intermediate Questions

### Q6: What is the difference between `joinedload()` and `selectinload()` in SQLAlchemy?
**Answer**:
*   `joinedload()`: Uses an explicit SQL `LEFT OUTER JOIN` in a single query. Ideal for One-to-One and Many-to-One relationships.
*   `selectinload()`: Issues a second query using an `IN (...)` clause (`SELECT * FROM books WHERE author_id IN (1, 2, ...)`). Ideal for One-to-Many and Many-to-Many relationships with large datasets to avoid duplicate parent rows in JOIN results.

---

### Q7: What does Werkzeug's `ProfilerMiddleware` do?
**Answer**:
`ProfilerMiddleware` wraps a Flask application's WSGI layer with Python's `cProfile` module. It profiles every incoming HTTP request and outputs detailed call count and cumulative execution time statistics to stdout or file logs.

---

### Q8: What parameters control database connection pooling in Flask-SQLAlchemy?
**Answer**:
*   `pool_size`: Number of persistent database connections to keep open.
*   `max_overflow`: Maximum number of extra temporary connections created under burst traffic.
*   `pool_recycle`: Seconds after which open idle connections are recycled to prevent stale socket timeouts.
*   `pool_pre_ping`: Performs a lightweight health check before reusing a pooled connection.

---

### Q9: Why is raw `Query.all()` dangerous on large database tables?
**Answer**:
Executing `Query.all()` on a table with millions of rows loads all database rows into Python memory as ORM objects at once, exhausting server RAM and causing Out-Of-Memory (OOM) crashes.

**Solution**: Use cursor pagination with `.paginate(page, per_page)`.

---

### Q10: How do you configure minimum payload size thresholds for `Flask-Compress`?
**Answer**:
Set `app.config['COMPRESS_MIN_SIZE'] = 500`, which ensures only responses larger than 500 bytes are compressed, avoiding unnecessary CPU overhead for small JSON responses.

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: How do you intercept and log slow SQL queries using SQLAlchemy Engine event listeners?
**Answer**:
Attach event hooks to `before_cursor_execute` (to record start time in `conn.info`) and `after_cursor_execute` (to calculate elapsed time). If `elapsed > threshold`, log the SQL statement and query parameters:

```python
@event.listens_for(Engine, "after_cursor_execute")
def check_slow_query(conn, cursor, statement, parameters, context, execmany):
    elapsed = time.time() - conn.info['start'].pop()
    if elapsed > 0.2:
        app.logger.warning(f"Slow Query ({elapsed:.2f}s): {statement}")
```

---

### Q12: How does Python's `tracemalloc` module help diagnose memory leaks in Flask?
**Answer**:
`tracemalloc` tracks Python memory block allocations. By calling `tracemalloc.take_snapshot()` before and after heavy requests, developers can compare snapshots (`snapshot2.compare_to(snapshot1, 'lineno')`) to identify exact file line numbers allocating un-garbage-collected objects.

---

### Q13: What is Connection Pool Starvation and how do you prevent it in high-concurrency Flask apps?
**Answer**:
Connection Pool Starvation occurs when all available database pool connections (`pool_size` + `max_overflow`) are held open by long-running HTTP requests or background jobs, forcing new requests to block or fail with timeouts.

**Prevention**: Keep database transactions short, offload long-running tasks to Celery workers, and scale DB pool sizes or use pgbouncer connection proxies.

---

### Q14: What is the difference between B-Tree and Hash indexes in database optimization?
**Answer**:
*   **B-Tree Index** (Default): Supports range queries (`<`, `>`, `BETWEEN`), equality (`=`), and sorting (`ORDER BY`).
*   **Hash Index**: Supports exact equality matches (`=`) with $O(1)$ lookup time, but cannot be used for range queries or sorting.

---

### Q15: How does HTTP Caching headers (`Cache-Control: max-age=3600, ETag`) complement server-side performance tuning?
**Answer**:
Client-side caching headers command browsers and CDN edge caches (Cloudflare) to store API responses locally. Subsequent requests are served directly from browser RAM or edge nodes without touching the Flask application server at all!
