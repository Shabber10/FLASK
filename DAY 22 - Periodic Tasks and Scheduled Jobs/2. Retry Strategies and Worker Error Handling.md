## 1. Automatic Retries with Exponential Backoff & Jitter

When periodic background tasks interact with external third-party APIs or databases, transient network timeouts will occur.

Configure automatic retries with **Exponential Backoff** and **Jitter** (random delay variance) to prevent overwhelming recovered servers:

```python
import requests
from celery_app import celery_app

@celery_app.task(
    bind=True,
    autoretry_for=(requests.exceptions.RequestException,), # Auto-retry on HTTP errors
    retry_backoff=True,         # Exponential backoff (1s, 2s, 4s, 8s, 16s...)
    retry_backoff_max=300,      # Cap maximum retry delay at 5 minutes
    retry_jitter=True,          # Add random delay variance to prevent Thundering Herd!
    max_retries=5
)
def sync_payment_gateway_task(self):
    """Sync payment transactions with Stripe API."""
    response = requests.get("https://api.stripe.com/v1/charges", timeout=5)
    response.raise_for_status()
    return response.json()
```

## 2. Preventing Celery Beat Race Conditions in Clusters

> ⚠️ **CRITICAL ENTERPRISE WARNING**: If you deploy your Flask application across 3 Kubernetes pods or EC2 servers, **DO NOT run `celery beat` on all 3 nodes!**
>
> If Beat runs on 3 nodes, **all 3 Beat instances will fire identical task triggers at midnight**, causing duplicate billing, duplicate emails, and database race conditions!

### Production Solutions:
1.  **Single Beat Instance Rule**: Run `celery beat` on a single dedicated container/pod.
2.  **Redlock Distributed Locking (`celery-redbeat`)**: Uses Redis distributed locks (`Redlock`) to guarantee that only 1 Beat process acquires the master lock in a cluster.

## 3. Light-Weight In-Process Alternative: `Flask-APScheduler`

For microservices or monolithic Flask applications without Redis or Celery infrastructure, **`Flask-APScheduler`** runs periodic jobs directly inside the Flask process:

```python
from flask import Flask
from flask_apscheduler import APScheduler

app = Flask(__name__)
scheduler = APScheduler()

# Configure APScheduler Jobs
app.config['SCHEDULER_API_ENABLED'] = True

@scheduler.task('interval', id='job_1', seconds=30)
def periodic_job():
    print("⏰ [APSCHEDULER] In-process job running every 30 seconds!")

scheduler.init_app(app)
scheduler.start()
```
