# Day 22: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from periodic task basics up to Celery Beat schedule configurations, `crontab()` helpers, exponential backoff retries, and multi-server Beat race condition prevention.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is a Periodic Task / Scheduled Job?
**Answer**:
A Periodic Task is an automated background function configured to execute repeatedly based on a time or calendar schedule (e.g., purging stale session records every 10 minutes or generating sales reports every Monday at 9:00 AM).

---

### Q2: What is Celery Beat?
**Answer**:
Celery Beat is a clock scheduler daemon process that tracks time and sends task execution messages to the Redis broker at specified scheduled intervals.

---

### Q3: Does Celery Beat execute background task functions itself?
**Answer**:
No. Celery Beat only sends task execution messages to the Message Broker (Redis). Separate background Celery Worker processes pull task messages from Redis and execute the actual Python code.

---

### Q4: What is Cron Syntax?
**Answer**:
Cron is the standard Linux format for specifying calendar-based execution times using 5 fields: `minute`, `hour`, `day_of_month`, `month`, and `day_of_week`.

---

### Q5: What is `APScheduler`?
**Answer**:
`APScheduler` (Advanced Python Scheduler) is an in-process Python scheduling library that allows Flask applications to run scheduled background jobs directly inside the Flask process without requiring Redis or Celery workers.

---

## 🟡 Level 2: Intermediate Questions

### Q6: Where do you configure periodic schedules in a Celery application?
**Answer**:
Inside the `celery_app.conf.beat_schedule` dictionary mapping schedule names to task functions and schedule rules:

```python
celery_app.conf.beat_schedule = {
    'nightly-cleanup': {
        'task': 'tasks.clean_sessions',
        'schedule': crontab(hour=0, minute=0),
    }
}
```

---

### Q7: How do you write a `crontab()` schedule in Celery that runs every Monday at 9:00 AM?
**Answer**:
```python
from celery.schedules import crontab

schedule = crontab(day_of_week='mon', hour=9, minute=0)
```

---

### Q8: How do you enable exponential backoff and jitter for retrying failing tasks in Celery?
**Answer**:
Set `retry_backoff=True` and `retry_jitter=True` in the `@celery_app.task` decorator:

```python
@celery_app.task(bind=True, autoretry_for=(Exception,), retry_backoff=True, retry_jitter=True, max_retries=5)
def sync_data(self):
    pass
```

---

### Q9: What command starts the Celery Beat scheduler from the command line?
**Answer**:
```bash
celery -A app.celery_app beat --loglevel=info
```

---

### Q10: What is the difference between an interval schedule and a `crontab()` schedule in Celery Beat?
**Answer**:
*   **Interval Schedule**: Triggers a task at fixed frequency durations (e.g. `schedule=30.0` or `timedelta(minutes=10)`).
*   **Crontab Schedule**: Triggers a task at specific wall-clock times (e.g. `crontab(hour=0, minute=0)` for midnight).

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: Why is running multiple `celery beat` instances in a multi-server deployment dangerous, and how do you solve it?
**Answer**:
If multiple `celery beat` processes run simultaneously across multiple servers or Kubernetes pods, **every Beat instance will fire duplicate task messages into Redis at the exact same scheduled time**, leading to duplicate billing charges or database race conditions.

**Solutions**:
1.  **Single Beat Instance Rule**: Run `celery beat` on a single dedicated container/pod.
2.  **Distributed Locking (`celery-redbeat`)**: Use Redis distributed locks (`Redlock`) to ensure only one Beat master process acquires the schedule lock.

---

### Q12: What is the purpose of `retry_jitter=True` in Celery retries?
**Answer**:
`retry_jitter=True` adds a randomized time delay variance to retry intervals. Without jitter, if a database recovers after an outage, hundreds of failed tasks retrying at the exact same exponential interval will hit the database simultaneously, causing a **Thundering Herd** crash.

---

### Q13: How do Dead Letter Queues (DLQ) work in Celery?
**Answer**:
When a task fails repeatedly and exhausts its maximum retries (`max_retries`), Celery routes the failed task message into a separate isolated queue called a **Dead Letter Queue (DLQ)**. Engineers can inspect DLQ messages, fix underlying bugs, and re-publish failed tasks manually without losing data.

---

### Q14: How can you dynamically update `beat_schedule` rules at runtime without restarting the Celery Beat daemon?
**Answer**:
Use a database-backed scheduler like **`django-celery-beat`** or custom SQLAlchemy Beat schedulers (`DatabaseScheduler`) that query schedule rules from SQL tables dynamically on every clock tick.

---

### Q15: How do you handle timezone shifts (e.g., Daylight Saving Time) in Celery Beat?
**Answer**:
Configure UTC as the standard timezone on your Celery application (`timezone='UTC'`, `enable_utc=True`) and specify target user timezones explicitly when constructing `crontab()` objects.
