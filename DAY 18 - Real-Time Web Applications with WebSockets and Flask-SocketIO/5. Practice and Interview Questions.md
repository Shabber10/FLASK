# Day 18: Practice & Technical Interview Questions

---

### Q1: What is the main difference between HTTP Polling and WebSockets?
**Answer**:
- **HTTP Polling**: Unidirectional request-response protocol. The client repeatedly sends HTTP GET requests to the server to check for new data, incurring heavy HTTP header overhead, latency, and CPU load.
- **WebSockets (RFC 6455)**: Full-duplex, bi-directional protocol over a single persistent TCP connection. After an initial HTTP Upgrade handshake, both client and server can push arbitrary text or binary data frames instantly with virtually zero header overhead.

---

### Q2: What is the HTTP Upgrade Handshake in WebSockets?
**Answer**:
A WebSocket connection initiates as a standard HTTP/1.1 `GET` request containing `Upgrade: websocket` and `Connection: Upgrade` headers. If accepted, the server responds with HTTP status `101 Switching Protocols`, and the underlying TCP socket remains open for WebSocket frame transmission.

---

### Q3: How does Socket.IO differ from raw WebSockets?
**Answer**:
- **Raw WebSockets**: Low-level TCP frame transport protocol. Lacks built-in event naming, rooms, or automatic reconnection logic.
- **Socket.IO**: High-level event-based messaging framework. Features automatic transport fallback (HTTP Long-Polling -> WebSockets), automatic exponential reconnection retries, named custom events, and built-in room/channel primitives.

---

### Q4: What is the difference between `emit('event', data)` and `emit('event', data, broadcast=True)` in Flask-SocketIO?
**Answer**:
- `emit('event', data)`: Sends the event message **ONLY** to the single client socket that emitted the current request.
- `emit('event', data, broadcast=True)`: Sends the event message to **ALL** clients currently connected to the Socket.IO server.

---

### Q5: How do `join_room(room_name)` and `leave_room(room_name)` work in Flask-SocketIO?
**Answer**:
Rooms allow grouping subset client sockets into named channels. Calling `join_room('room_a')` subscribes the calling client's session ID (`request.sid`) to `'room_a'`. Emitting with `to='room_a'` delivers the message only to clients subscribed to `'room_a'`.

---

### Q6: Why must you use `socketio.run(app)` instead of `app.run()` to start a Flask-SocketIO app?
**Answer**:
Standard `app.run()` launches Werkzeug's built-in WSGI development server, which does not support persistent WebSocket connections or HTTP 101 upgrades. `socketio.run(app)` wraps the WSGI server with Eventlet, Gevent, or Werkzeug WebSocket adapters required for persistent WebSocket frame processing.

---

### Q7: How do you handle cross-process WebSocket broadcasting when running multiple Gunicorn WSGI workers?
**Answer**:
Pass a Redis message queue URL to `SocketIO(app, message_queue='redis://localhost:6379/0')`. 

When Worker #1 emits a broadcast event, Flask-SocketIO publishes the event to Redis Pub/Sub, which distributes the message to all other Gunicorn worker processes so their connected WebSocket clients receive the update.

---

### Q8: What is `request.sid` in Flask-SocketIO event handlers?
**Answer**:
`request.sid` is a unique Session ID string assigned to each connected Socket.IO client connection. It acts as the socket's private room identifier.

---

### Q9: How do you send a message to all clients in a room EXCEPT the sender?
**Answer**:
Pass `include_self=False`:

```python
emit('user_typing', {'username': username}, to=room_name, include_self=False)
```

---

### Q10: How do you authenticate users connecting via Socket.IO?
**Answer**:
Authenticate clients during the `connect` event handler:

```python
@socketio.on('connect')
def connect_handler(auth):
    token = auth.get('token') if auth else None
    user = verify_jwt_token(token)
    if not user:
        return False # Returning False rejects the WebSocket connection!
```
