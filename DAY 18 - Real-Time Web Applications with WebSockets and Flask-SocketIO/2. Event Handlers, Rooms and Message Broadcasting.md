# Day 18: Event Handlers, Rooms & Message Broadcasting

In this section, we examine Flask-SocketIO event handlers (`@socketio.on`), message broadcasting, target emitting, multi-room communication primitives (`join_room`, `leave_room`), and cross-process message queues with Redis.

---

## 1. Event Handlers & Message Emitting

Socket.IO applications communicate by emitting and handling custom named events:

```python
from flask_socketio import SocketIO, emit, send
from flask import request

socketio = SocketIO(app)

# 1. Connection Event Handlers
@socketio.on('connect')
def handle_connect():
    print(f"Client connected: Session ID (sid) = {request.sid}")
    emit('server_response', {'data': 'Connected to SocketIO Server'})

@socketio.on('disconnect')
def handle_disconnect():
    print(f"Client disconnected: sid = {request.sid}")

# 2. Custom Named Event Handler
@socketio.on('client_message')
def handle_custom_message(json_data):
    print(f"Received message from client: {json_data}")
    
    # Broadcast message to ALL connected clients
    emit('message_broadcast', json_data, broadcast=True)
```

---

## 2. Emitting Methods Comparison

| Function Call | Target Audience | Example Usage |
| :--- | :--- | :--- |
| `emit('event', data)` | Only the client who sent the active event | Echoing confirmation back to sender |
| `emit('event', data, broadcast=True)` | ALL connected clients | System-wide notifications |
| `emit('event', data, include_self=False)` | All connected clients **EXCEPT** the sender | Typing indicators in chat |
| `emit('event', data, to='room_name')` | All clients inside a specific room channel | Targeted multi-room chat messages |

## 3. Multi-Room Communication (`join_room` & `leave_room`)

Rooms allow segmenting connected clients into dynamic channels (e.g. chat rooms, project boards, game lobbies):

```python
from flask_socketio import join_room, leave_room, emit

@socketio.on('join_channel')
def on_join(data):
    username = data['username']
    room = data['room']
    
    # Add client socket to room channel
    join_room(room)
    
    # Emit notification ONLY to clients inside this room
    emit('room_notice', {'msg': f"{username} has joined {room}"}, to=room)

@socketio.on('leave_channel')
def on_leave(data):
    username = data['username']
    room = data['room']
    
    leave_room(room)
    emit('room_notice', {'msg': f"{username} has left {room}"}, to=room)

@socketio.on('send_room_message')
def on_room_message(data):
    room = data['room']
    emit('new_message', {'user': data['username'], 'text': data['text']}, to=room)
```

## 4. Multi-Process Scaling with Redis Message Queue

In production environments running multiple Gunicorn/Gevent WSGI worker processes, a client connected to Worker Process #1 cannot broadcast messages directly to clients connected to Worker Process #2.

Pass a Redis message queue URL to `SocketIO` to enable inter-process message broadcasting across workers:

```python
# Enables Redis pub/sub for cross-process WebSocket broadcasting
socketio = SocketIO(app, message_queue='redis://localhost:6379/0')
```
