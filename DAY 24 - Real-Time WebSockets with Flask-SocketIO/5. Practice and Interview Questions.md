# Day 24: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from WebSocket basics up to Socket.IO event handlers, multi-room channels, Redis Pub/Sub scaling, and greenlet async servers.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is a WebSocket?
**Answer**:
A WebSocket is a computer communications protocol that provides persistent, bi-directional, full-duplex communication channels over a single TCP connection, allowing servers to push data to clients instantly without waiting for HTTP requests.

---

### Q2: What is the main difference between HTTP Polling and WebSockets?
**Answer**:
*   **HTTP Polling**: Client continuously sends HTTP requests every few seconds asking if new data is available (high overhead, slow).
*   **WebSockets**: Single persistent open connection where the server pushes data instantly to the client the moment an event occurs.

---

### Q3: What is `Flask-SocketIO`?
**Answer**:
`Flask-SocketIO` is a Flask extension that integrates Socket.IO into Flask applications, providing low-latency real-time WebSocket communication, event handlers, and fallback mechanisms.

---

### Q4: What is an Event in `Flask-SocketIO`?
**Answer**:
An Event is a named message payload exchanged between server and client. Handlers are declared using `@socketio.on('event_name')`, and messages are sent using `emit('event_name', data)`.

---

### Q5: What is a Room in `Flask-SocketIO`?
**Answer**:
A Room is a virtual channel that groups multiple connected socket clients together (e.g. `join_room('Tech-Support')`), allowing targeted event broadcasting to specific subsets of users.

---

## 🟡 Level 2: Intermediate Questions

### Q6: What is the difference between `send()` and `emit()` in `Flask-SocketIO`?
**Answer**:
*   `send()`: Sends unnamed standard text or JSON string messages (listened to via `@socketio.on('message')`).
*   `emit()`: Sends custom named events (e.g. `emit('user_score_update', {'score': 100})`).

---

### Q7: What does `broadcast=True` do when emitting an event?
**Answer**:
It sends the event to **all** connected clients across the server instead of sending it only back to the client that originated the request.

---

### Q8: How do you send a message exclusively to clients inside a specific room?
**Answer**:
Pass the `to=room_name` parameter to `emit()`:

```python
emit('chat_message', {'msg': 'Hello Room!'}, to='Lobby')
```

---

### Q9: Why must you launch your application with `socketio.run(app)` instead of standard `app.run()`?
**Answer**:
Standard `app.run()` launches Flask's built-in Werkzeug WSGI server, which cannot maintain long-lived persistent WebSocket connections. `socketio.run()` wraps Flask with an asynchronous event loop server capable of handling WebSockets.

---

### Q10: What HTTP status code signals a successful WebSocket handshake upgrade?
**Answer**:
`HTTP 101 Switching Protocols`.

---

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: Why does cross-client broadcasting fail when running Gunicorn with multiple worker processes, and how do you solve it?
**Answer**:
When Gunicorn runs multiple worker processes, each worker maintains isolated memory. A client connected to Worker 1 will not receive events emitted by Worker 2.

**Solution**: Configure a central Redis Pub/Sub message broker (`message_queue='redis://localhost:6379/0'`). When Worker 2 emits an event, it publishes to Redis, which broadcasts it across all worker processes.

---

### Q12: Why are asynchronous greenlet worker servers (Eventlet or Gevent) mandatory for WebSockets in production?
**Answer**:
Standard WSGI workers allocate 1 operating system thread per request. Because WebSockets remain open indefinitely, standard threads quickly exhaust memory resources. Eventlet/Gevent greenlets use cooperative multitasking to handle 10,000+ concurrent WebSocket connections per process with minimal memory overhead.

---

### Q13: What is the difference between WebSockets and Server-Sent Events (SSE)?
**Answer**:
*   **WebSockets**: Bi-directional (both client and server can send data anytime over TCP).
*   **Server-Sent Events (SSE)**: Uni-directional (server streams updates to client over standard HTTP; client cannot push data back over the same channel).

---

### Q14: How does Socket.IO handle client reconnections after network drops?
**Answer**:
The Socket.IO client automatically attempts reconnection with exponential backoff. Upon reconnecting, a new Socket ID (`sid`) is assigned, and custom application logic must re-authenticate the user and re-join their previous rooms.

---

### Q15: How do you secure WebSocket connections with JWT authentication in `Flask-SocketIO`?
**Answer**:
Pass the JWT token in the initial connection query parameters or headers (`auth={"token": "bearer_jwt"}`). In the `@socketio.on('connect')` handler, decode the JWT; if invalid or expired, call `disconnect()` to reject the socket connection.
