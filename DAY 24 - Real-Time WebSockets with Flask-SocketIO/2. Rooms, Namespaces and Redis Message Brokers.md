## 1. Multi-Room Group Channels (`join_room` & `leave_room`)

In applications like Slack or Discord, users join specific chat channels. `Flask-SocketIO` provides **Rooms** to isolate communication:

```python
from flask import request
from flask_socketio import SocketIO, emit, join_room, leave_room

@socketio.on('join')
def on_join(data):
    username = data['username']
    room = data['room']
    
    join_room(room)  # Adds client's SID to specified room channel
    print(f"👥 {username} joined room '{room}'")
    
    # Broadcast join notification ONLY to clients inside this room!
    emit('status_update', {
        'msg': f"{username} has joined room '{room}'."
    }, to=room)

@socketio.on('leave')
def on_leave(data):
    username = data['username']
    room = data['room']
    
    leave_room(room)  # Removes client's SID from room channel
    emit('status_update', {
        'msg': f"{username} has left room '{room}'."
    }, to=room)

@socketio.on('room_message')
def on_room_message(data):
    room = data['room']
    # Target message ONLY to clients in room
    emit('new_message', {'user': data['user'], 'text': data['text']}, to=room)
```

## 2. Namespaces for Route Multiplexing

**Namespaces** allow you to separate different functional areas of your application over a single WebSocket connection using distinct URL endpoints (e.g. `/chat` vs `/admin_metrics`):

```python
from flask_socketio import Namespace

class AdminMetricsNamespace(Namespace):
    def on_connect(self):
        print("🔐 Admin connected to /admin_metrics namespace")

    def on_disconnect(self):
        print("🔒 Admin disconnected from /admin_metrics namespace")

    def on_request_cpu_stats(self, data):
        self.emit('cpu_stats', {'usage_percent': 42.5})

# Register Namespace
socketio.on_namespace(AdminMetricsNamespace('/admin_metrics'))
```

## 3. Production Scaling with Redis Pub/Sub (`message_queue`)

> ⚠️ **MULTI-WORKER WARNING**: When running Gunicorn with 4 worker processes, a client connected to Worker 1 will NOT receive messages emitted by Worker 2 because each process has isolated memory!

### The Enterprise Solution: Redis Message Queue (Pub/Sub)
Connect `Flask-SocketIO` to **Redis Pub/Sub** as a message broker. When Worker 2 emits a message, it publishes to Redis, which broadcasts it across all Gunicorn workers instantly:

```python
# Multi-Worker Redis Pub/Sub Integration
socketio = SocketIO(
    app,
    cors_allowed_origins="*",
    message_queue='redis://localhost:6379/0' # Enables cross-worker broadcasting!
)
```

## 4. Production Asynchronous Servers (Eventlet / Gevent)

Standard WSGI workers block 1 operating system thread per open socket. Because WebSockets remain open indefinitely, use **Eventlet** or **Gevent** greenlet asynchronous servers to support 10,000+ concurrent sockets per process:

```bash
# Production Gunicorn Command with Eventlet Workers
gunicorn --worker-class eventlet -w 1 --bind 0.0.0.0:5000 app:app
```
