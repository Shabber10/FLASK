### Q1: What is a Composite Index in database design and when should you create one?
**Answer**:
A Composite Index is an index created across two or more columns in a table (e.g. `db.Index('idx_user_status', 'user_id', 'status')`). 

Create a composite index when queries frequently filter, join, or sort using multiple columns simultaneously in `WHERE` clauses (e.g. `WHERE user_id = 5 AND status = 'COMPLETED'`). The column order in a composite index matters: place the most selective or frequently queried leading column first.

### Q2: What is `@hybrid_property` in SQLAlchemy and how does `@property` differ from `@hybrid_property`?
**Answer**:
- `@property`: Standard Python property evaluated exclusively on instantiated Python object instances in memory. It **cannot** be translated into SQL clauses inside `db.select().where()` queries.
- `@hybrid_property`: A hybrid attribute that functions as a Python property on instances AND supplies an `@<property_name>.expression` method that SQLAlchemy compiles into an inline SQL expression for database-side filtering, sorting, and aggregations.

### Q3: What is the purpose of `pool_pre_ping=True` in SQLAlchemy engine configuration?
**Answer**:
Database engines and network firewalls drop idle connections after a timeout period. If a web application attempts to re-use a dropped pooled connection, an unhandled `OperationalError: Disconnect` is raised.

Setting `pool_pre_ping=True` instructs SQLAlchemy to issue a lightweight `SELECT 1` ping query before handing out a connection from the pool. If the ping fails, the stale connection is discarded and replaced with a fresh connection transparently.

### Q4: How do you measure and profile individual SQL query execution times in Flask-SQLAlchemy?
**Answer**:
Attach SQLAlchemy `Engine` event listeners to `before_cursor_execute` and `after_cursor_execute`:

```python
from sqlalchemy import event
from sqlalchemy.engine import Engine
import time

@event.listens_for(Engine, "before_cursor_execute")
def start_timer(conn, cursor, statement, parameters, context, executemany):
    context._start_time = time.time()

@event.listens_for(Engine, "after_cursor_execute")
def log_timer(conn, cursor, statement, parameters, context, executemany):
    elapsed_ms = (time.time() - context._start_time) * 1000
    if elapsed_ms > 100: # Log queries taking longer than 100ms
        print(f"[SLOW QUERY ({elapsed_ms:.1f}ms)] {statement}")
```

### Q5: How do you execute raw SQL queries safely in SQLAlchemy without risking SQL Injection vulnerabilities?
**Answer**:
Wrap raw SQL strings in `sqlalchemy.text()` and pass query parameters in a secondary parameter dictionary:

```python
# SAFE: Uses bound parameters
query = text("SELECT * FROM users WHERE email = :email AND status = :status")
results = db.session.execute(query, {"email": user_email, "status": "ACTIVE"}).all()

# UNSAFE: Vulnerable to SQL Injection!
# query = text(f"SELECT * FROM users WHERE email = '{user_email}'")
```

### Q6: What does `load_only()` do and when should it be used for query optimization?
**Answer**:
By default, SQLAlchemy retrieves all table columns in `SELECT` statements. When querying tables that contain large `TEXT`, `BLOB`, or `JSON` fields, loading unused columns causes memory overhead and network latency.

`load_only(Model.col1, Model.col2)` explicitly restricts the `SELECT` query to fetch only specified columns:

```python
stmt = db.select(User).options(load_only(User.id, User.username))
```

### Q7: What is `EXPLAIN ANALYZE` and how does it help optimize database performance?
**Answer**:
`EXPLAIN ANALYZE` is a database command executed ahead of a query that forces the RDBMS query planner to output its execution strategy tree. It details whether the engine used B-Tree index scans, full table scans (Sequential Scans), index lookups, hash joins, or nested loops, along with exact execution time per node.

### Q8: What are the trade-offs of adding too many database indexes to a table?
**Answer**:
While indexes speed up `SELECT` queries, they incur trade-offs:
1. **Write Overhead**: Every `INSERT`, `UPDATE`, or `DELETE` statement must update both the table data and all associated B-Tree index structures.
2. **Storage Overhead**: Indexes consume extra disk space and RAM memory in the database engine buffer pool.

### Q9: How do `pool_size` and `max_overflow` work in connection pooling?
**Answer**:
- `pool_size`: The steady-state number of persistent database connections maintained in the pool.
- `max_overflow`: The maximum number of temporary connections allowed to open above `pool_size` under sudden spike loads. Overflow connections are closed once idle.

### Q10: How do you perform bulk database updates efficiently in Flask-SQLAlchemy without loading models into memory?
**Answer**:
Execute a bulk UPDATE statement directly using `db.update()`:

```python
stmt = db.update(User).where(User.is_active == False).values(status='DEACTIVATED')
db.session.execute(stmt)
db.session.commit()
```
