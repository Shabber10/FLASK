## 1. Hybrid Attributes & Expressions (`@hybrid_property`)

A **Hybrid Property** defines a Python property on an ORM model that can be evaluated in two contexts:
1. **Python Instance Level**: Calculated in Python code on a model object.
2. **SQL Expression Level**: Translated into an inline SQL expression for use inside `db.select().where()` clauses.

### Hybrid Property Example

```python
from flask_sqlalchemy import SQLAlchemy
from sqlalchemy.ext.hybrid import hybrid_property, hybrid_method
from sqlalchemy import func

db = SQLAlchemy()

class OrderItem(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    unit_price = db.Column(db.Float, nullable=False)
    quantity = db.Column(db.Integer, nullable=False)

    # 1. Python Instance Level Access (`item.total_price`)
    @hybrid_property
    def total_price(self):
        return self.unit_price * self.quantity

    # 2. SQL Expression Level Access (`where(OrderItem.total_price > 100)`)
    @total_price.expression
    def total_price(cls):
        return cls.unit_price * cls.quantity
```

### Usage in Queries

```python
# Filter orders directly in SQL using the hybrid property!
stmt = db.select(OrderItem).where(OrderItem.total_price > 500.00)
high_value_items = db.session.execute(stmt).scalars().all()
```

## 2. Safe Raw SQL Execution (`text()`)

For complex reporting queries or database-specific extensions, execute raw SQL using `sqlalchemy.text()`:

```python
from sqlalchemy import text

# ALWAYS bind parameters to prevent SQL Injection vulnerabilities
sql_query = text("""
    SELECT u.username, COUNT(o.id) as total_orders, SUM(o.total_amount) as total_spent
    FROM users u
    JOIN orders o ON u.id = o.user_id
    WHERE o.status = :order_status
    GROUP BY u.id
    HAVING SUM(o.total_amount) >= :min_spent
    ORDER BY total_spent DESC
""")

results = db.session.execute(sql_query, {
    "order_status": "COMPLETED",
    "min_spent": 1000.00
}).all()

for row in results:
    print(f"User: {row.username} | Orders: {row.total_orders} | Total Spent: ${row.total_spent:.2f}")
```

## 3. Connection Pool Health (`pool_pre_ping`)

In long-running application deployments, database servers (or firewalls) drop idle connections after a timeout period. When an application thread attempts to use a dropped connection, SQLAlchemy throws an `OperationalError: MySQL server has gone away` or `SSL connection has been closed`.

### Preventing Disconnect Errors with `pool_pre_ping=True`

`pool_pre_ping=True` instructs SQLAlchemy to issue a lightweight test query (`SELECT 1`) to verify connection health before returning it from the pool:

```python
app.config['SQLALCHEMY_ENGINE_OPTIONS'] = {
    'pool_size': 10,
    'max_overflow': 20,
    'pool_recycle': 1800,
    'pool_pre_ping': True  # Automatically tests connection validity before execution!
}
```
