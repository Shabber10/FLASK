# Day 26: Subdomain Routing, Schema Switching & Tenant Context

In this section, we examine tenant resolution strategies (Subdomains vs Custom Headers), Flask `g` context injection, dynamic SQLAlchemy query filtering, and tenant context middleware.

---

## 1. Tenant Resolution Strategies

Before executing business logic, the application must identify which tenant owns the incoming request:

1. **Subdomain Resolution** (e.g. `acme.saasapp.com` -> `acme`).
2. **Custom HTTP Header** (e.g. `X-Tenant-ID: acme`).
3. **JWT Claim** (e.g. `"tenant_id": "acme"` inside bearer token payload).

---

## 2. Flask Subdomain Routing & Context Injection

Flask natively supports subdomain matching by setting `SERVER_NAME` in configuration:

```python
app.config['SERVER_NAME'] = 'saasapp.com:5000'

@app.before_request
def resolve_tenant_context():
    """Resolves active tenant from HTTP Host header or X-Tenant-ID header."""
    tenant_slug = None
    
    # 1. Try X-Tenant-ID header
    if 'X-Tenant-ID' in request.headers:
        tenant_slug = request.headers.get('X-Tenant-ID')
    else:
        # 2. Extract subdomain from Host header (e.g. acme.saasapp.com)
        host = request.host.split(':')[0]
        parts = host.split('.')
        if len(parts) >= 3:
            tenant_slug = parts[0]
            
    if tenant_slug:
        tenant = Tenant.query.filter_by(slug=tenant_slug, is_active=True).first()
        if not tenant:
            abort(404, description="Tenant domain not found or deactivated.")
        
        # Inject active tenant object into Flask's thread-local `g` proxy!
        g.tenant = tenant
    else:
        g.tenant = None
```

## 3. Automated Query Filtering with SQLAlchemy Events

To eliminate human error (forgetting to add `tenant_id` filters), hook into SQLAlchemy's `do_orm_execute` event to automatically inject `tenant_id` criteria into all queries:

```python
from sqlalchemy.orm import Session

@event.listens_for(Session, 'do_orm_execute')
def receive_do_orm_execute(execute_state):
    """Intercepts ORM queries and auto-applies tenant_id filtering."""
    if execute_state.is_select and hasattr(g, 'tenant') and g.tenant:
        # Automatically append tenant_id filter if model has tenant_id column
        mapper = execute_state.bind_mapper
        if mapper and hasattr(mapper.class_, 'tenant_id'):
            execute_state.statement = execute_state.statement.where(
                mapper.class_.tenant_id == g.tenant.id
            )
```
