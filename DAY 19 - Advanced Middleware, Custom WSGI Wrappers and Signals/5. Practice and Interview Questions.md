# Day 19: Practice & Technical Interview Questions

---

### Q1: What is PEP 3333 WSGI Middleware and how does it wrap `app.wsgi_app` in Flask?
**Answer**:
PEP 3333 defines the WSGI standard interface between web servers and Python web applications. In Flask, `app.wsgi_app` is the actual WSGI application callable. 

WSGI Middleware is a Python class or wrapper function that wraps `app.wsgi_app` to intercept incoming `environ` dictionaries before Flask routes the request, and wraps `start_response` to inspect or inject response headers before HTTP data is sent to the web server.

---

### Q2: Why is `ProxyFix` middleware necessary when deploying Flask behind Nginx or AWS ALB?
**Answer**:
When Flask runs behind a reverse proxy (e.g. Nginx or AWS ALB), the proxy terminates external client HTTPS connections and forwards traffic over internal HTTP to Flask. 

Without `ProxyFix`, Flask sees `request.remote_addr` as the IP of the proxy server and `request.is_secure` as `False`. `ProxyFix` updates `environ` using `X-Forwarded-For`, `X-Forwarded-Proto`, and `X-Forwarded-Host` headers so `request.remote_addr` returns the real client IP and `url_for(..., _external=True)` generates HTTPS URLs correctly.

### Q3: What is the primary difference between Flask Request Hooks (`@app.before_request`) and Flask Signals (`Blinker`)?
**Answer**:
- **Request Hooks**: Part of Flask's HTTP request pipeline. Functions execute in sequence and can modify request data, alter response instances, or short-circuit view execution (e.g. returning a 401 response).
- **Flask Signals**: Implementation of the **Observer Pattern**. Signals emit read-only event notifications (`user_registered.send()`). Subscribers receive notifications asynchronously or synchronously to perform decoupled side-effects (logging, audit trails, metrics) without altering response outputs.

---

### Q4: What is the signature of a PEP 3333 compliant WSGI application callable?
**Answer**:
A WSGI callable must accept two positional parameters:
1. `environ`: A Python dictionary containing CGI environment variables, HTTP request headers, and WSGI stream handles.
2. `start_response`: A callable function `start_response(status, response_headers, exc_info=None)` used to set the HTTP status code and response headers.

---

### Q5: How do you intercept and modify outgoing HTTP headers inside custom WSGI middleware?
**Answer**:
Wrap the `start_response` callable passed into `__call__(self, environ, start_response)`:

```python
def custom_start_response(status, headers, exc_info=None):
    headers.append(('X-Powered-By', 'Custom WSGI Middleware'))
    return start_response(status, headers, exc_info)

return self.app(environ, custom_start_response)
```

### Q6: What built-in Flask signals are available for tracking application events?
**Answer**:
- `request_started`: Emitted before request processing begins.
- `request_finished`: Emitted when response is returned.
- `got_request_exception`: Emitted when an unhandled error occurs.
- `template_rendered`: Emitted when a Jinja2 template finishes rendering.

---

### Q7: Are Blinker signal subscribers executed in a separate thread or synchronously?
**Answer**:
By default, Blinker signals execute **synchronously** in the same thread that called `signal.send()`. If a signal subscriber function performs a slow operation (e.g. sending a network email), it will block the calling view function unless offloaded to a background task queue like Celery.

### Q8: How do you create a custom signal in Flask using Blinker?
**Answer**:

```python
from blinker import Namespace

my_signals = Namespace()
order_placed = my_signals.signal('order-placed')

# Subscriber
@order_placed.connect
def on_order_placed(sender, order_id, amount):
    print(f"Order #{order_id} placed: ${amount}")

# Sender
order_placed.send(app, order_id=501, amount=99.95)
```

### Q9: What security risks occur if `ProxyFix` is configured with `x_for=1` when the app is NOT behind a trusted reverse proxy?
**Answer**:
If `ProxyFix` is enabled on an application directly exposed to the public internet, malicious clients can spoof `X-Forwarded-For` HTTP headers in incoming requests. `ProxyFix` will blindly trust the spoofed header, allowing attackers to bypass IP-based rate limiters or IP whitelists.

---

### Q10: When would you choose custom WSGI middleware over `@app.before_request`?
**Answer**:
Choose **WSGI Middleware** when:
1. Intercepting non-Flask WSGI traffic or modifying raw WSGI `environ` before Flask context initialization.
2. Integrating third-party WSGI components (like `ProxyFix` or WSGI profilers).
3. Modifying raw HTTP response headers across all applications mounted under a WSGI stack.
