# Day 19: Custom WSGI Middleware (PEP 3333)

Welcome to **Day 19** of the 30-Day Enterprise Flask Masterclass! Today, we explore lower-level WSGI architecture, PEP 3333 middleware wrappers, reverse proxy header patching (`ProxyFix`), request/response interception, and event decoupling with Flask Signals.

---

## 1. What is Custom WSGI Middleware?

In Flask, the application object `app` is a WSGI callable. When a WSGI server (Gunicorn, uWSGI, Werkzeug) receives an HTTP request, it invokes `app(environ, start_response)`.

Under the hood, Flask stores its core WSGI application callable inside `app.wsgi_app`. **WSGI Middleware** is a Python class or function that wraps `app.wsgi_app`, intercepting incoming `environ` dictionaries before Flask routes the request, and intercepting `start_response` headers before output is returned to the client:

```
WSGI Server (Gunicorn)
       |
       v
+-------------------------------------------------------------------+
| Custom WSGI Middleware (e.g. ProxyFix, RequestTimingMiddleware)   |
|  - Intercepts & Modifies `environ` (Headers, Remote IP, Protocol) |
|  - Intercepts `start_response` (HTTP Status, Headers)             |
+-------------------------------------------------------------------+
       |
       v
+-------------------------------------------------------------------+
| Flask Core WSGI Application (`app.wsgi_app`)                      |
|  - Context Pushing, Route Matching, View Execution                |
+-------------------------------------------------------------------+
```

## 2. Writing a Custom WSGI Middleware Class

A PEP 3333 compliant WSGI middleware class must implement `__init__(self, app)` and `__call__(self, environ, start_response)`:

```python
import time

class RequestTimingWSGIMiddleware:
    """WSGI Middleware measuring low-level request execution latency."""
    
    def __init__(self, app):
        self.app = app

    def __call__(self, environ, start_response):
        start_time = time.time()

        def custom_start_response(status, headers, exc_info=None):
            # Calculate execution latency before headers are sent to client
            latency_ms = (time.time() - start_time) * 1000
            headers.append(('X-WSGI-Latency-MS', f"{latency_ms:.2f}"))
            return start_response(status, headers, exc_info)

        # Pass request down the WSGI chain
        return self.app(environ, custom_start_response)

# Attach Middleware to Flask Application
app = Flask(__name__)
app.wsgi_app = RequestTimingWSGIMiddleware(app.wsgi_app)
```

## 3. Reverse Proxy Header Patching (`ProxyFix`)

When a Flask application runs behind a reverse proxy or load balancer (Nginx, AWS ALB, Cloudflare), the proxy forwards traffic over HTTP to Flask. Without middleware, `request.remote_addr` returns the proxy IP, and `request.is_secure` returns `False`!

Werkzeug provides `ProxyFix` middleware to safely parse `X-Forwarded-For`, `X-Forwarded-Proto`, and `X-Forwarded-Host` headers:

```python
from werkzeug.middleware.proxy_fix import ProxyFix

app = Flask(__name__)

# Configure ProxyFix middleware
# x_for=1: Trust 1 proxy for client IP (X-Forwarded-For)
# x_proto=1: Trust 1 proxy for HTTPS protocol (X-Forwarded-Proto)
# x_host=1: Trust 1 proxy for Host header (X-Forwarded-Host)
app.wsgi_app = ProxyFix(
    app.wsgi_app,
    x_for=1,
    x_proto=1,
    x_host=1,
    x_port=1,
    x_prefix=1
)
```
