# Day 19: Flask Signals & Event Decoupling (Blinker)

In this section, we examine Flask Signals, Blinker integration, signal vs request hook differences, core built-in signals, and custom domain event signals.

---

## 1. What are Flask Signals?

**Signals** implement the **Observer Pattern** (Publish-Subscribe) in Flask using the `Blinker` library. 

Signals allow decoupled sender components to emit notifications when specific application events occur, allowing subscriber functions to react without modifying the core view handler logic:

```
Sender (View Handler)                   Blinker Signal                   Subscribers (Listeners)
+-----------------------+              +--------------+               +-----------------------+
|  User registers       | -----------> | user_signed  | ------------> | 1. Send Welcome Email |
|  `user_registered.    |  .send(app)  | _up signal   |               | 2. Create Audit Log   |
|   send(self, user=u)` |              +--------------+               | 3. Increment Metrics  |
+-----------------------+                                             +-----------------------+
```

---

## 2. Signals vs. Request Lifecycle Hooks

| Feature | Request Hooks (`@app.before_request`) | Flask Signals (`user_registered`) |
| :--- | :--- | :--- |
| **Purpose** | Intercept and modify request/response flow | Passive event notification and audit tracking |
| **Modifiability** | Can modify response, abort requests, or redirect | **Read-Only**: Subscribers cannot alter response output |
| **Execution Guarantee**| Executed sequentially in request pipeline | Executed synchronously when signal is sent |
| **Coupling** | Direct dependency on Flask HTTP lifecycle | Decoupled domain event broadcasting |

---

## 3. Built-in Flask Signals

Flask provides built-in signals for key application lifecycle events:

- `request_started`: Emitted before request processing begins.
- `request_finished`: Emitted when response is returned to client.
- `got_request_exception`: Emitted when an unhandled exception occurs.
- `template_rendered`: Emitted when a Jinja2 template is rendered.
- `user_logged_in` / `user_logged_out`: Emitted by Flask-Login on auth events.

```python
from flask import request_started, request_finished

def log_request_start(sender, **extra):
    print(f"[SIGNAL: request_started] Sender: {sender}")

# Connect subscriber to signal
request_started.connect(log_request_start, app)
```

## 4. Creating Custom Application Signals

Define custom signals for domain-specific business events using `blinker.Namespace`:

```python
from blinker import Namespace

# Create custom signal namespace
my_signals = Namespace()

# Declare domain signals
user_registered_signal = my_signals.signal('user-registered')
order_completed_signal = my_signals.signal('order-completed')

# 1. Subscriber Function
@user_registered_signal.connect
def on_user_registered(sender, user_id, email, **kwargs):
    print(f"[AUDIT SIGNAL] New User Registered! ID: {user_id} | Email: {email}")

# 2. Emitting Signal in View Handler
@app.route('/api/signup', methods=['POST'])
def signup():
    user = create_user(request.json)
    
    # Emit signal (Pass sender app instance and keyword parameters)
    user_registered_signal.send(app, user_id=user.id, email=user.email)
    
    return jsonify({"status": "registered"}), 201
```
