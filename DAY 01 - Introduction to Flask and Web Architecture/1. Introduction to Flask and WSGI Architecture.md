# Day 01: Introduction to Flask and WSGI Architecture

## 1. Web Architecture & WSGI Overview
Web Server Gateway Interface (WSGI) is the standard specified in PEP 3333 that defines how Python web applications communicate with web servers (such as Nginx, Apache, Gunicorn, or Werkzeug).

```
+----------------+      +-------------------+      +-------------------+      +-------------------+
|  HTTP Client   | ---> | Web Server        | ---> | WSGI Server       | ---> | Flask Application |
|  (Browser/API) | <--- | (Nginx / Apache)  | <--- | (Gunicorn/uWSGI)  | <--- | (App Instance)    |
+----------------+      +-------------------+      +-------------------+      +-------------------+
```

### WSGI Specification Mechanics
A WSGI callable takes two parameters:
1. `environ`: A dictionary containing HTTP headers, request variables, and server environment data.
2. `start_response`: A callback function supplied by the WSGI server to set status codes and response headers.

### Flask's Built-in WSGI Engine: Werkzeug
Flask is built on top of **Werkzeug**, a comprehensive WSGI utility library that handles request routing, HTTP header parsing, cookies, form data parsing, and context locals.
