## 1. What is Flask?

**Flask** is a lightweight, flexible web framework written in Python designed for building web applications and RESTful APIs quickly and easily.

*   **Lightweight Framework**: Flask provides only the essential core features needed to build web applications, allowing developers to add extra components only when required.
*   **Extensions**: If you need additional features in Flask, you install extensions:
    *   Authentication & Logins → `Flask-Login`
    *   Database & ORM → `Flask-SQLAlchemy`
    *   Form Handling & Validation → `Flask-WTF`
    *   RESTful API building → `Flask-RESTful`

> **One-Line Definition for Students**:  
> *"Flask is a beginner-friendly Python web framework used to build websites, REST APIs, data dashboards, and machine learning applications."*

---

## 2. What is a Framework & Why is Flask a "Microframework"?

### 🔹 What is a Framework?
A **Framework** is a ready-made structure (skeleton) that:
1.  Saves development time.
2.  Avoids writing low-level code from scratch.
3.  Provides standardized rules and tools to build applications easily.
*   *Key benefit*: You focus on your unique application logic, while the framework handles server routing and request dispatching.

### 🔹 Why is Flask called a Microframework?
Flask is called a **microframework** because:
1.  It keeps the core simple and minimal.
2.  It does not force a specific database, form validator, or file layout structure on you.
3.  Extra features are added on demand using extensions.

## 3. Advantages & Disadvantages of Flask

### ✅ Advantages
1.  **Simple and Easy to Learn**: Clean syntax; build a working web app in under 10 lines of Python.
2.  **Lightweight and Flexible**: Gives developers total freedom to design application structure.
3.  **Highly Customizable**: Add only the tools you need via extensions.
4.  **Extensive Community & Documentation**: Rich ecosystem with solutions for almost any use case.

### ❌ Disadvantages
1.  **More Manual Setup for Large Apps**: Does not come with built-in admin panel or default ORM like Django.
2.  **Developer Discipline Required**: Gives freedom, which means poor organization in large teams can lead to maintenance issues if not properly architected.

## 5. What is WSGI? (Web Server Gateway Interface)

### Definition & Acronym
**WSGI** stands for **W**eb **S**erver **G**ateway **I**nterface (pronounced *"WIZ-gee"*). It is a Python specification standard (**PEP 3333**) that defines a universal ruleset for communication between web servers and Python web applications.

```
+------------------+         +--------------------+         +--------------------+
|    Web Server    |  HTTP   |    WSGI Server     |  WSGI   | Python Framework   |
| (Nginx / Apache) | ======> | (Gunicorn / uWSGI) | ======> |  (Flask / Django)  |
+------------------+         +--------------------+         +--------------------+
```

> **Definition**: *"WSGI is a Python standard that defines how a web server talks to a Python web application, acting as a bridge between them."*

## 6. Restaurant Mental Model of Flask & WSGI

Think of web architecture like a restaurant:

```
Development Mode:
Browser  ──▶  Werkzeug (Dev Server)  ──▶  Flask App

Production Mode:
Browser  ──▶  Nginx (Web Server)  ──▶  Gunicorn (WSGI)  ──▶  Flask App
```

| Restaurant Element | Web Architecture Equivalent | Role / Description |
| :--- | :--- | :--- |
| **Customer** | **Browser** | Sends requests and waits for response. |
| **Order** | **HTTP Request** | Details what page or API user wants. |
| **Waiter** | **Werkzeug / Gunicorn (WSGI)** | Receives order and carries it to kitchen. |
| **Kitchen** | **Flask Application** | Main framework containing recipes & routes. |
| **Recipe Book** | **Route Table (`app.route`)** | Maps URL paths to specific Python functions. |
| **Cook / Chef** | **Route Function (`home()`)** | Executes code to prepare page or data. |
| **Prepared Food** | **Response Object** | HTML page or JSON data ready to return. |
| **Waiter Delivers** | **HTTP Response** | WSGI server sends response back to browser. |

> 📌 **Key Insight**: Notice that in development vs production, **only the waiter changes** (Werkzeug → Nginx + Gunicorn). The chef (**Flask**) remains exactly the same!

## 7. Low-Level Raw WSGI Callable Example

According to PEP 3333, every WSGI application must be a callable accepting `(environ, start_response)`:

```python
def raw_wsgi_application(environ, start_response):
    request_method = environ.get('REQUEST_METHOD', 'GET')
    path_info = environ.get('PATH_INFO', '/')
    
    status = '200 OK'
    headers = [('Content-Type', 'text/html; charset=utf-8')]
    
    start_response(status, headers)
    
    html_body = f"<h1>Raw WSGI App</h1><p>Path: {path_info}</p>"
    return [html_body.encode('utf-8')]
```

## 8. The 3 Core Pillars Behind Flask

Flask is built on top of three core components:

```
                            +-------------------------+
                            |   FLASK FRAMEWORK       |
                            +------------+------------+
                                         |
           +-----------------------------+-----------------------------+
           v                             v                             v
+---------------------+       +---------------------+       +---------------------+
|      WERKZEUG       |       |       JINJA2        |       |        CLICK        |
| (WSGI & Routing)    |       | (Templating Engine) |       |    (CLI Toolkit)    |
+---------------------+       +---------------------+       +---------------------+
```

1.  **Werkzeug** (*"VERK-tsoyg"*): Handles HTTP request/response parsing, URL routing, and WSGI middleware.
2.  **Jinja2** (*"JIN-jah-two"*): Template engine rendering dynamic HTML using Python variables (`{{ name }}`) and loops (`{% for %}`).
3.  **Click**: CLI toolkit powering `flask run` commands.
