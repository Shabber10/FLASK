## 1. What is Web Development? (Class Notes Definition)

**Web Development** is the process of creating websites or web applications that can be accessed through the internet using a web browser. It involves designing, coding, database management, and server maintenance.

### 🌐 Two Main Parts of Web Development

| Component | Side | Technologies | What It Does |
| :--- | :--- | :--- | :--- |
| **Frontend** | Client-Side | HTML, CSS, JavaScript | Everything the user sees and interacts with directly inside their browser (buttons, forms, layout, styling, animations). |
| **Backend** | Server-Side | Python (Flask), MySQL, Node.js, PHP | Handles the business logic, database storage, user authentication, calculations, and data processing behind the scenes. |

---

## 2. Webpage vs. Website vs. Web Application

To understand web development clearly, remember this simple classroom book analogy:

```
📖 BOOK ANALOGY:
- Webpage  = A single page in a book.
- Website  = The entire complete book (a collection of related webpages).
- Web App  = An interactive digital notebook where you can read, write, update, and delete entries.
```

| Term | Classroom Definition | Real-World Example |
| :--- | :--- | :--- |
| **Webpage** | A single document that contains text, images, videos, hyperlinks, and tables. | `about.html`, `contact.html`, a single blog post |
| **Website** | A collection of related webpages linked together under a single domain name. | Wikipedia, College portal, Portfolio site |
| **Web Application** | A dynamic website where users perform interactive tasks (logging in, submitting orders, querying databases). | Gmail, Instagram, Student Management Portal |

---

## 3. Static vs. Dynamic Webpages

```
1. STATIC WEBPAGE (Fixed Content - Same for Everyone)
   Client Browser ──(Request)──> Web Server ──(Returns Fixed HTML)──> Display Fixed Page

2. DYNAMIC WEBPAGE (Dynamic Content - Personalized & Interactive)
   Client Browser ──(Request)──> Web Server (Flask) ──(Executes Python & Queries MySQL)──> Generates Custom HTML ──> Display
```

| Feature | Static Webpage | Dynamic Webpage |
| :--- | :--- | :--- |
| **Technology** | HTML + CSS only | Python (Flask) + Jinja2 + Database (MySQL) |
| **Content** | Fixed for every visitor | Changes based on time, logged-in user, and user input |
| **Database** | Does NOT connect to a database | Connects to a database to fetch and store records |
| **Example** | Simple restaurant menu page | Student dashboard showing the student's own marks and profile |

---

## 4. Web Browser vs. Web Server

*   **Web Browser (Client)**: A software application installed on the user's device (e.g., Google Chrome, Microsoft Edge, Mozilla Firefox) used to request, render, and display web pages.
*   **Web Server (Host)**: Software or hardware (e.g., Flask Development Server, Nginx, Apache) that stores website files, processes incoming HTTP requests, and sends back responses.

## 5. The HTTP Request-Response Lifecycle

Every time a user visits a website or clicks a button, an **HTTP (HyperText Transfer Protocol)** cycle takes place:

```
[1. User Enters URL: http://127.0.0.1:5000/students]
                         │
                         ▼
           ┌───────────────────────────┐
           │   Web Browser (Client)    │
           └─────────────┬─────────────┘
                         │ 2. HTTP GET Request
                         ▼
           ┌───────────────────────────┐
           │    Flask Server (:5000)   │
           └─────────────┬─────────────┘
                         │ 3. Query MySQL Database (`collegedb`)
                         ▼
           ┌───────────────────────────┐
           │      MySQL Database       │
           └─────────────┬─────────────┘
                         │ 4. Return Student Rows
                         ▼
           ┌───────────────────────────┐
           │   Flask renders HTML      │
           └─────────────┬─────────────┘
                         │ 5. HTTP Response (Status 200 OK + HTML)
                         ▼
           ┌───────────────────────────┐
           │  Browser renders Page!    │
           └───────────────────────────┘
```

## 6. What is Flask? (Class Notes Core Concept)

**Flask** is a lightweight, micro web framework written in Python. It was created by **Armin Ronacher**.

### 🌟 Why Flask is Called a "Microframework"
Flask is called "micro" because it keeps the core simple and extensible:
1. It does **not** force a particular database tool, form validator, or authentication library upon you.
2. It provides the essential core features: **Routing**, **Request Handling**, and **Jinja2 Templating**.
3. Any extra functionality is added using **Extensions (Libraries)**:

| Feature Needed | Extension Used in Flask |
| :--- | :--- |
| **Database ORM** | `Flask-SQLAlchemy` or raw `mysql-connector-python` |
| **User Authentication & Login** | `Flask-Login` |
| **Form Validation & CSRF** | `Flask-WTF` |
| **REST APIs** | `Flask-RESTful` / `Flask-Smorest` |
| **Email Sending** | `Flask-Mail` / built-in `smtplib` |
