## 1. What is the Internet vs. The World Wide Web (WWW)?

People often use the terms "Internet" and "World Wide Web" interchangeably, but they are two different things:

*   **The Internet**: The massive physical network of connected computers, cables, routers, and satellites around the globe. It is the global infrastructure (the roads).
*   **The World Wide Web (WWW)**: A service built *on top* of the Internet. It is a system of interlinked documents (web pages), media, and applications accessed via web browsers using URLs (the cars driving on the roads).

> **Analogy**: The Internet is like the physical highway system. The WWW is like the delivery trucks moving goods across those highways.

## 2. The Client-Server Architecture

Every web interaction involves two primary entities: a **Client** and a **Server**.

```
+------------------+                    +------------------+
|      CLIENT      |   HTTP Request     |      SERVER      |
| (Chrome/Browser) | -----------------> |  (Web Application|
|                  | <----------------- |   on Computer)   |
+------------------+   HTTP Response    +------------------+
```

### What is a Client?
A **Client** is any device or software that requests information from the web.
*   **Examples**: Google Chrome, Safari, Firefox, a mobile app on your phone, or a command-line tool like `curl`.
*   **Role**: It renders the user interface (HTML/CSS/JS) and captures user input (button clicks, form typing).

### What is a Server?
A **Server** is a powerful computer connected to the internet 24/7 that stores website files and backend code (like Python/Flask).
*   **Role**: It listens for incoming requests from clients, processes data (e.g., checks database passwords, calculates numbers), and sends back a response.

## 3. How the Internet Finds Sites: IP, Domain, DNS & Ports

When you type `https://www.google.com` in your browser, how does your computer know which server in the world to connect to?

### 1. IP Address (Internet Protocol Address)
Every device on the internet has a unique numerical address, like a street address.
*   **Example IPv4**: `142.250.190.46`
*   **Localhost IP**: `127.0.0.1` (Points back to your own local computer!).

### 2. Domain Name
Human beings are terrible at remembering numbers like `142.250.190.46`. Domain names are human-readable nicknames mapped to IP addresses.
*   **Example**: `google.com`, `github.com`.

### 3. DNS (Domain Name System)
DNS is the **phonebook of the Internet**. When you type `google.com`, your browser asks a DNS server: *"What IP address belongs to google.com?"*. The DNS server replies with `142.250.190.46`.

### 4. Port Numbers
A server can run multiple applications at once (e.g., a website, an email server, a database). **Ports** are like room numbers in an apartment building.
*   **Port 80**: Standard HTTP (unencrypted websites).
*   **Port 443**: Standard HTTPS (encrypted secure websites).
*   **Port 5000**: Flask's default local development port (`http://127.0.0.1:5000`).

## 4. HTTP & HTTPS Demystified

**HTTP** stands for **H**yper**T**ext **T**ransfer **P**rotocol. It is the agreed-upon set of rules that clients and servers use to talk to each other. **HTTPS** is HTTP with an encrypted security layer (SSL/TLS).

### 1. Anatomy of an HTTP Request

When you visit a page or submit a form, your browser sends an HTTP request containing:

1.  **Request Method (HTTP Verb)**:
    *   `GET`: Fetch data from server (e.g., viewing a profile page).
    *   `POST`: Send new data to server (e.g., submitting a login form).
    *   `PUT` / `PATCH`: Update existing data on server.
    *   `DELETE`: Remove data from server.
2.  **Request URL / Path**: E.g., `/login` or `/api/users`.
3.  **Headers**: Metadata like browser version, language, accepted formats (`User-Agent`, `Content-Type`).
4.  **Body (Payload)**: Data sent during `POST` or `PUT` requests (e.g., username & password).

### 2. Anatomy of an HTTP Response

The server processes your request and sends back an HTTP response containing:

1.  **Status Code**: A 3-digit number indicating success or failure.
2.  **Response Headers**: Server information, cookies, content types.
3.  **Response Body**: The actual data (HTML web page, image, or JSON data).

#### 🚦 Essential HTTP Status Codes to Remember

| Code Range | Category | Common Examples | Meaning |
| :--- | :--- | :--- | :--- |
| **2xx** | **Success** | `200 OK`, `201 Created` | Everything went smoothly! |
| **3xx** | **Redirection** | `301 Moved Permanently`, `302 Found` | The resource moved to another URL. |
| **4xx** | **Client Error** | `404 Not Found`, `401 Unauthorized` | You made a mistake (wrong URL, invalid password). |
| **5xx** | **Server Error** | `500 Internal Server Error` | The server crashed or Python code threw an unhandled bug! |

## 5. Static Web Pages vs. Dynamic Web Applications

```
STATIC PAGE:  Browser <=================> Web Server (Static HTML file)
                                       
DYNAMIC APP:  Browser <===> Web Server <===> WSGI <===> Python Code (Flask) <===> Database
```

*   **Static Web Page**: HTML/CSS/JS files stored directly on disk. Every user sees the exact same page (e.g., a restaurant menu page).
*   **Dynamic Web Application**: Python code runs on the server every time a request arrives. It queries databases, checks permissions, and builds custom HTML or JSON data tailored to the specific user (e.g., your personal Facebook feed or Amazon cart).
