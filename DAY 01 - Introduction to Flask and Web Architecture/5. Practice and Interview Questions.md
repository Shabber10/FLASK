### Q1: What is PEP 3333 and what problem does WSGI solve in Python web development?
**Answer**:
PEP 3333 defines the **Web Server Gateway Interface (WSGI)** standard. Before WSGI, Python web frameworks (such as Zope, Webware, or Django) required dedicated web server adapters for Apache or IIS. 

WSGI solves this problem by defining a universal interface between web servers (Nginx, Apache, Gunicorn) and web frameworks (Flask, Django). Any WSGI-compliant server can execute any WSGI-compliant application without code modification.

### Q2: Explain the exact signature and requirements of a WSGI application callable.
**Answer**:
A WSGI application must be a callable object (function or class method) accepting two positional parameters:
1. `environ`: A Python `dict` containing CGI environment variables, HTTP headers, request metadata, and input streams (`wsgi.input`).
2. `start_response`: A callback function supplied by the server signature `start_response(status, response_headers, exc_info=None)`.

The WSGI callable must invoke `start_response()` before yielding response data, and must return an **iterable of byte strings** (e.g. `[b"Hello World"]`).

### Q3: What does `__name__` do when passed to `Flask(__name__)`?
**Answer**:
`__name__` is a special Python variable containing the name of the current module. Passing `__name__` tells Flask where the application file is located on the filesystem. Flask uses this root path to locate:
- Static assets (`/static`)
- Jinja2 template files (`/templates`)
- Local instance configuration folder (`/instance`)

If you instantiate Flask inside a package, `__name__` points to the package root directory.

### Q4: Explain the difference between Application Context and Request Context in Flask.
**Answer**:
- **Application Context**: Bound to `current_app` and `g`. Created when handling a request or executing CLI commands. Holds application configuration, logger instances, and request-scoped temporary storage (`g`).
- **Request Context**: Bound to `request` and `session`. Created when an HTTP request arrives. Encapsulates incoming HTTP headers, parameters, POST form payloads, files, and signed user cookies.

Both contexts are managed using Werkzeug's `LocalProxy` and Python's `contextvars` to ensure thread-safety across concurrent workers.

### Q5: How do WSGI Middlewares work in Flask? Provide a code example.
**Answer**:
A WSGI middleware wraps Flask's underlying `app.wsgi_app` callable. It intercepts incoming `environ` data before Flask processes the request and intercepts response headers/status codes before returning bytes to the server.

```python
class SimpleLoggingMiddleware:
    def __init__(self, wsgi_app):
        self.wsgi_app = wsgi_app

    def __call__(self, environ, start_response):
        print(f"[LOG] Incoming Request Path: {environ.get('PATH_INFO')}")
        return self.wsgi_app(environ, start_response)

app.wsgi_app = SimpleLoggingMiddleware(app.wsgi_app)
```

### Q6: Why should `debug=True` or `FLASK_DEBUG=1` never be enabled in production environments?
**Answer**:
Setting `debug=True` enables Werkzeug's interactive web-based debugger. If an unhandled exception occurs, Werkzeug displays an interactive Python console in the browser allowing arbitrary Python code execution on the server host, leading to **Remote Code Execution (RCE)** vulnerabilities.

### Q7: What are the `.env` and `.flaskenv` files used for in Flask projects?
**Answer**:
- `.flaskenv`: Used for public, non-sensitive development settings (e.g. `FLASK_APP=app.py`, `FLASK_DEBUG=1`, `FLASK_RUN_PORT=5000`). It is checked into Git version control.
- `.env`: Used for private, sensitive credentials (e.g. `SECRET_KEY`, database passwords, API secret keys). It is added to `.gitignore` and never committed to source control.

### Q8: How can you access the active Flask application object (`current_app`) inside a script or shell without making an HTTP request?
**Answer**:
Use `app.app_context()` context manager:

```python
from app import app
from flask import current_app

with app.app_context():
    print(f"App Name: {current_app.name}")
    print(f"Config Secret: {current_app.config['SECRET_KEY']}")
```

### Q9: What is the role of Werkzeug in the Flask ecosystem?
**Answer**:
Werkzeug is the WSGI utility library underlying Flask. It provides:
1. HTTP Request and Response handling wrappers.
2. High-performance URL routing (`Map`, `Rule`, `BaseConverter`).
3. Thread-safe/async-safe context local proxies (`LocalProxy`).
4. WSGI development server with reloader and interactive debugger.
5. Password hashing utilities (`generate_password_hash`, `check_password_hash`).

### Q10: Write a pure WSGI callable that parses query string parameters without using any third-party framework.
**Answer**:

```python
from urllib.parse import parse_qs

def query_parsing_wsgi_app(environ, start_response):
    query_string = environ.get('QUERY_STRING', '')
    parsed_params = parse_qs(query_string)
    
    status = '200 OK'
    headers = [('Content-Type', 'text/plain; charset=utf-8')]
    start_response(status, headers)
    
    response_body = f"Parsed Query Parameters: {parsed_params}\n"
    return [response_body.encode('utf-8')]
```
