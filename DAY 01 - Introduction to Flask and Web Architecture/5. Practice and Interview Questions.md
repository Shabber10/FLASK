# Day 01: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from absolute web basics up to enterprise Python WSGI internals.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is the difference between a Client and a Server on the Web?
**Answer**:
*   A **Client** (e.g., Google Chrome, Firefox, or a mobile app) is software used by humans to request information from the web and display rendered HTML/CSS pages.
*   A **Server** is a computer connected to the internet 24/7 that hosts backend software (like Python/Flask) and databases. It waits for incoming HTTP requests from clients and responds with data.

---

### Q2: What does WSGI stand for, and what does it do in plain English?
**Answer**:
WSGI stands for **W**eb **S**erver **G**ateway **I**nterface.
In plain English, WSGI is a standard ruleset (defined in PEP 3333) that acts as a universal bridge/translator between web servers (like Nginx or Gunicorn) and Python applications (like Flask or Django). Without WSGI, web servers would not know how to execute Python code.

---

### Q3: What is the IP address `127.0.0.1` and what does it mean?
**Answer**:
`127.0.0.1` is known as **localhost**. It is a special loopback IP address that points directly back to your own computer. When you run a Flask app locally at `http://127.0.0.1:5000/`, your computer is acting as both the Client and the Server.

---

### Q4: What is the difference between an HTTP `GET` request and an HTTP `POST` request?
**Answer**:
*   `GET`: Used to retrieve/read data from a server without modifying anything (e.g., viewing a profile page). Data parameters are attached directly to the URL (`?search=python`).
*   `POST`: Used to send/submit new data to a server (e.g., submitting a login form or uploading a file). Data is sent securely inside the request body payload.

---

### Q5: What does an HTTP status code `404` mean? What about `200` and `500`?
**Answer**:
*   `200 OK`: Success! The server processed the request successfully.
*   `404 Not Found`: Client error. The requested URL path does not exist on the server.
*   `500 Internal Server Error`: Server error. The Python backend crashed or encountered an unhandled code bug.

## 🟡 Level 2: Intermediate Questions

### Q6: What does `__name__` do when passed to `app = Flask(__name__)`?
**Answer**:
`__name__` is a special built-in Python variable containing the name of the active module. Flask uses `__name__` to determine the root filesystem path of your application. Flask uses this root path to locate:
1.  Static assets (`/static`)
2.  HTML templates (`/templates`)
3.  Local instance settings (`/instance`)

---

### Q7: Why is Flask called a "Micro-framework"? Does it mean it can't handle large applications?
**Answer**:
"Micro" does not mean weak. It means Flask keeps its core minimalist—providing routing, HTTP handling, and templating while giving developers freedom to choose their database ORMs, form packages, and authentication tools. Massive enterprise systems (Netflix, Pinterest, Reddit) use Flask at huge scale.

---

### Q8: Explain the difference between Application Context and Request Context in Flask.
**Answer**:
*   **Application Context** (`current_app`, `g`): Holds application-level settings, database connections, and request-scoped temporary storage (`g`). Active during request processing or CLI execution.
*   **Request Context** (`request`, `session`): Encapsulates data specific to the incoming HTTP request (headers, query parameters, POST data, cookies, and session state).

---

### Q9: Why should `debug=True` NEVER be enabled in production environments?
**Answer**:
Setting `debug=True` enables Werkzeug's interactive web-based debugger. If an unhandled exception occurs in production, Werkzeug displays an interactive Python console in the browser allowing arbitrary Python code execution on the server host, leading to **Remote Code Execution (RCE)** vulnerabilities.

---

### Q10: What are `.env` and `.flaskenv` files used for in Flask applications?
**Answer**:
*   `.flaskenv`: Contains public development environment variables (e.g. `FLASK_APP=app.py`, `FLASK_DEBUG=1`). Safe to commit to Git.
*   `.env`: Contains private secrets (e.g., `SECRET_KEY`, database passwords, API secret keys). Must be added to `.gitignore` and never committed to source control.

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: What is PEP 3333 and what problem did WSGI solve in Python web development?
**Answer**:
PEP 3333 defines the **Web Server Gateway Interface (WSGI)** specification. Before WSGI, Python web frameworks required custom server adapters. WSGI solved this fragmentation by defining a universal interface: any WSGI-compliant web server (Gunicorn/uWSGI) can execute any WSGI-compliant application (Flask/Django) without code modification.

---

### Q12: Explain the exact signature and requirements of a WSGI application callable.
**Answer**:
A WSGI application must be a callable object (function or class method) accepting two positional parameters:
1.  `environ`: A Python `dict` containing CGI environment variables, HTTP headers, request metadata, and input streams (`wsgi.input`).
2.  `start_response`: A callback function supplied by the server: `start_response(status, response_headers, exc_info=None)`.

The callable must invoke `start_response()` before yielding response data, and must return an **iterable of byte strings** (e.g. `[b"Hello World"]`).

---

### Q13: How do WSGI Middlewares work in Flask? Provide a code example.
**Answer**:
A WSGI middleware wraps Flask's underlying `app.wsgi_app` callable. It intercepts incoming `environ` data before Flask processes the request and intercepts response headers/status codes before returning bytes to the server.

```python
class LoggingMiddleware:
    def __init__(self, wsgi_app):
        self.wsgi_app = wsgi_app

    def __call__(self, environ, start_response):
        print(f"[LOG] Incoming Request Path: {environ.get('PATH_INFO')}")
        return self.wsgi_app(environ, start_response)

app.wsgi_app = LoggingMiddleware(app.wsgi_app)
```

---

### Q14: What is the main difference between WSGI and ASGI?
**Answer**:
*   **WSGI**: Synchronous protocol designed for HTTP 1.1 using multi-threading or process pools.
*   **ASGI**: Asynchronous protocol designed for high-concurrency event loops (`async`/`await`), supporting HTTP 1.1, HTTP/2, and WebSockets.

---

### Q15: Write a pure WSGI callable that parses query string parameters without using any third-party framework.
**Answer**:

```python
from urllib.parse import parse_qs

def query_parsing_wsgi_app(environ, start_response):
    query_string = environ.get('QUERY_STRING', '')
    parsed_params = parse_qs(query_string)
    
    status = '200 OK'
    headers = [('Content-Type', 'text/plain; charset=utf-8')]
    start_response(status, headers)
    
    response_body = f"Parsed Query Parameters: {parsed_params}\n"
    return [response_body.encode('utf-8')]
```
