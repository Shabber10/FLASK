## 1. Apache Kafka Core Architecture

**Apache Kafka** is a distributed event streaming platform designed for high-throughput, fault-tolerant message queueing:

- **Topic**: A named stream of record messages (e.g. `telemetry_events`).
- **Partition**: Topics are divided into parallel partitions distributed across Kafka brokers to scale throughput.
- **Consumer Group**: A group of background worker processes sharing the workload of reading messages from topic partitions.

```
Kafka Topic: `user_clickstream`
+-----------------------+     +-----------------------+     +-----------------------+
| Partition 0           |     | Partition 1           |     | Partition 2           |
| [Msg 0][Msg 1][Msg 2] |     | [Msg 0][Msg 1][Msg 2] |     | [Msg 0][Msg 1][Msg 2] |
+-----------------------+     +-----------------------+     +-----------------------+
            |                             |                             |
            v                             v                             v
   [ Consumer Worker 1 ]         [ Consumer Worker 2 ]         [ Consumer Worker 3 ]
```

## 2. Python Kafka Producer Integration

Inside Flask ingestion endpoints, send messages asynchronously to Kafka using non-blocking producers:

```python
from confluent_kafka import Producer
import json

producer = Producer({'bootstrap.servers': 'localhost:9092'})

@app.route('/api/v1/telemetry', methods=['POST'])
def ingest_telemetry():
    payload = request.get_json(silent=True) or {}
    
    # Non-blocking produce call
    producer.produce(
        'telemetry_events',
        key=str(payload.get('user_id', '')),
        value=json.dumps(payload).encode('utf-8')
    )
    # Trigger low-latency background IO message dispatch
    producer.poll(0)
    
    # Immediately return HTTP 202 Accepted!
    return jsonify({"status": "queued"}), 202
```

## 3. Real-Time Time-Window Aggregations

Analytical dashboards aggregate events into discrete time windows:

### 1. Tumbling Time Windows
Non-overlapping, continuous fixed time intervals (e.g., Every 1-minute window: 10:00-10:01, 10:01-10:02).

### 2. Sliding Time Windows
Overlapping time intervals that advance continuously (e.g., Total events over the *last 5 minutes*, evaluated every second).

```sql
-- Tumbling 1-Minute Aggregation Query (TimescaleDB / PostgreSQL)
SELECT 
    time_bucket('1 minute', created_at) AS time_window,
    event_type,
    COUNT(*) AS total_events
FROM telemetry_events
GROUP BY time_window, event_type
ORDER BY time_window DESC;
```
