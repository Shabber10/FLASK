# Day 09: Practice & Technical Interview Questions

---

### Q1: Why should you use Flask-Migrate / Alembic instead of `db.create_all()` in production?
**Answer**:
`db.create_all()` only creates tables that do not exist yet. It cannot detect or apply alterations to existing tables (e.g. adding a new column, modifying data types, dropping constraints, or adding indexes). Dropping and recreating tables destroys existing production data. Flask-Migrate / Alembic generates version-controlled migration scripts that incrementally alter schemas without data loss.

---

### Q2: What is the `alembic_version` table and what role does it play during `flask db upgrade`?
**Answer**:
The `alembic_version` table is a single-column database table managed automatically by Alembic. It stores a single string value: the **revision hash** of the current database schema state (e.g. `'a1b2c3d4e5f6'`). 

When `flask db upgrade` is executed, Alembic compares the hash in `alembic_version` against the migration DAG in `migrations/versions/` and executes only the pending `upgrade()` scripts required to reach the target revision head.

---

### Q3: What is SQLite Batch Mode (`render_as_batch=True`) and why is it necessary for SQLite?
**Answer**:
SQLite lacks native SQL support for many `ALTER TABLE` operations (such as dropping a column or modifying column constraints). 

When `render_as_batch=True` is enabled in `migrations/env.py`, Alembic uses a batch workflow: it creates a temporary table with the new schema, copies all existing rows into the temporary table, drops the original table, and renames the temporary table.

### Q4: How do you add a non-nullable column (`nullable=False`) to a database table that already contains existing data rows?
**Answer**:
Adding a `NOT NULL` column without a default value fails on populated tables. Perform a three-step migration inside the revision's `upgrade()` function:
1. Add column with `nullable=True` (or with a `server_default`).
2. Run SQL `UPDATE` statement via `op.execute()` to populate existing `NULL` rows with a default value.
3. Call `op.alter_column(..., nullable=False)` to enforce the non-null constraint.

### Q5: What does `flask db stamp head` do and when would you use it?
**Answer**:
`flask db stamp head` updates the `alembic_version` table value to match the latest revision hash in `migrations/versions/` **without executing any migration SQL code**.

It is used when a database schema has already been manually created or altered, but Alembic's version tracking table is uninitialized or out-of-sync with the codebase.

### Q6: What happens if two developers create migration scripts concurrently on different git branches?
**Answer**:
Alembic detects multiple "heads" (multiple revisions pointing to the same parent `down_revision`), preventing `flask db upgrade` from running due to a branching conflict.

To resolve branching conflicts:
1. Run `flask db heads` to inspect conflicting revision hashes.
2. Run `flask db merge -m "merge_branches" head1_hash head2_hash` to generate a merge revision script that combines both branches into a single linear history chain.

### Q7: How does `flask db migrate` auto-detect model changes, and what changes CANNOT be auto-detected?
**Answer**:
`flask db migrate` compares SQLAlchemy model metadata against database reflection schemas.
- **Can Auto-Detect**: Added/dropped tables, added/dropped columns, changed column nullability, added unique constraints/indexes.
- **Cannot Auto-Detect (Without Extension)**: Column table renames, un-named constraints, database-specific custom types, server default changes (unless `compare_server_default=True` is set in `env.py`).

### Q8: How do you seed static lookup table data inside an Alembic migration script?
**Answer**:
Use `op.bulk_insert()` along with an Alembic `table()` declaration:

```python
from alembic import op
from sqlalchemy.sql import table, column
from sqlalchemy import String, Integer

roles_table = table('roles', column('id', Integer), column('name', String))

def upgrade():
    op.bulk_insert(roles_table, [
        {'id': 1, 'name': 'Admin'},
        {'id': 2, 'name': 'Member'}
    ])
```

### Q9: What is the purpose of `script.py.mako` in the `migrations/` folder?
**Answer**:
`script.py.mako` is a Mako template file that dictates the code structure and imports used when `flask db migrate` autogenerates new revision files in `migrations/versions/`.

### Q10: How do you register a custom Flask CLI command (e.g. `flask seed_db`)?
**Answer**:
Decorate a function with `@app.cli.command('command_name')`:

```python
@app.cli.command('seed_db')
def seed_db():
    click.echo("Seeding initial database data...")
    # Add seed logic here
```
