# Day 09: Schema Evolution, Revisions & Data Seeding

In this section, we examine the internal code structure of Alembic revision files, handling non-nullable column additions to populated tables, data seeding, and SQLite batch mode configuration.

---

## 1. Anatomy of an Alembic Revision File

Every file in `migrations/versions/` contains metadata identifiers and two core functions (`upgrade` and `downgrade`):

```python
"""add user bio and phone

Revision ID: 7a8b9c1d2e3f
Revises: 1a2b3c4d5e6f
Create Date: 2026-08-08 10:00:00.000000

"""
from alembic import op
import sqlalchemy as sa

# Revision Identifiers used by Alembic
revision = '7a8b9c1d2e3f'
down_revision = '1a2b3c4d5e6f'
branch_labels = None
depends_on = None

def upgrade():
    # Executed when running `flask db upgrade`
    op.add_column('users', sa.Column('bio', sa.Text(), nullable=True))
    op.add_column('users', sa.Column('phone', sa.String(length=20), nullable=True))

def downgrade():
    # Executed when running `flask db downgrade`
    op.drop_column('users', 'phone')
    op.drop_column('users', 'bio')
```

## 2. Adding NOT NULL Columns to Populated Tables

Adding a `NOT NULL` column to a table that already contains rows causes database errors unless handled in stages:

### Two-Step Migration Strategy
1. **Step 1**: Add the column as `nullable=True` with a server default or default value in Alembic.
2. **Step 2**: Update existing NULL rows with default data via `op.execute()`.
3. **Step 3**: Alter the column constraint to `nullable=False`.

```python
def upgrade():
    # 1. Add column as nullable
    op.add_column('users', sa.Column('status', sa.String(20), nullable=True))
    
    # 2. Backfill existing NULL rows with default value
    op.execute("UPDATE users SET status = 'active' WHERE status IS NULL")
    
    # 3. Alter column to NOT NULL
    op.alter_column('users', 'status', nullable=False)
```

## 3. SQLite Batch Alter Mode (`batch_alter_table`)

Relational databases like PostgreSQL and MySQL support native `ALTER TABLE DROP COLUMN` or `ALTER TABLE ALTER COLUMN`. SQLite has limited native `ALTER TABLE` support.

To perform complex schema alterations on SQLite, Alembic must use **Batch Mode**, which creates a temporary table, copies existing data over, drops the old table, and renames the temporary table.

### Enabling Batch Mode in `migrations/env.py`

Modify `migrations/env.py` to enable `render_as_batch=True`:

```python
def run_migrations_online():
    connectable = engine_from_config(
        config.get_section(config.config_ini_section),
        prefix="sqlalchemy.",
        poolclass=pool.NullPool,
    )

    with connectable.connect() as connection:
        context.configure(
            connection=connection,
            target_metadata=target_metadata,
            render_as_batch=True  # Enables SQLite Batch Alter Support!
        )

        with context.begin_transaction():
            context.run_migrations()
```

## 4. Data Seeding inside Revisions (`op.bulk_insert`)

Alembic revisions can seed lookup tables (e.g. system roles, permission flags) during upgrades:

```python
from sqlalchemy.sql import table, column
from sqlalchemy import String, Integer

roles_table = table('roles',
    column('id', Integer),
    column('name', String)
)

def upgrade():
    op.create_table('roles',
        sa.Column('id', sa.Integer(), primary_key=True),
        sa.Column('name', sa.String(length=50), nullable=False)
    )
    
    # Seed initial system roles
    op.bulk_insert(roles_table, [
        {'id': 1, 'name': 'Administrator'},
        {'id': 2, 'name': 'Moderator'},
        {'id': 3, 'name': 'Member'}
    ])
```
