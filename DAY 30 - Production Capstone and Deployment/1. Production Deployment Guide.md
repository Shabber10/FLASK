## 1. The 12-Factor App Rules for Enterprise Flask

The **12-Factor App** methodology defines modern cloud-native software architecture principles:

1.  **Codebase**: One codebase tracked in Revision Control (Git), many deployments (Dev, Staging, Prod).
2.  **Dependencies**: Explicitly declare dependencies in `requirements.txt` or `pyproject.toml`.
3.  **Config**: Store environment variables (Database URLs, API keys) in environment variables—NEVER hardcode secrets in source code!
4.  **Backing Services**: Treat databases (PostgreSQL), caches (Redis), and brokers (RabbitMQ) as attached network resources.
5.  **Stateless Processes**: Flask processes must be completely stateless. Store user sessions in Redis or JWTs so any Gunicorn worker can handle any request.
6.  **Logs**: Treat logs as event streams. Output JSON logs to `sys.stdout` so Docker/Kubernetes can capture them.

#### ⚖️ Development Server (`flask run`) vs 3-Tier Production Architecture

| Deployment Aspect | Development Server (`flask run`) | Production 3-Tier Stack (Nginx + Gunicorn) |
| :--- | :--- | :--- |
| **Concurrency Capacity** | 🐢 Single-Threaded (1 user request at a time) | ⚡ Multi-Worker (Gunicorn pre-fork process pool) |
| **SSL HTTPS Encryption** | ❌ Plain HTTP (No SSL/TLS termination) | 🔒 Nginx handles Let's Encrypt SSL Certificates |
| **Static File Delivery** | 🐢 Slow Python WSGI static serving | ⚡ Ultra-fast Nginx raw C file streaming |
| **Crash Resilience** | 💥 Unhandled exception crashes entire server | 🛡️ Gunicorn auto-restarts failed worker processes |
| **Security Shielding** | ❌ No DDoS or slowloris protection | 🛡️ Nginx limits request rates and buffers slow clients |

## 2. Production Environment & Secrets Management

Use `python-dotenv` or cloud secret managers (AWS Secrets Manager, HashiCorp Vault):

```python
# config.py
import os
from dotenv import load_dotenv

load_dotenv()  # Loads .env in development

class ProductionConfig:
    DEBUG = False
    TESTING = False
    SECRET_KEY = os.environ.get('SECRET_KEY')  # Required in Production!
    SQLALCHEMY_DATABASE_URI = os.environ.get('DATABASE_URL')
    SQLALCHEMY_ENGINE_OPTIONS = {
        'pool_size': 10,
        'max_overflow': 20,
        'pool_recycle': 1800,
        'pool_pre_ping': True
    }
```

## 4. Kubernetes Healthcheck & Readiness Probes (`/healthz` & `/readyz`)

Cloud load balancers and Kubernetes require health probes to monitor pod health:

*   **Liveness Probe (`GET /healthz`)**: Confirms the Flask process is alive. If this returns 500 or times out, Kubernetes restarts the container!
*   **Readiness Probe (`GET /readyz`)**: Confirms the Flask process AND backing services (PostgreSQL & Redis) are ready to accept traffic!

```python
@app.route('/healthz', methods=['GET'])
def liveness_check():
    """Liveness probe returning 200 OK if server process is running."""
    return jsonify({"status": "UP", "timestamp": datetime.datetime.utcnow().isoformat()}), 200

@app.route('/readyz', methods=['GET'])
def readiness_check():
    """Readiness probe verifying DB and Redis connectivity."""
    try:
        # Check Database
        db.session.execute(text('SELECT 1'))
        # Check Redis
        redis_client.ping()
        return jsonify({"status": "READY", "database": "CONNECTED", "redis": "CONNECTED"}), 200
    except Exception as e:
        app.logger.error(f"Readiness check failed: {str(e)}")
        return jsonify({"status": "NOT_READY", "error": str(e)}), 503
```
