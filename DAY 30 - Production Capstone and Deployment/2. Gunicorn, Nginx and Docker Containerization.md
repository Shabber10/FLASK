## 1. Gunicorn Production Setup

**Gunicorn (Green Unicorn)** is a Python WSGI HTTP server for UNIX. It uses a pre-fork worker model to run multiple parallel worker processes.

### Worker Formula Rule:
Calculate the optimal number of Gunicorn workers using:
$$\text{Workers} = (2 \times \text{CPU Cores}) + 1$$

For a 2-Core Server: $(2 \times 2) + 1 = 5 \text{ Workers}$.

```bash
# Launch Gunicorn with 5 Workers on Port 8000
gunicorn --workers=5 \
         --worker-class=gthread \
         --threads=2 \
         --bind=0.0.0.0:8000 \
         --access-logfile - \
         --error-logfile - \
         "app_factory:create_app('production')"
```

## 2. Nginx Reverse Proxy Configuration

Nginx sits in front of Gunicorn, handling SSL HTTPS encryption, static file caching, and request proxying:

```nginx
# /etc/nginx/sites-available/flask_app
server {
    listen 80;
    server_name api.mycompany.com;
    return 301 https://$host$request_uri; # Redirect HTTP -> HTTPS
}

server {
    listen 443 ssl http2;
    server_name api.mycompany.com;

    ssl_certificate /etc/letsencrypt/live/api.mycompany.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.mycompany.com/privkey.pem;

    # Static Assets Served Directly by Nginx (Bypasses Flask!)
    location /static/ {
        alias /var/www/flask_app/static/;
        expires 30d;
    }

    # Proxy API Requests to Gunicorn WSGI Server
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 3. Production Multi-Stage `Dockerfile`

Create an optimized, secure Docker image using non-root user privileges:

```dockerfile
# Multi-Stage Dockerfile for Flask
FROM python:3.11-slim AS builder

WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir --user -r requirements.txt

# Final Production Stage
FROM python:3.11-slim AS runner

# Create non-root system user for container security!
RUN useradd -m -u 1000 appuser
WORKDIR /app

# Copy installed dependencies and code
COPY --from=builder /root/.local /home/appuser/.local
COPY . .

ENV PATH=/home/appuser/.local/bin:$PATH
USER appuser

EXPOSE 8000

CMD ["gunicorn", "--workers=4", "--bind=0.0.0.0:8000", "app:app"]
```

## 4. Multi-Container Orchestration (`docker-compose.yml`)

Orchestrate your entire application stack in a single command:

```yaml
version: '3.8'

services:
  web:
    build: .
    command: gunicorn --workers=4 --bind 0.0.0.0:8000 "app:create_app('production')"
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://flaskuser:flaskpass@postgres:5432/flaskdb
      - REDIS_URL=redis://redis:6379/0
    depends_on:
      - postgres
      - redis

  postgres:
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: flaskuser
      POSTGRES_PASSWORD: flaskpass
      POSTGRES_DB: flaskdb
    volumes:
      - postgres_data:/var/lib/postgresql/data

  redis:
    image: redis:alpine

  celery_worker:
    build: .
    command: celery -A app.celery worker --loglevel=info
    depends_on:
      - redis

volumes:
  postgres_data:
```

Command to start full microservice stack:
```bash
docker-compose up -d --build
```
