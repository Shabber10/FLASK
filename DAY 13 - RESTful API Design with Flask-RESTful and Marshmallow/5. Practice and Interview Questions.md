# Day 13: Practice & Technical Interview Questions

---

### Q1: What is the difference between `PUT` and `PATCH` HTTP methods in RESTful API design?
**Answer**:
- **`PUT`**: Replaces the **entire** target resource state. The client must supply a complete representation payload. Missing attributes in the request payload are reset or set to default/NULL values. `PUT` operations are **idempotent**.
- **`PATCH`**: Applies a **partial** update to the target resource. Only the attributes explicitly provided in the request payload are modified; unmentioned fields remain untouched. `PATCH` operations are **non-idempotent**.

---

### Q2: What is the difference between `schema.dump()` and `schema.load()` in Marshmallow?
**Answer**:
- `schema.dump(obj)`: **Serialization**. Takes a Python object (e.g. SQLAlchemy model instance) and converts it into a JSON-serializable dictionary.
- `schema.load(data_dict)`: **Deserialization & Validation**. Takes an unvalidated JSON dictionary, validates field rules, type coercions, and constraints, returning a clean Python dictionary (or raising a `ValidationError`).

---

### Q3: What is Idempotency in REST APIs, and which HTTP verbs are idempotent?
**Answer**:
An HTTP method is **idempotent** if making multiple identical requests has the exact same effect on the server database state as making a single request.
- **Idempotent Verbs**: `GET`, `PUT`, `DELETE`, `HEAD`, `OPTIONS`.
- **Non-Idempotent Verbs**: `POST`, `PATCH`.

---

### Q4: When should an API endpoint return `201 Created` vs `200 OK`?
**Answer**:
- **`201 Created`**: Returned after a `POST` request successfully creates a new resource in the database. The response should optionally include a `Location` header pointing to the newly created resource URI.
- **`200 OK`**: Returned for successful `GET`, `PUT`, or `PATCH` operations where data is retrieved or modified without creating a new entity.

---

### Q5: What status code should be returned when client JSON fails validation rules?
**Answer**:
Return **`422 Unprocessable Entity`** (or `400 Bad Request`). `422` signifies that the server understands the JSON syntax of the request, but the payload parameters fail validation constraints (e.g. invalid email format or password too short).

---

### Q6: How do `dump_only=True` and `load_only=True` work in Marshmallow fields?
**Answer**:
- `dump_only=True`: Field is included during **serialization** (`schema.dump()`), but ignored during **deserialization** (`schema.load()`). (e.g. auto-incremented `id`, `created_at` timestamps).
- `load_only=True`: Field is processed during **deserialization** (`schema.load()`), but excluded from public JSON responses during **serialization** (`schema.dump()`). (e.g. raw `password` inputs).

---

### Q7: How do you handle nested model relationships in Marshmallow schemas?
**Answer**:
Use `fields.Nested()`:

```python
class CommentSchema(Schema):
    id = fields.Int(dump_only=True)
    body = fields.Str(required=True)

class PostSchema(Schema):
    id = fields.Int(dump_only=True)
    title = fields.Str(required=True)
    comments = fields.Nested(CommentSchema, many=True, dump_only=True)
```

---

### Q8: What does `many=True` do in `schema.dump(objs, many=True)`?
**Answer**:
Passing `many=True` instructs Marshmallow to iterate over an iterable collection (such as a list of ORM instances) and serialize each item, returning a list of dictionaries instead of expecting a single model object.

---

### Q9: Why is `204 No Content` preferred for HTTP `DELETE` endpoints?
**Answer**:
`204 No Content` explicitly indicates that the deletion request was processed successfully and that the response body is intentionally empty, saving bandwidth.

---

### Q10: How do Flask-RESTful `Resource` classes map to URL routes?
**Answer**:
`Resource` classes define methods matching HTTP verbs (`get()`, `post()`, `put()`, `patch()`, `delete()`). Registering the resource with `api.add_resource(MyResource, '/url')` maps incoming HTTP requests directly to the corresponding verb method on the class.
