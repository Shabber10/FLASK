# Day 14: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, plus a **Rapid-Fire 1-Liner Interview Recap** covering state management, cookie security flags, session lifecycles, and Redis server-side architecture.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is HTTP Statelessness in simple terms?
**Answer**:
HTTP Statelessness means that the web server treats every incoming HTTP request as completely independent. It has no built-in memory to recognize that two separate requests came from the exact same user. State management is required to persist identity across requests.

---

### Q2: What is the core difference between a Cookie and a Session?
**Answer**:
* **Cookie**: A small text file (~4 KB) stored directly in the user's web browser and sent automatically in HTTP headers. Best for non-sensitive data like UI themes.
* **Session**: A server-side or cryptographically signed mechanism that remembers the logged-in user state. The browser receives an encrypted or random session identifier, while private data is verified by the server.

---

### Q3: Is data inside Flask's default client-side session encrypted?
**Answer**:
No. Default Flask sessions are **signed (tamper-proof)** using HMAC with `SECRET_KEY`, but **NOT encrypted**. Anyone can decode the Base64 session payload in browser developer tools. Never store raw passwords or sensitive credentials in `session`.

---

### Q4: How do you set and read a cookie in Flask?
**Answer**:
```python
from flask import make_response, request

# Setting a cookie
res = make_response("Cookie set!")
res.set_cookie("username", "Jani", max_age=86400)

# Reading a cookie
user = request.cookies.get("username", "Guest")
```

---

### Q5: What happens when a user calls `session.clear()` vs `session.pop('user')`?
**Answer**:
* `session.pop('user', None)` removes only the specific key `'user'`, leaving any other session data intact.
* `session.clear()` completely wipes all key-value pairs stored in the active session dictionary, logging the user out completely.

---

### Q6: What is the default lifespan of a Flask session?
**Answer**:
* If `session.permanent = False` (default), the session is a "browser session" and expires as soon as the user closes their browser window.
* If `session.permanent = True`, it lasts for 31 days by default (or the custom duration configured via `app.permanent_session_lifetime`).

## 🟡 Level 2: Intermediate Questions

### Q7: How does `SESSION_COOKIE_HTTPONLY = True` protect against XSS attacks?
**Answer**:
The `HttpOnly` flag instructs the browser that the cookie must only be sent in HTTP headers and **cannot be accessed by client-side JavaScript** (`document.cookie`). If an attacker injects a malicious XSS script into your page, they cannot steal the session cookie.

---

### Q8: What does `SESSION_COOKIE_SECURE = True` do?
**Answer**:
It instructs the browser to send the session cookie **ONLY over encrypted `HTTPS://` connections**, preventing man-in-the-middle (MITM) network sniffers on public Wi-Fi from intercepting the cookie over unencrypted HTTP.

---

### Q9: What is `SESSION_COOKIE_SAMESITE = 'Lax'` and how does it prevent CSRF?
**Answer**:
`SameSite='Lax'` prevents the browser from sending the session cookie when a request originates from a third-party website (e.g. clicking a link on an external phishing site). This blocks Cross-Site Request Forgery (CSRF) attacks.

---

### Q10: How does Flask verify that a client-side session cookie hasn't been tampered with?
**Answer**:
Flask uses the `itsdangerous` library to compute an HMAC SHA-256 signature using `SECRET_KEY`. When the client sends the cookie back, Flask recomputes the signature. If a user modified the payload (e.g. changing `user_id` from `42` to `1`), the signature check fails and Flask discards the session.

---

### Q11: When does a session cookie get removed or invalidated?
**Answer**:
There are 3 main triggers:
1. **Session Timeout / Expiry**: When the time elapsed exceeds `permanent_session_lifetime`, the server rejects the expired timestamp.
2. **User Logout**: When `session.clear()` or `session.pop()` is called, removing user identity from the session.
3. **Manual Cookie Deletion**: When the user clears their browser cookies in browser settings.

---

### Q12: Why should you use `werkzeug.security` for database authentication instead of plain SQL password matching?
**Answer**:
Plaintext passwords (`WHERE password = user_input`) expose user credentials if the database is breached. `werkzeug.security.generate_password_hash` uses strong salted hashing algorithms (like `scrypt` or `pbkdf2`), and `check_password_hash` performs secure constant-time hash comparisons.

## 🔴 Level 3: Advanced & Enterprise Questions

### Q13: Why are Server-Side Sessions (using Redis) required for enterprise production systems?
**Answer**:
Enterprise systems require Server-Side Sessions because:
1. Browser cookies have a strict **4KB size limit**, which overflows when storing large session objects.
2. Client-side cookies cannot be **instantly revoked** by an administrator (e.g. forcing a global logout after a password reset). Redis allows instant deletion of session keys.
3. Client-side session data is visible to users via Base64 decoding.

---

### Q14: What is the difference between `'filesystem'` and `'redis'` in `Flask-Session`?
**Answer**:
* `'filesystem'`: Stores session files in a local folder (`flask_session/`) on the server disk. Good for single-server development or staging, but fails in multi-server load-balanced clusters.
* `'redis'`: Stores sessions in a centralized, ultra-fast in-memory cache shared across multiple Flask instances with automatic TTL key expiration.

---

### Q15: How can an administrator implement instant single-user session revocation in Redis?
**Answer**:
Query Redis for the target user's session UUID key and delete it directly:
```python
redis_client = app.config['SESSION_REDIS']
redis_client.delete(f"session:{target_session_uuid}")
```
The next time the user makes an HTTP request, Flask looks up the UUID in Redis, finds no matching key, and treats the request as unauthenticated.

---

### Q16: What is Session Fixation and how do you prevent it in Flask?
**Answer**:
Session Fixation occurs when an attacker tricks a victim into using a known session ID prior to logging in. Prevent it by calling `session.clear()` or regenerating the session ID immediately upon successful authentication.

---

### Q17: What happens if `SECRET_KEY` is leaked or changed in a Flask application?
**Answer**:
* **If changed/rotated**: All existing active client-side signed session cookies fail HMAC verification, instantly logging out all current users across the platform.
* **If leaked**: Attackers can forge valid HMAC signatures and impersonate any user on the platform.

## 🎓 Rapid-Fire 1-Liner Interview Recap

> **Q: Why is State Management required in web applications?**  
> **A:** Because HTTP is stateless and the server forgets the user after every request. State management identifies and remembers users across requests.

> **Q: What is the difference between Cookies and Sessions?**  
> **A:** Cookies store small data (~4KB) in the browser, while Sessions store user data on the server with a signed/random identifier in the browser.

> **Q: When is a session cookie removed or invalidated?**  
> **A:** When the session lifetime expires, when the user logs out (`session.clear()`), or when the user clears browser cookies.

> **Q: What does `HttpOnly` prevent?**  
> **A:** It blocks browser JavaScript (`document.cookie`) from accessing cookies, preventing XSS token theft.

> **Q: What does `Secure` enforce?**  
> **A:** It forces cookies to be sent over encrypted HTTPS connections only.
