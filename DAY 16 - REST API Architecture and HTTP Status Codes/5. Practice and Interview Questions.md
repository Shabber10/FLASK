# Day 16: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from API basics up to HTTP method idempotency, RFC 7807 problem details, and API versioning strategies.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is an API in simple terms?
**Answer**:
An API (Application Programming Interface) is a software messenger that allows two different computer applications (such as a mobile phone app and a server database) to exchange structured data over a network.

---

### Q2: What is REST?
**Answer**:
REST (Representational State Transfer) is a standardized set of architectural principles for designing web APIs using standard HTTP verbs (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`) and JSON payloads over clean resource URLs.

---

### Q3: What is a Resource in a RESTful API?
**Answer**:
A Resource is a data entity or object (like Users, Products, or Orders) represented by a clean plural noun URL path (e.g. `/api/v1/users`).

---

### Q4: What is the difference between status code `200 OK` and `404 Not Found`?
**Answer**:
*   `200 OK`: Indicates that the request succeeded and the server returned the requested data payload.
*   `404 Not Found`: Indicates that the requested resource URL path or resource ID does not exist on the server.

---

### Q5: Why should API endpoints return JSON instead of HTML web pages?
**Answer**:
JSON is a lightweight, language-agnostic data format that can be easily parsed by any client application (iOS, Android, React, Python scripts, or microservices), unlike HTML which is designed specifically for web browser rendering.

---

## 🟡 Level 2: Intermediate Questions

### Q6: What is the exact difference between `PUT` and `PATCH` in RESTful APIs?
**Answer**:
*   `PUT`: Performs a **full replacement** of the resource. The client must supply all required fields of the resource payload.
*   `PATCH`: Performs a **partial update**. The client sends only the specific attributes that need to be modified.

---

### Q7: When should an API return `201 Created` versus `204 No Content`?
**Answer**:
*   `201 Created`: Returned after a successful `POST` request that creates a new resource. The response body includes the newly created object.
*   `204 No Content`: Returned after a successful operation (typically `DELETE`) where the server does not need to return any payload body.

---

### Q8: What does HTTP Method Idempotency mean? Which HTTP methods are idempotent?
**Answer**:
An HTTP method is **Idempotent** if executing the exact same request once or multiple times produces the exact same server state.
*   **Idempotent Methods**: `GET`, `PUT`, `DELETE`.
*   **Non-Idempotent Method**: `POST` (sending 10 identical POST requests creates 10 duplicate records).

---

### Q9: What is the difference between status code `400 Bad Request` and `422 Unprocessable Entity`?
**Answer**:
*   `400 Bad Request`: The request syntax itself is malformed or unparseable JSON.
*   `422 Unprocessable Entity`: The JSON syntax is valid, but the data payload fails semantic business validation rules (e.g. a negative price or missing required key).

---

### Q10: Why should RESTful URLs use nouns instead of verbs?
**Answer**:
REST relies on using standard HTTP verbs (`GET`, `POST`, `DELETE`) to express actions. Including verbs in the URL path (like `/getUsers` or `/deleteProduct`) creates redundant, unstandardized RPC-style endpoints. Clean RESTful paths use plural nouns (`/api/v1/products`).

---

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: What is RFC 7807 (Problem Details for HTTP APIs)?
**Answer**:
RFC 7807 is an official IETF standard for returning standardized, machine-readable JSON error details. It defines standard fields like `type`, `title`, `status`, `detail`, and `instance` so clients can parse error responses reliably across any API.

---

### Q12: What are the 3 common API Versioning strategies in enterprise systems?
**Answer**:
1.  **URI Path Versioning (Most Common)**: `/api/v1/products` vs `/api/v2/products`.
2.  **Custom Request Header Versioning**: `X-API-Version: 2`.
3.  **Accept Header Content Negotiation**: `Accept: application/vnd.company.v2+json`.

---

### Q13: What is HATEOAS in RESTful API design?
**Answer**:
HATEOAS (Hypermedia As The Engine Of Application State) is a REST constraint where API responses dynamically include hypermedia links (`_links`) guiding the client on what actions can be performed next from the current resource state.

---

### Q14: How should a REST API handle pagination for large collections?
**Answer**:
Use query parameters (`/api/v1/products?page=2&per_page=20`) and return pagination metadata inside the response envelope (`page`, `per_page`, `total_records`, `total_pages`).

---

### Q15: What status code should be returned when a database unique constraint fails (e.g., duplicate email registration)?
**Answer**:
`HTTP 409 Conflict`, which explicitly signals that the request could not be completed due to a conflict with the current state of the target resource.
