# Day 16: Practice & Technical Interview Questions

This comprehensive question bank is organized into **3 progressive levels**, from fundamental concepts to intermediate status code distinctions and enterprise API architectures.

---

## 🟢 Level 1: Beginner & Conceptual Questions

### Q1: What is an API in simple terms?
**Answer**:
An API (Application Programming Interface) is a software bridge that allows two different applications to communicate and exchange data.
* **Real-life analogy**: A waiter in a restaurant taking orders from a customer (Client) to the kitchen chef (Server) and bringing back the prepared food (Response).

---

### Q2: What is the difference between API, REST API, and RESTful API?
**Answer**:
* **API**: Any medium or interface that allows two software programs to communicate (can follow any format or protocol like SOAP, GraphQL, or custom RPC).
* **REST API**: An API designed following REST principles, typically using standard HTTP verbs (`GET`, `POST`, `PUT`, `DELETE`) and clean plural noun resource URLs (`/students`).
* **RESTful API**: A REST API that strictly and consistently satisfies **all** official REST architectural constraints (Client-Server, Statelessness, Cacheability, Uniform Interface, Layered System).
* **Rule to Remember**: *"Every RESTful API is a REST API, but not every REST API is fully RESTful."* (Just like every sports bike is a bike, but not every bike is a sports bike).

---

### Q3: What is the difference between `401 Unauthorized` and `403 Forbidden`?
**Answer**:
* **`401 Unauthorized`**: Authentication is missing or invalid. The user is **NOT logged in**.
  * *Analogy*: Trying to watch a Netflix video without logging into your account.
* **`403 Forbidden`**: The user is successfully authenticated (logged in), but **lacks permission** to perform this action.
  * *Analogy*: An employee entering the office building with a valid ID card, but being denied access into the CEO's private safe.

---

### Q4: Why should we use `jsonify()` instead of returning plain Python dictionaries in Flask?
**Answer**:
`jsonify()` serializes the Python dictionary or list into a valid JSON string and automatically attaches the critical HTTP header: `Content-Type: application/json`.
While modern Flask allows returning a dictionary directly, `jsonify()`:
1. Is explicit and industry-standard.
2. Supports serializing top-level arrays/lists cleanly.
3. Is clear in interviews and production codebases.

---

### Q5: What is the difference between `request.args`, `request.form`, and `request.get_json()` in Flask?
**Answer**:
* `request.args`: Extracts URL query parameters from the query string (e.g. `/students?course=python` ➔ `request.args.get('course')`).
* `request.form`: Extracts data submitted via standard HTML `<form>` POST submissions (`application/x-www-form-urlencoded` or `multipart/form-data`).
* `request.get_json()`: Parses and extracts the JSON body payload sent in REST API requests with `Content-Type: application/json`.

## 🟡 Level 2: Intermediate Status Codes & CRUD Questions

### Q6: What is the difference between `400 Bad Request` and `422 Unprocessable Content`?
**Answer**:
* **`400 Bad Request`**: The request syntax is broken or malformed (e.g., incomplete JSON like `{"name": }` or invalid characters).
* **`422 Unprocessable Content`**: The JSON syntax is completely valid, but the data fails business validation (e.g., `age: -5` or missing a required field).

---

### Q7: What is the exact difference between `PUT` and `PATCH`?
**Answer**:
* `PUT`: Completely replaces the resource. All fields must be supplied by the client.
* `PATCH`: Partially updates only the specific fields supplied in the request body.

---

### Q8: When should an API return `201 Created` versus `204 No Content`?
**Answer**:
* `201 Created`: Returned after a successful `POST` request that creates a new record in the database. Returns the newly created object.
* `204 No Content`: Returned when an operation succeeds (often `DELETE`), but the server sends an empty body (`return "", 204`).

---

### Q9: What does HTTP Method Idempotency mean? Which methods are idempotent?
**Answer**:
An HTTP method is **Idempotent** if repeating the exact same request 1 time or 100 times produces the exact same server state.
* **Idempotent**: `GET`, `PUT`, `DELETE`.
* **Non-Idempotent**: `POST` (repeating `POST /students` creates duplicate students).

---

### Q10: Why should RESTful URLs use nouns instead of verbs?
**Answer**:
In REST, the action is defined by the **HTTP Method** (`GET`, `POST`, `DELETE`). Adding verbs in the URL path (like `/getAllStudents` or `/deleteStudent`) is redundant. REST uses clean plural nouns (`/students`, `/students/101`).

## 🔴 Level 3: Advanced & Enterprise Architecture Questions

### Q11: What status code is returned on database constraint conflicts (e.g. duplicate email)?
**Answer**:
`HTTP 409 Conflict`, which explicitly signals that the request could not be processed because it conflicts with current server data.

---

### Q12: What are Roy Fielding's 6 REST Architectural Constraints?
**Answer**:
1. Client-Server Separation
2. Statelessness
3. Cacheability
4. Uniform Interface
5. Layered System
6. Code on Demand (Optional)

---

### Q13: What is RFC 7807 (Problem Details for HTTP APIs)?
**Answer**:
An IETF standard schema for returning machine-readable JSON error details with consistent keys: `type`, `title`, `status`, `detail`, and `instance`.

---

### Q14: How should REST APIs implement API versioning?
**Answer**:
1. **URI Path Versioning (Recommended)**: `/api/v1/students`.
2. **Custom Header**: `X-API-Version: 1`.
3. **Accept Header**: `Accept: application/vnd.app.v1+json`.

---

### Q15: What is HATEOAS?
**Answer**:
Hypermedia As The Engine Of Application State (HATEOAS) is a REST constraint where API responses include hypermedia `_links` instructing the client on next possible actions from the current state.
