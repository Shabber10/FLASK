# Day 16: REST API Architecture & HTTP Status Codes

## 1. REST Architectural Constraints
Representational State Transfer (REST) APIs rely on stateless client-server interaction:
- **GET**: Read resource state.
- **POST**: Create new resource instance.
- **PUT**: Replace existing resource state entirely.
- **PATCH**: Partially update resource attributes.
- **DELETE**: Remove resource instance.

## 2. Standardized HTTP Status Codes
- `200 OK`: Request succeeded.
- `201 Created`: Resource successfully created.
- `204 No Content`: Successful deletion (no response body).
- `400 Bad Request`: Payload validation failed.
- `401 Unauthorized`: Missing or invalid credentials.
- `403 Forbidden`: Authenticated user lacks permission.
- `404 Not Found`: Resource endpoint does not exist.
- `422 Unprocessable Entity`: Semantic validation errors.
