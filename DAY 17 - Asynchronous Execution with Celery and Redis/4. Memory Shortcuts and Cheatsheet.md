## 🧠 Memory Mnemonics

### 1. Celery Architecture Components
Remember **C-E-L-E-R-Y** rules:
- **C**: **Client / Producer** (Flask app dispatching tasks via `.delay()`)
- **E**: **Execution Worker** (`celery worker` process pulling tasks from broker)
- **L**: **Lightweight Message Format** (JSON serialized task arguments)
- **E**: **Event Scheduler** (`celery beat` for cron/interval scheduled jobs)
- **R**: **Redis / RabbitMQ Broker** (Buffering queued tasks safely)
- **Y**: **Yielded Result Backend** (`AsyncResult(task_id)` status lookups)

---

### 2. Task Lifecycle States
- **`PENDING`**: Queued in broker, awaiting a worker.
- **`STARTED` / `PROGRESS`**: Worker is actively executing task.
- **`SUCCESS`**: Completed successfully; return value stored in backend.
- **`FAILURE`**: Exception raised during task execution.
- **`RETRY`**: Failed task waiting for automatic retry interval.

## ⚡ Quick-Reference Code Snippets

### 1. Flask Celery Application Context Wrapper
```python
def celery_init_app(app: Flask) -> Celery:
    class FlaskTask(Task):
        def __call__(self, *args, **kwargs):
            with app.app_context():
                return self.run(*args, **kwargs)

    celery_app = Celery(app.name, task_cls=FlaskTask)
    celery_app.config_from_object(app.config["CELERY"])
    return celery_app
```

### 2. Dispatching Tasks & Retries
```python
# Dispatch task asynchronously
task = my_task.delay(arg1, arg2)

# Task with Retry Logic
@celery_app.task(bind=True, max_retries=3)
def retry_task(self, data):
    try:
        process(data)
    except Exception as exc:
        raise self.retry(exc=exc, countdown=10)
```

### 3. CLI Commands
```bash
# Start Worker Process
celery -A app.celery_app worker --loglevel=info

# Start Beat Scheduler Daemon
celery -A app.celery_app beat --loglevel=info
```
