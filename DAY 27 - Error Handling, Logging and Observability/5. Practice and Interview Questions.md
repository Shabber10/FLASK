# Day 27: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from error handling and logging basics up to structured JSON logging, correlation IDs, custom exception hierarchies, and production APM tracing.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is the purpose of Error Handling in web applications?
**Answer**:
Error Handling intercepts application exceptions and crashes gracefully, ensuring users receive clean, formatted HTTP error responses (e.g. JSON error payloads) instead of unformatted 500 HTML server crash pages.

---

### Q2: What are the 5 standard Python Logging Levels in order of increasing severity?
**Answer**:
1. `DEBUG`: Detailed diagnostic information.
2. `INFO`: Confirmation that things are operating normally.
3. `WARNING`: Indication of an unexpected occurrence.
4. `ERROR`: Serious error; a specific function failed.
5. `CRITICAL`: Fatal error; application may crash completely.

---

### Q3: Why is Structured JSON Logging preferred over plain text `print()` statements in production?
**Answer**:
Plain text logs cannot be parsed or searched easily by automated log monitoring systems. Structured JSON logs encode key-value pairs (like `level`, `user_id`, `correlation_id`), allowing platforms like Datadog, ELK, or CloudWatch to query and filter millions of log entries instantly.

---

### Q4: How do you log messages in Flask?
**Answer**:
Use Flask's built-in `app.logger` instance:

```python
app.logger.info("User logged in")
app.logger.error("Database query failed")
```

---

### Q5: What is a Request Correlation ID (`X-Request-ID`)?
**Answer**:
A Correlation ID is a unique UUID string generated when an HTTP request arrives. It accompanies the request across all internal functions and microservices, allowing engineers to trace a single user request across all generated log entries.

---

## 🟡 Level 2: Intermediate Questions

### Q6: Why should internal exception stack tracebacks never be exposed to users in production?
**Answer**:
Exposing raw stack tracebacks reveals internal file paths, database connection strings, table schemas, and library versions, giving malicious hackers a blueprint to exploit application vulnerabilities.

---

### Q7: How do you log a full exception traceback to a file while returning a generic JSON error to the user?
**Answer**:
Use `exc_info=True` inside `app.logger.error()` in a global `@app.errorhandler`:

```python
@app.errorhandler(Exception)
def handle_crash(err):
    app.logger.error("Unhandled Crash", exc_info=True)
    return jsonify({"error": "Internal Server Error"}), 500
```

---

### Q8: How do you design a custom domain exception hierarchy in Flask?
**Answer**:
Inherit from a custom base exception class that stores HTTP status codes and error payloads:

```python
class BaseAPIException(Exception):
    def __init__(self, message, status_code=400):
        self.message = message
        self.status_code = status_code

class ResourceNotFound(BaseAPIException):
    def __init__(self, item_name):
        super().__init__(f"{item_name} not found", status_code=404)
```

---

### Q9: How do you prevent log files from filling up a server's hard drive?
**Answer**:
Use `logging.handlers.RotatingFileHandler` with `maxBytes` (e.g. 10MB) and `backupCount` (e.g. 5), which automatically rotates old logs and deletes ancient log files when the size limit is reached.

---

### Q10: How do you register a global exception handler for HTTP 404 errors?
**Answer**:
Use `@app.errorhandler(404)`:

```python
@app.errorhandler(404)
def not_found(e):
    return jsonify({"error": "Resource Not Found"}), 404
```

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: How does Application Performance Monitoring (APM) with Sentry work in Flask?
**Answer**:
APM tools like Sentry hook into Flask's WSGI middleware and exception handling pipeline (`sentry_sdk.init(dsn="...")`). When an unhandled exception or slow transaction occurs, Sentry captures the error context, local variable states, user agent, and stack trace in real-time, alerting the engineering team via Slack/email.

---

### Q12: How do you inject Correlation IDs automatically into all Python log records using custom `logging.Filter` classes?
**Answer**:
Define a custom `logging.Filter` subclass that extracts `g.correlation_id` from Flask's request context and sets `record.correlation_id = getattr(g, 'correlation_id', 'N/A')`, ensuring every logger call automatically formats correlation IDs.

---

### Q13: What is the ELK Stack and how does it ingest Flask logs?
**Answer**:
ELK stands for **Elasticsearch** (search engine), **Logstash** (log collector/parser), and **Kibana** (visualization UI). Flask outputs structured JSON logs to stdout or log files, which Filebeat/Logstash ships into Elasticsearch for real-time querying in Kibana.

---

### Q14: What is Log Sampling and why is it used in high-traffic production environments?
**Answer**:
High-traffic APIs generating 100,000 requests per second will generate terabytes of logs, incurring massive storage costs. Log Sampling logs 100% of ERROR and WARNING events, but samples only 1% or 5% of routine `INFO` HTTP GET requests.

---

### Q15: How do OpenTelemetry and W3C Trace Context headers (`traceparent`) enable distributed tracing across microservices?
**Answer**:
W3C Trace Context standardizes the `traceparent` HTTP header (`version-trace_id-parent_id-trace_flags`). When Microservice A calls Microservice B, it forwards `traceparent`. APM systems (Jaeger/Zipkin) stitch these spans together to render a complete timeline waterfall chart of the entire multi-service transaction.
