## 1. Configuring `dictConfig` for Structured JSON Logs

Python's `logging.config.dictConfig` dictionary configuration defines how logs are formatted and where they are output (Console stdout vs File handlers):

```python
import logging
from logging.config import dictConfig
from flask import Flask

# Configure Structured Logging before initializing Flask app!
dictConfig({
    'version': 1,
    'disable_existing_loggers': False,
    'formatters': {
        'json_formatter': {
            'format': '%(asctime)s %(levelname)s %(name)s %(message)s'
        }
    },
    'handlers': {
        'console': {
            'class': 'logging.StreamHandler',
            'stream': 'ext://sys.stdout',
            'formatter': 'json_formatter',
            'level': 'INFO'
        },
        'file_app': {
            'class': 'logging.handlers.RotatingFileHandler',
            'filename': 'logs/app.log',
            'maxBytes': 10485760,  # 10 MB per log file
            'backupCount': 5,      # Retain up to 5 historical log files
            'formatter': 'json_formatter',
            'level': 'INFO'
        }
    },
```python
    'root': {
        'level': 'INFO',
        'handlers': ['console', 'file_app']
    }
})

app = Flask(__name__)
```

#### ⚖️ Unstructured Text Logs vs Structured JSON Logging

| Logging Characteristic | Unstructured Plain Text (`print()`) | Structured JSON Logging (`dictConfig`) |
| :--- | :--- | :--- |
| **Log Format** | Raw string text (`2026-08-10 User failed...`) | Machine-readable JSON (`{"event": "AUTH_FAIL", "user_id": 42}`) |
| **Datadog / ELK Indexing** | 🐢 Slow regex parsing required | ⚡ Instant key-value filtering & indexing |
| **Correlation ID Tracking** | ❌ Hard to trace across microservices | ✅ Injected `correlation_id` key in every record |
| **Log Storage Management** | ⚠️ Fills hard disk until server crashes | 🛡️ `RotatingFileHandler` auto-caps disk size |
| **Severity Level Filtering** | ❌ All logs printed indiscriminately | ✅ Configurable levels (`DEBUG`, `INFO`, `ERROR`) |

## 2. Using `app.logger` inside Route Handlers

Use Flask's built-in `app.logger` to emit log entries across your application:

```python
@app.route('/api/v1/orders', methods=['POST'])
def create_order():
    order_data = request.get_json() or {}
    
    app.logger.info(f"Received order creation request for customer {order_data.get('customer_id')}")
    
    if not order_data.get('items'):
        app.logger.warning("Order creation failed: No items provided in payload")
        return jsonify({"error": "No items provided"}), 400
        
    # Process order...
    app.logger.info("Order #1042 successfully created and stored in DB")
    return jsonify({"status": "success", "order_id": 1042}), 201
```

## 3. Injecting Request Correlation IDs (`X-Request-ID`)

Add a middleware that assigns a unique UUID correlation ID to every incoming HTTP request and attaches it to request context (`g.correlation_id`) and outgoing headers:

```python
import uuid
from flask import request, g

@app.before_request
def assign_correlation_id():
    # Extract X-Request-ID from client header or generate a fresh UUID4
    correlation_id = request.headers.get('X-Request-ID') or str(uuid.uuid4())
    g.correlation_id = correlation_id

@app.after_request
def inject_correlation_header(response):
    # Pass correlation ID back in response headers for client tracing!
    if hasattr(g, 'correlation_id'):
        response.headers['X-Request-ID'] = g.correlation_id
    return response
```
