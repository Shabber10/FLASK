# Day 23: Practice & Technical Interview Questions

---

### Q1: What is SQL Injection (SQLi) and how does SQLAlchemy ORM prevent it?
**Answer**:
SQL Injection occurs when untrusted user input is directly concatenated into raw SQL strings, allowing attackers to manipulate SQL syntax and execute unauthorized database commands.

SQLAlchemy ORM prevents SQLi by using **Prepared Statements with Parameterized Bindings**. User input is passed separately to the database driver as parameter values (not as SQL query executable text), ensuring the database treats input strictly as data literals.

---

### Q2: What is Cross-Site Scripting (XSS) and how does Jinja2 auto-escaping mitigate it?
**Answer**:
XSS occurs when an application includes un-sanitized user input in HTML responses, allowing attackers to inject malicious `<script>` tags that execute JavaScript in victims' browser contexts.

Jinja2 automatically encodes HTML special characters (`<` -> `&lt;`, `>` -> `&gt;`, `"` -> `&quot;`) inside variable interpolations (`{{ var }}`), rendering user input as safe text characters rather than executable HTML tags.

### Q3: What is Cross-Site Request Forgery (CSRF) and how do CSRF Tokens prevent it?
**Answer**:
CSRF tricks an authenticated user's browser into sending unwanted HTTP POST/PUT requests to a vulnerable application where the user holds an active session cookie.

`Flask-WTF` injects cryptographically signed, session-specific CSRF tokens (`csrf_token`) into forms and headers. The server rejects any state-changing request missing a valid token matching the user's session state.

### Q4: What is the purpose of the `Content-Security-Policy` (CSP) HTTP header?
**Answer**:
CSP dictates which domain origins the browser is permitted to load scripts, stylesheets, fonts, and images from. A restrictive CSP policy (`default-src 'self'`) prevents attackers from loading external malicious scripts even if an XSS vulnerability exists.

---

### Q5: What does the `X-Frame-Options` header protect against?
**Answer**:
`X-Frame-Options` prevents **Clickjacking attacks**, where an attacker embeds a transparent `<iframe>` of your web page over a deceptive button on a malicious site, tricking users into clicking buttons (e.g. "Transfer Money") without their knowledge. Setting `X-Frame-Options: DENY` or `SAMEORIGIN` stops browsers from loading the site in iFrames.

### Q6: Why should `Flask-Limiter` use a Redis storage backend in production instead of in-memory storage?
**Answer**:
In multi-worker production deployments (e.g. Gunicorn with 4 workers), memory-based rate limiting tracks request counters per worker process independently. An attacker could bypass rate limits by distributing requests across workers. Redis provides a centralized, shared counter store across all Gunicorn worker processes.

---

### Q7: What is HSTS (`Strict-Transport-Security`) and why is `max-age=31536000` recommended?
**Answer**:
HSTS instructs web browsers to automatically convert all future HTTP requests to HTTPS before sending them to the server, preventing Man-in-the-Middle (MitM) SSL stripping attacks. `max-age=31536000` sets this enforcement policy for 1 year (31,536,000 seconds).

---

### Q8: What security risks occur if `DEBUG = True` is left enabled in production?
**Answer**:
1. **Interactive Debugger**: Exposes Werkzeug's web-based interactive Python console on unhandled exceptions, allowing remote arbitrary code execution (RCE).
2. **Information Disclosure**: Exposes environment variables, secret keys, file paths, database schemas, and stack traces to visitors.

---

### Q9: What is the `X-Content-Type-Options: nosniff` header?
**Answer**:
It prevents browsers from "MIME-sniffing" response bodies away from the declared `Content-Type`. This stops attackers from uploading malicious JavaScript inside image files (`.jpg`) and tricking the browser into executing them as script files.

---

### Q10: How do you handle HTTP 429 Rate Limit Exceeded errors gracefully in Flask APIs?
**Answer**:
Register an error handler for status 429 using `@app.errorhandler(429)`:

```python
@app.errorhandler(429)
def ratelimit_handler(e):
    return jsonify({
        "error": "Too Many Requests",
        "message": f"Quota exceeded: {e.description}"
    }), 429
```
