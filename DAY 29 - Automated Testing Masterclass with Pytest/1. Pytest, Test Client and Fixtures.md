## 1. Project Test Setup (`conftest.py`)

In Pytest, **`conftest.py`** is a special file located in your root directory. Any fixtures defined in `conftest.py` are automatically shared across all test files without requiring explicit imports!

```python
# conftest.py
import pytest
from app_factory import create_app
from database import db

@pytest.fixture(scope='module')
def app():
    """Configures a fresh Flask app instance for testing."""
    _app = create_app('testing')
    _app.config.update({
        'TESTING': True,                               # Disables error catching, exposes tracebacks
        'SQLALCHEMY_DATABASE_URI': 'sqlite:///:memory:' # Uses isolated fast in-memory DB
    })

    with _app.app_context():
        db.create_all()     # Setup fresh DB schema
        yield _app          # Hand app control to test execution!
        db.drop_all()       # Teardown & wipe DB after module tests finish!

@pytest.fixture
def client(app):
    """Provides a virtual HTTP test client for simulating requests."""
    return app.test_client()
```

#### ⚖️ Manual Postman Testing vs Pytest Automated Test Suite

| Testing Characteristic | Manual Testing (Postman / Browser) | Pytest Automated Test Suite |
| :--- | :--- | :--- |
| **Execution Speed** | 🐢 Slow (Takes 15-30 minutes per release) | ⚡ Instant (Executes 100+ tests in 2 seconds) |
| **Human Error Risk** | High (Human testers miss edge cases when tired) | Zero (Runs exact deterministic code assertions) |
| **Database Isolation** | ⚠️ Pollutes dev DB with garbage test records | 🛡️ Uses `sqlite:///:memory:` wiped after each test |
| **Continuous Integration** | ❌ Cannot be run headlessly in GitHub Actions | ✅ Integrates seamlessly into GitHub CI pipelines |
| **Regression Prevention** | ⚠️ Bugs often reappear in older endpoints | 🛡️ Prevents regressions on every git commit |

## 2. Simulating HTTP Requests with `app.test_client()`

The Flask `test_client()` allows sending virtual GET, POST, PUT, and DELETE requests:

```python
# test_auth_api.py

def test_user_registration(client):
    """Tests successful user registration API endpoint."""
    payload = {
        "username": "testuser",
        "email": "testuser@example.com",
        "password": "SecurePassword123"
    }

    # Simulate HTTP POST request with JSON payload
    response = client.post(
        '/api/v1/auth/register',
        json=payload,
        headers={'Content-Type': 'application/json'}
    )

    # 1. Assert Status Code
    assert response.status_code == 201

    # 2. Assert Response JSON
    json_data = response.get_json()
    assert json_data['status'] == 'success'
    assert json_data['user']['username'] == 'testuser'
```

## 3. Advanced Fixtures: Authentication Headers

Create reusable fixtures to test protected JWT or session-authenticated routes:

```python
@pytest.fixture
def auth_client(client):
    """Fixture providing a test client with an active Authorization Bearer token header."""
    # 1. Register test user
    client.post('/api/v1/auth/register', json={
        "username": "auth_user", "email": "auth@example.com", "password": "Password123!"
    })

    # 2. Log in to obtain JWT access token
    login_res = client.post('/api/v1/auth/login', json={
        "username": "auth_user", "password": "Password123!"
    })
    token = login_res.get_json()['access_token']

    # 3. Inject Bearer token header into client environment
    client.environ_base['HTTP_AUTHORIZATION'] = f"Bearer {token}"
    return client
```
