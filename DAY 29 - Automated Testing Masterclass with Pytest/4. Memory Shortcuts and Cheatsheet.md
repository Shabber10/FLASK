## 🔤 Automated Testing Terminology Decoder

| Term | Meaning | Real-World Example |
| :--- | :--- | :--- |
| **Automated Testing** | Code that automatically tests application endpoints in seconds. | `python -m pytest` |
| **Pytest** | Standard Python testing framework discovering `test_*.py` files. | `def test_login():` |
| **`test_client()`** | Virtual HTTP client simulating requests against Flask routes in-memory. | `client.post('/api/login', json=...)` |
| **`@pytest.fixture`** | Reusable setup/teardown function supplying test dependencies. | `@pytest.fixture def client():` |
| **`yield` Teardown** | Pauses fixture setup, hands control to test, and runs cleanup after. | `yield app; db.drop_all()` |
| **Assertion** | Python statement verifying expected values (`assert status == 200`). | `assert res.status_code == 200` |
| **`mocker.patch()`** | Intercepts slow/external API calls and returns fake responses. | `mocker.patch('requests.post')` |
| **`pytest-cov`** | Measures percentage of application code executed during tests. | `pytest --cov=app` |
| **`conftest.py`** | Root configuration file defining shared fixtures across test files. | Root project `conftest.py` |
| **CI (Continuous Integration)** | Automatically running `pytest` on GitHub Actions upon git push. | `.github/workflows/ci.yml` |

## 🧠 Memory Mnemonics

### 1. Pytest Fixture Lifecycle (`F-I-X-T-U-R-E`)
Remember **F-I-X-T-U-R-E** for fixture management:
- **F** -> **Function / Module Scoping** (`scope='function'`)
- **I** -> **Initialize In-Memory DB** (`sqlite:///:memory:`)
- **X** -> **eXecute `yield` Statement** (Hands control to test function)
- **T** -> **Teardown Resources After Yield** (`db.drop_all()`)
- **U** -> **Use Shared Fixtures in `conftest.py`**
- **R** -> **Return Virtual Test Client** (`app.test_client()`)
- **E** -> **Environment Isolation** (`TESTING = True`)

---

### 2. Test Verification Rules (`A-S-S-E-R-T`)
Remember **A-S-S-E-R-T** for writing test assertions:
- **A** -> **Assert HTTP Status Code** (`assert response.status_code == 200`)
- **S** -> **Sanity Check JSON Payload** (`assert response.json['status'] == 'success'`)
- **S** -> **Select In-Memory Test DB**
- **E** -> **Ensure Test Isolation** (Each test runs in a clean DB state)
- **R** -> **Require Mocking for External APIs** (`mocker.patch`)
- **T** -> **Trigger Pytest Runner** (`python -m pytest -v`)

## ⚡ Quick-Reference Code Snippets

### 1. Root `conftest.py` Setup
```python
import pytest
from app import create_app, db

@pytest.fixture(scope='module')
def app():
    app = create_app('testing')
    app.config.update({
        'TESTING': True,
        'SQLALCHEMY_DATABASE_URI': 'sqlite:///:memory:'
    })
    with app.app_context():
        db.create_all()
        yield app
        db.drop_all()

@pytest.fixture
def client(app):
    return app.test_client()
```

### 2. Testing Route with Test Client & JSON Assertion
```python
def test_create_item(client):
    res = client.post('/api/v1/items', json={"name": "Widget"})
    assert res.status_code == 201
    assert res.get_json()['name'] == "Widget"
```

### 3. Mocking External API with Pytest-Mock
```python
def test_stripe_charge(mocker):
    fake = mocker.Mock()
    fake.json.return_value = {"status": "paid"}
    mocker.patch('requests.post', return_value=fake)

    res = charge_card(500)
    assert res['status'] == "paid"
```

### 4. CLI Pytest & Coverage Commands
```bash
python -m pytest -v                       # Run verbose tests
pytest --cov=app                           # Measure code coverage
pytest --cov=app --cov-report=html         # Generate HTML coverage report
```
