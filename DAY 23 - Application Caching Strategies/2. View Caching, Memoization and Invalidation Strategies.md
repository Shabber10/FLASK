## 1. View Caching (`@cache.cached`)

View Caching stores the complete HTTP response (HTML rendered string or JSON body) generated by a Flask route function:

```python
from flask import jsonify
from app_factory import cache

@app.route('/api/v1/catalog')
@cache.cached(timeout=60)  # Caches full JSON response for 60 seconds!
def get_catalog():
    print("⚠️ [DATABASE QUERY] Fetching catalog records from DB...")
    products = Product.query.all()
    return jsonify([p.to_dict() for p in products])
```

---

## 2. Function Memoization (`@cache.memoize`)

Unlike View Caching (which caches HTTP endpoints), **Function Memoization** caches the return values of internal Python functions based on the exact positional and keyword arguments passed into them:

```python
@cache.memoize(timeout=300)
def calculate_user_loyalty_score(user_id, year):
    """Heavy mathematical calculation cached per (user_id, year) pair."""
    print(f"⚠️ [COMPUTATION] Computing loyalty score for user #{user_id} in {year}...")
    orders = Order.query.filter_by(user_id=user_id, year=year).all()
    score = sum(o.total_amount for o in orders) * 1.5
    return score
```

Automate cache invalidation using SQLAlchemy ORM event listeners:


## 4. Cache Stampede (Thundering Herd) Mitigation with Working Code

> ⚠️ **Cache Stampede**: Occurs when a high-traffic cache key (e.g. 10,000 req/sec) expires. Hundreds of web request threads discover a Cache Miss simultaneously and swarm the database at once, causing database connection exhaustion and server crashes!

### Solution 1: Distributed Mutex Locking with Redis (`redis.lock`)

With Mutex Locking, only **ONE** worker thread acquires the lock to query the database and re-populate Redis; all other threads sleep briefly and read the freshly computed cache value:

```python
import time
import json
import redis
from flask import jsonify

redis_client = redis.Redis.from_url("redis://localhost:6379/0", decode_responses=True)

def get_product_with_mutex(product_id):
    cache_key = f"product:{product_id}"
    cached_data = redis_client.get(cache_key)
    if cached_data:
        return json.loads(cached_data)

    # 🔒 Cache Miss! Acquire distributed Redis lock with a 5-second timeout
    lock = redis_client.lock(f"lock:{cache_key}", timeout=5)
    
    if lock.acquire(blocking=True, blocking_timeout_sec=2):
        try:
            # Double-check if another thread populated the cache while we were waiting
            cached_data = redis_client.get(cache_key)
            if cached_data:
                return json.loads(cached_data)

            # Query database
            product = Product.query.get(product_id)
            if product:
                data = product.to_dict()
                # Store in Redis with TTL
                redis_client.setex(cache_key, 300, json.dumps(data))
                return data
            return None
        finally:
            lock.release()
    else:
        # Fallback if lock timed out: try reading cache one last time
        cached_data = redis_client.get(cache_key)
        return json.loads(cached_data) if cached_data else None
```

### Solution 2: TTL Jitter (Randomized Expiration)

Prevent hundreds of cache keys that were seeded at the same time from expiring simultaneously:

```python
import random

def set_cache_with_jitter(key, value, base_ttl_seconds=300):
    """Adds +/- 15% randomized jitter to cache expiration time."""
    jitter = random.uniform(-0.15, 0.15) * base_ttl_seconds
    actual_ttl = int(base_ttl_seconds + jitter)
    redis_client.setex(key, actual_ttl, json.dumps(value))
```
