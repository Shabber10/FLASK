# Day 13: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from CLI basics up to custom extension authoring and Click command groups.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is a CLI in web development?
**Answer**:
A CLI (Command Line Interface) is a text-based terminal interface where developers execute administrative commands (such as database migrations, data seeding, or system resets) by typing commands into a terminal, rather than exposing them on public web URLs.

---

### Q2: Why should database seeding or table resets be built as CLI commands rather than HTTP web routes?
**Answer**:
Exposing administrative operations (like `DROP TABLE`) on HTTP web routes exposes them to web security risks (accidental clicks, unauthorized visitors, CSRF attacks). Building them as CLI commands ensures they can only be executed by authorized developers or automated scripts directly on the server terminal.

---

### Q3: What Python library powers Flask's command-line interface?
**Answer**:
**Click** ("Command Line Interface Creation Kit"), which is integrated into Flask via `app.cli`.

---

### Q4: What is a Flask Extension?
**Answer**:
A Flask Extension is a reusable Python package or class designed to add features to Flask applications (e.g. database ORM, user authentication, form validation) without cluttering core route handlers.

---

### Q5: How do you register a custom terminal command on a Flask app instance?
**Answer**:
Decorate a function with `@app.cli.command("command-name")`:
```python
@app.cli.command("hello")
def hello():
    click.echo("Hello World!")
```

---

## 🟡 Level 2: Intermediate Questions

### Q6: Why is `@with_appcontext` required on CLI commands that interact with databases?
**Answer**:
`@with_appcontext` ensures that an active Flask application context is pushed prior to executing the CLI function. This allows the command to access `current_app`, `g`, configuration settings, and active database connection sessions (`db.session`).

---

### Q7: What is the difference between `@click.argument` and `@click.option`?
**Answer**:
*   `@click.argument`: Defines a **required positional parameter** (e.g., `flask seed-users admin`).
*   `@click.option`: Defines an **optional named flag** with a default fallback value and help description (e.g., `flask seed-users --count 10`).

---

### Q8: What standard pattern should every custom Flask extension class follow for initialization?
**Answer**:
It should support the **Dual Initialization Pattern**:
1.  Accept an optional `app` parameter in `__init__(self, app=None)`.
2.  Provide an `init_app(self, app)` method so the extension can be initialized globally and bound to an app inside an Application Factory.

---

### Q9: Where does a custom extension store its instance reference on the Flask application?
**Answer**:
Inside the `app.extensions` dictionary using a unique key string:
```python
app.extensions['my_extension_name'] = self
```

---

### Q10: How do you ask a user for a Yes/No confirmation in a Click CLI command?
**Answer**:
Use `click.confirm(message, default=False, abort=True)`:
```python
click.confirm("Are you sure you want to drop all tables?", abort=True)
```
If the user types `n`, Click automatically aborts execution safely!

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: How do you group related CLI commands under a custom command namespace (e.g., `flask user create`, `flask user delete`)?
**Answer**:
Use `AppGroup` from `flask.cli`:

```python
from flask.cli import AppGroup

user_cli = AppGroup('user', help='User management commands')

@user_cli.command('create')
@click.argument('name')
def create(name):
    click.echo(f"Created {name}")

app.cli.add_command(user_cli)
```

---

### Q12: How can a custom extension automatically register CLI commands onto the host Flask app?
**Answer**:
Inside the extension's `init_app(app)` method, define a command function decorated with `@app.cli.command()`:

```python
class MyExtension:
    def init_app(self, app):
        @app.cli.command("ext-action")
        def ext_action_cmd():
            click.echo("Extension CLI action executed!")
```

---

### Q13: How does `app.config.setdefault()` help when authoring custom extensions?
**Answer**:
`app.config.setdefault('KEY', default_val)` sets a default configuration value **only if** the user hasn't already defined a custom value in `app.config`. This allows extension authors to provide sensible defaults while giving developers complete override control.

---

### Q14: How do you test custom CLI commands using `pytest`?
**Answer**:
Use Flask's built-in CLI test runner `app.test_cli_runner()`:

```python
def test_seed_command(app):
    runner = app.test_cli_runner()
    result = runner.invoke(args=['seed-users', '--count', '3'])
    assert 'Successfully seeded' in result.output
    assert result.exit_code == 0
```

---

### Q15: How can a custom extension attach request lifecycle hooks dynamically?
**Answer**:
Inside `init_app(app)`, call application hook registration methods directly:

```python
class RequestLoggerExt:
    def init_app(self, app):
        app.before_request(self._on_before_request)
        app.after_request(self._on_after_request)
```
