## 1. Virtual Machines vs. Containers

Traditional Virtual Machines (VMs) virtualize physical hardware, requiring a full guest operating system for every application instance. Containers virtualize the host operating system kernel, sharing OS resources while isolating application processes:

```
Virtual Machines (Heavyweight):               Containers (Lightweight):
+---------------------------------+          +---------------------------------+
| App 1   | App 2   | App 3       |          | App 1   | App 2   | App 3       |
| Bins/Lib| Bins/Lib| Bins/Lib    |          | Bins/Lib| Bins/Lib| Bins/Lib    |
| Guest OS| Guest OS| Guest OS    |          +---------------------------------+
+---------------------------------+          | Container Engine (Docker)       |
| Hypervisor (VMware / KVM)       |          +---------------------------------+
+---------------------------------+          | Shared Host OS Kernel (Linux)   |
| Physical Host Infrastructure    |          +---------------------------------+
+---------------------------------+          | Physical Host Infrastructure    |
+---------------------------------+          +---------------------------------+
```

## 2. Docker Image Layering & Build Cache

A Docker Image is a read-only template composed of stacked filesystem layers. Every instruction in a `Dockerfile` (`FROM`, `RUN`, `COPY`) creates an immutable layer:

```
+-------------------------------------------------------+
| Layer 5: COPY . . (Source Code - Changes Frequently)  |
+-------------------------------------------------------+
| Layer 4: RUN pip install -r requirements.txt          | <- CACHED if requirements.txt unchanged
+-------------------------------------------------------+
| Layer 3: COPY requirements.txt .                      | <- CACHED
+-------------------------------------------------------+
| Layer 2: WORKDIR /app                                 | <- CACHED
+-------------------------------------------------------+
| Layer 1: FROM python:3.11-slim                        | <- Base OS Layer
+-------------------------------------------------------+
```

### Dockerfile Layer Optimization Rule
Order `Dockerfile` instructions from **least frequently changed** to **most frequently changed**. 

Copy `requirements.txt` and run `pip install` BEFORE copying the application source code (`COPY . .`). This ensures Docker reuses cached dependency layers, reducing build time from 3 minutes to 2 seconds!

## 3. Multi-Stage Docker Builds

Multi-stage builds allow compiling dependencies in a heavy "builder" image, and copying only the compiled artifacts into a lightweight, secure production runtime image:

```dockerfile
# ==============================================================================
# Stage 1: Build & Dependency Stage
# ==============================================================================
FROM python:3.11-slim AS builder

WORKDIR /app
RUN apt-get update && apt-get install -y --no-install-recommends gcc libpq-dev

COPY requirements.txt .
RUN pip install --no-cache-dir --user -r requirements.txt

# ==============================================================================
# Stage 2: Minimal Production Runtime Stage
# ==============================================================================
FROM python:3.11-slim AS runner

WORKDIR /app

# Non-Root Security User
RUN useradd -m -u 1000 appuser

# Copy installed dependencies from builder stage
COPY --from=builder /root/.local /home/appuser/.local
COPY . .

# Set ownership to non-root user
RUN chown -R appuser:appuser /app
USER appuser

ENV PATH="/home/appuser/.local/bin:${PATH}"
EXPOSE 5000

CMD ["gunicorn", "--bind", "0.0.0.0:5000", "wsgi:app"]
```

## 4. The `.dockerignore` File

Add a `.dockerignore` file in the project root to prevent copying unneeded files (virtualenvs, git metadata, local SQLite databases, secret `.env` files) into Docker images:

```
.git
.gitignore
__pycache__
*.pyc
*.pyo
*.db
venv/
.env
.pytest_cache/
```
