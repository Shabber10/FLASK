# Day 22: Multi-Container Orchestration (Docker Compose)

In this section, we examine multi-container orchestration with `docker-compose.yml`, service networking, persistent volumes, environment variable injection, and service health checks.

---

## 1. What is Docker Compose?

Modern enterprise web applications rarely consist of a single isolated container. A production stack requires multiple interconnected services:
- Flask Web API (`Gunicorn`)
- Relational Database (`PostgreSQL`)
- In-Memory Cache & Message Broker (`Redis`)
- Asynchronous Task Workers (`Celery`)

**Docker Compose** is an orchestration tool that defines and runs multi-container Docker applications using a single YAML configuration file (`docker-compose.yml`).

---

## 2. Production `docker-compose.yml` Architecture

```yaml
version: '3.8'

services:
  # 1. PostgreSQL Database Service
  db:
    image: postgres:15-alpine
    restart: always
    environment:
      POSTGRES_DB: saas_prod
      POSTGRES_USER: pguser
      POSTGRES_PASSWORD: SecretPassword123!
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U pguser -d saas_prod"]
      interval: 5s
      timeout: 5s
      retries: 5

  # 2. Redis Message Broker Service
  redis:
    image: redis:7-alpine
    restart: always
    ports:
      - "6379:6379"

  # 3. Flask Web API Service
  web:
    build:
      context: .
      dockerfile: Dockerfile
    restart: always
    ports:
      - "5000:5000"
    environment:
      DATABASE_URL: postgresql://pguser:SecretPassword123!@db:5432/saas_prod
      REDIS_URL: redis://redis:6379/0
      CELERY_BROKER_URL: redis://redis:6379/0
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started

  # 4. Celery Asynchronous Worker Service
  celery_worker:
    build: .
    command: celery -A app.celery_app worker --loglevel=info
    restart: always
    environment:
      DATABASE_URL: postgresql://pguser:SecretPassword123!@db:5432/saas_prod
      REDIS_URL: redis://redis:6379/0
    depends_on:
      - web
      - redis

volumes:
  postgres_data:
```

---

## 3. Inter-Container Networking & Service Discovery

Docker Compose creates an isolated private virtual network for all services defined in `docker-compose.yml`.

Containers communicate using **Automatic DNS Service Discovery**:
- Inside the `web` container, the PostgreSQL database hostname resolves to `db:5432`.
- The Redis message broker hostname resolves to `redis:6379`.

You do **NOT** use `localhost` or `127.0.0.1` to connect to database containers in Docker Compose!

---

## 4. Docker Compose CLI Commands

```bash
# 1. Build images and start multi-container stack in background (-d)
docker-compose up -d --build

# 2. Inspect real-time status of running services
docker-compose ps

# 3. Stream aggregated container logs
docker-compose logs -f web

# 4. Stop and remove containers, networks, and volumes
docker-compose down -v
```
