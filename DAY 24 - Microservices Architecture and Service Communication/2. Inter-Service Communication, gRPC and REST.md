# Day 24: Inter-Service Communication, gRPC & Circuit Breakers

In this section, we examine synchronous REST vs gRPC protocols, asynchronous event-driven messaging, distributed resiliency, and the Circuit Breaker pattern.

---

## 1. Synchronous vs. Asynchronous Communication

Microservices communicate across network boundaries using two primary communication models:

```
1. Synchronous HTTP/REST or gRPC (Request-Response):
User Service ------------------------> Payment Service (Blocks waiting for HTTP 200)

2. Asynchronous Event Messaging (Pub/Sub):
Order Service ---> [ RabbitMQ / Kafka ] ---> Inventory Service (Consumes event asynchronously)
                                        ---> Analytics Service (Consumes event asynchronously)
```

---

## 2. gRPC vs. REST (JSON over HTTP/1.1)

While REST over HTTP/1.1 is readable and standard for public web APIs, internal microservice-to-microservice communication increasingly uses **gRPC**:

| Protocol | Transport | Payload Format | Performance | Scheme |
| :--- | :--- | :--- | :--- | :--- |
| **REST API** | HTTP/1.1 | Plaintext JSON | Standard | Weakly typed JSON Schemas |
| **gRPC** | HTTP/2 | Binary Protocol Buffers (`.proto`) | **7x-10x Faster** serialization | Strongly typed `.proto` contracts |

---

## 3. Resiliency & The Circuit Breaker Pattern

In distributed systems, network requests can fail or experience latency. If Service A synchronously calls Service B, and Service B hangs, Service A worker threads exhaust rapidly, causing a **Cascading Failure** across the entire cluster!

The **Circuit Breaker Pattern** monitors inter-service call failure rates and trips open when downstream failures cross a threshold:

```
        +-------------------------------------------------------------+
        |                 Circuit Breaker State Machine               |
        +-------------------------------------------------------------+

             Normal Operations              Failures Exceed Threshold
           +-------------------+               +-------------------+
           |    CLOSED State   | ------------> |    OPEN State     |
           | (Requests Flow)   |               | (Fast Fail / 503) |
           +-------------------+               +-------------------+
                     ^                                   |
                     |         Timeout Expires           |
                     +-----------------------------------+
                                (HALF-OPEN Test)
```

### Implementing Circuit Breakers in Python (`pybreaker`)

```python
import pybreaker
import requests

# Create Circuit Breaker (Trips open after 5 consecutive failures; stays open 30s)
db_breaker = pybreaker.CircuitBreaker(fail_max=5, reset_timeout=30)

@db_breaker
def call_user_microservice(user_id):
    """Wrapped request call. Rejects instantly with CircuitBreakerError if OPEN!"""
    response = requests.get(f"http://user-service:5000/users/{user_id}", timeout=2.0)
    response.raise_for_status()
    return response.json()
```
