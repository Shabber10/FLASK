# Day 11: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from blueprint basics up to asset isolation, subdomain routing, and nested blueprints.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is a Flask Blueprint in simple terms?
**Answer**:
A Flask Blueprint is a mini-application container used to group related routes, HTML templates, static files, and error handlers into an independent sub-module.

---

### Q2: Can a Flask Blueprint run as a standalone web application?
**Answer**:
No. A Blueprint is not a complete application instance by itself; it cannot execute `blueprint.run()`. It represents a set of operations that must be registered onto an actual `Flask` application instance using `app.register_blueprint()`.

---

### Q3: Why do enterprise developers use Blueprints instead of putting all routes in `app.py`?
**Answer**:
Putting thousands of lines of code inside `app.py` causes Git merge conflicts, unreadable scripts, and tight coupling. Blueprints allow teams to break applications into clean, independent packages (e.g. `auth`, `admin`, `billing`, `api`).

---

### Q4: How do you register a Blueprint named `auth_bp` onto a Flask app with a `/auth` prefix?
**Answer**:
Pass `url_prefix` when instantiating the blueprint or when calling `app.register_blueprint()`:

```python
auth_bp = Blueprint('auth', __name__, url_prefix='/auth')
app.register_blueprint(auth_bp)
```

---

### Q5: How do you generate a URL to a route defined inside a Blueprint?
**Answer**:
Prefix the view function name with the blueprint's internal name:
```python
url_for('auth.login')  # 'blueprint_name.function_name'
```

---

## 🟡 Level 2: Intermediate Questions

### Q6: How does `@bp.before_request` differ from `@app.before_request`?
**Answer**:
*   `@bp.before_request`: Executes **ONLY** for incoming HTTP requests that match routes belonging to that specific Blueprint.
*   `@app.before_request`: Executes globally for **ALL** incoming HTTP requests across the entire Flask application.

---

### Q7: What is Template Shadowing in Blueprints and how do you prevent it?
**Answer**:
Template Shadowing occurs when two blueprints contain template files with identical relative filenames (e.g., `templates/index.html`). Because Flask searches global template paths first, it will always render the first matching template it finds.

**Prevention**: Namespacing blueprint templates inside a subfolder matching the blueprint name (e.g. `templates/auth/login.html` and `templates/admin/dashboard.html`).

---

### Q8: How do relative and absolute `url_for()` references differ inside a Blueprint view function?
**Answer**:
*   `url_for('.login')` (Relative): Uses a leading dot to refer to `login()` inside the **current active blueprint**.
*   `url_for('auth.login')` (Absolute): Specifies `auth.login` explicitly, allowing references across any blueprint.

---

### Q9: Can you override a Blueprint's `url_prefix` during registration on the main app?
**Answer**:
Yes. Passing `url_prefix` to `app.register_blueprint()` overrides the default `url_prefix` defined on the `Blueprint()` constructor:

```python
app.register_blueprint(auth_bp, url_prefix='/security-login')
```

---

### Q10: How do you serve static assets (CSS, JS, images) from inside a specific Blueprint?
**Answer**:
Define `static_folder` and `static_url_path` when creating the blueprint:

```python
auth_bp = Blueprint('auth', __name__, static_folder='static', static_url_path='/auth-static')
```
Assets are referenced in templates using `url_for('auth.static', filename='css/style.css')`.

---

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: How do you configure Blueprint Subdomain Routing in Flask?
**Answer**:
Specify `subdomain` when instantiating the blueprint, and configure `SERVER_NAME` on the main application:

```python
app.config['SERVER_NAME'] = 'mycompany.com:5000'
admin_bp = Blueprint('admin', __name__, subdomain='admin')

@admin_bp.route('/')
def admin_home():
    return "Admin Subdomain"

app.register_blueprint(admin_bp)
```
Routes in `admin_bp` will respond exclusively to requests sent to `admin.mycompany.com:5000`.

---

### Q12: How do Nested Blueprints work in Flask 2.0+?
**Answer**:
In Flask 2.0+, Blueprints can be registered inside other parent Blueprints. The child blueprint inherits the parent blueprint's `url_prefix` and subdomain settings:

```python
api_bp = Blueprint('api', __name__, url_prefix='/api')
v1_bp = Blueprint('v1', __name__, url_prefix='/v1')

api_bp.register_blueprint(v1_bp)  # Final URL: /api/v1/...
app.register_blueprint(api_bp)
```

---

### Q13: What is the difference between `@bp.errorhandler` and `@bp.app_errorhandler`?
**Answer**:
*   `@bp.errorhandler(500)`: Catches 500 errors raised **ONLY** by view functions defined within that specific blueprint.
*   `@bp.app_errorhandler(500)`: Catches 500 errors raised **globally anywhere** across the entire Flask application.

---

### Q14: How does `@bp.context_processor` work?
**Answer**:
`@bp.context_processor` injects variables or utility functions automatically into the Jinja2 template context **ONLY** when rendering templates from routes within that specific blueprint:

```python
@auth_bp.context_processor
def inject_auth_config():
    return dict(auth_version="2.0.0")
```

---

### Q15: How should Blueprints be structured when implementing the Application Factory Pattern?
**Answer**:
Define Blueprints in separate package files without importing `app`. Inside your `create_app()` factory function, import the blueprint instances and call `app.register_blueprint()` dynamically.
