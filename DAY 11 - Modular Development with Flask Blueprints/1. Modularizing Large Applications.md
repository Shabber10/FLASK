## 1. Defining a Flask Blueprint

To create a Blueprint, instantiate the `Blueprint` class. Give it a unique internal name and pass `__name__`:

```python
from flask import Blueprint, render_template

# Define Blueprint instance
auth_bp = Blueprint(
    name='auth',                  # Internal blueprint identifier name used in url_for()
    import_name=__name__,         # Package location
    url_prefix='/auth'            # Base URL prepended to all routes in this blueprint
)

# Route registered on the blueprint (accessible at /auth/login)
@auth_bp.route('/login', methods=['GET', 'POST'])
def login():
    return render_template('auth/login.html')

# Route registered on the blueprint (accessible at /auth/logout)
@auth_bp.route('/logout')
def logout():
    return "User logged out."
```

## 2. Registering Blueprints on the Main Application

A Blueprint remains inactive until you register it on your main `Flask` application instance using **`app.register_blueprint()`**:

```python
from flask import Flask
# Import blueprint objects from sub-modules
from auth_routes import auth_bp
from admin_routes import admin_bp

app = Flask(__name__)

# Register Blueprints onto Flask application
app.register_blueprint(auth_bp)
app.register_blueprint(admin_bp, url_prefix='/system-admin') # Override url_prefix if needed!
```

## 3. Blueprint-Specific Request Hooks & Handlers

Blueprints support dedicated request lifecycle hooks that execute **only** for routes belonging to that specific blueprint:

```python
@auth_bp.before_request
def check_auth_maintenance():
    # Executes BEFORE any route handler inside auth_bp!
    print("🔒 Auth Blueprint request initiated...")

@auth_bp.app_errorhandler(404)
def handle_global_404(error):
    # App-level error handler registered by this blueprint
    return "Custom 404 Page from Auth Module", 404
```

> **Hook Scope Comparison**:
> *   `@bp.before_request`: Executes **ONLY** for requests matching routes inside `bp`.
> *   `@bp.before_app_request`: Executes for **ALL** requests across the entire application.

## 4. Enterprise Package Directory Layout

In production enterprises, each Blueprint resides inside its own sub-package directory containing dedicated routes, forms, and services:

```
my_enterprise_app/
├── app.py                     # Main application factory & blueprint registration
├── auth/                      # Auth Module Package
│   ├── __init__.py            # Instantiates auth_bp
│   ├── routes.py              # Auth route handlers
│   ├── forms.py               # WTForms classes for Auth
│   └── templates/             # Auth-specific HTML templates
│       └── auth/
│           └── login.html
├── admin/                     # Admin Module Package
│   ├── __init__.py            # Instantiates admin_bp
│   └── routes.py              # Admin dashboard routes
└── api/                       # REST API Package
    ├── __init__.py            # Instantiates api_bp
    └── v1_endpoints.py        # JSON API routes
```
