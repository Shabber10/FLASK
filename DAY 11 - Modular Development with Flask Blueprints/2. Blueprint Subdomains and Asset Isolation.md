## 1. Subdomain Routing with Blueprints

In enterprise SaaS platforms, different modules are often mapped to custom subdomains (e.g. `admin.mycompany.com` or `api.mycompany.com`).

Flask Blueprints support subdomain binding via the `subdomain` parameter:

```python
from flask import Flask, Blueprint

app = Flask(__name__)
# SERVER_NAME is required for Flask subdomain matching during local development
app.config['SERVER_NAME'] = 'mycompany.local:5000'

# Admin Blueprint bound to 'admin' subdomain (admin.mycompany.local:5000)
admin_bp = Blueprint('admin', __name__, subdomain='admin')

@admin_bp.route('/')
def admin_home():
    return "Welcome to Admin Subdomain Dashboard!"

app.register_blueprint(admin_bp)
```

## 2. Template & Static Asset Isolation

Each Blueprint can manage its own independent folder of HTML templates and static assets (CSS, JS, images):

```python
auth_bp = Blueprint(
    'auth',
    __name__,
    url_prefix='/auth',
    template_folder='templates',       # Dedicated blueprint templates folder
    static_folder='static',            # Dedicated blueprint static assets folder
    static_url_path='/auth-assets'     # URL path for static assets (/auth/auth-assets/style.css)
)
```

> ⚠️ **Template Shadowing Gotcha**:
> By default, Flask searches the global `templates/` folder before blueprint `template_folder` locations. If both `auth` and `admin` blueprints have a file named `templates/index.html`, Flask will always pick the first one it finds!
>
> **Best Practice Solution**: Always place blueprint templates inside a subfolder matching the blueprint name (e.g., `templates/auth/login.html` and `templates/admin/dashboard.html`).

## 3. Cross-Blueprint URL Generation (`url_for`)

When generating URLs across different blueprints, prefix the view function name with the target blueprint's internal name:

```python
from flask import redirect, url_for

# 1. Routing to a view function inside the SAME blueprint
redirect(url_for('.login'))             # Relative reference (dot prefix)

# 2. Routing to a view function in a DIFFERENT blueprint
redirect(url_for('auth.login'))         # Absolute reference ('blueprint.endpoint')

# 3. Referencing static assets inside a blueprint
image_url = url_for('auth.static', filename='logo.png')
```

## 4. Nesting Blueprints (Parent & Child Modules)

In Flask 2.0+, you can register Blueprints **inside other Blueprints** to create hierarchical sub-modules:

```python
# Parent API Blueprint (/api)
api_bp = Blueprint('api', __name__, url_prefix='/api')

# Child v1 Blueprint (/v1)
v1_bp = Blueprint('v1', __name__, url_prefix='/v1')

@v1_bp.route('/users')
def list_v1_users():
    return "API v1 Users List"

# Register child blueprint onto parent blueprint!
api_bp.register_blueprint(v1_bp)

# Register parent blueprint onto main Flask app (Final URL: /api/v1/users)
app.register_blueprint(api_bp)
```
