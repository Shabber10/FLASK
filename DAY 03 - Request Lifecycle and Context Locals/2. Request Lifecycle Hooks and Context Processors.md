# Day 03: Request Lifecycle Hooks & Context Processors

In this section, we examine the complete execution pipeline of a Flask request, lifecycle hook decorators (`before_request`, `after_request`, `teardown_request`), error escalation, and global template context processors.

---

## 1. Complete Request Lifecycle Flow

When an HTTP request enters Flask, it passes through sequential lifecycle stages:

```
                          +-----------------------------------+
                          |      Incoming HTTP Request        |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Push App & Request Contexts       |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Execute `@app.before_request`     |
                          | (If returns response -> Short   |
                          |  circuit directly to after_req)   |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Execute Matched View Function     |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Execute `@app.after_request`      |
                          | (Modifies Response Object)        |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Execute `@app.teardown_request`   |
                          | (Clean up DB connections/sockets) |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Send Response & Pop Contexts      |
                          +-----------------------------------+
```

## 2. Request Lifecycle Hook Decorators

### 1. `@app.before_request`
Executes before every request view function.
- If `@app.before_request` returns `None`, execution continues to the next hook or view function.
- **Short-Circuiting**: If it returns a response object (or tuple/redirect), view execution is skipped, and Flask jumps directly to `@app.after_request`.

```python
@app.before_request
def authenticate_user():
    g.start_time = time.time()
    api_key = request.headers.get('X-API-KEY')
    if not api_key and request.endpoint != 'public_route':
        return jsonify({"error": "Unauthorized"}), 401
```

### 2. `@app.after_request`
Executes after the view function returns successfully. 
- Must accept a `Response` object as an argument and **must return a Response object**.
- **Important**: `@app.after_request` is **skipped** if an unhandled exception occurs during request execution!

```python
@app.after_request
def add_security_headers(response):
    response.headers['X-Content-Type-Options'] = 'nosniff'
    response.headers['X-Frame-Options'] = 'DENY'
    return response
```

### 3. `@app.teardown_request`
Executes after the request completes.
- Accepts an `exception` argument (`None` if no exception occurred, or the `Exception` instance if an error was raised).
- **Guaranteed Execution**: Executes regardless of whether an unhandled exception occurred, making it the proper place to close DB connections, release locks, or cleanup temporary files.

```python
@app.teardown_request
def close_db_connection(exception=None):
    db = g.pop('db_connection', None)
    if db is not None:
        db.close()
```

## 3. Global Context Processors (`@app.context_processor`)

Jinja2 templates often require global variables (e.g. current year, app title, logged-in user profile). Instead of passing these variables in every `render_template()` call, use `@app.context_processor`.

### Context Processor Example

```python
from datetime import datetime
from flask import Flask, render_template

app = Flask(__name__)

@app.context_processor
def inject_global_template_vars():
    """Injects dictionary keys automatically into all Jinja2 templates."""
    return {
        'current_year': datetime.utcnow().year,
        'app_name': 'Enterprise Flask Platform',
        'support_email': 'support@example.com'
    }
```

In Jinja2 templates, these variables are immediately accessible:

```html
<footer>
    <p>&copy; {{ current_year }} {{ app_name }}. Contact {{ support_email }}</p>
</footer>
```
