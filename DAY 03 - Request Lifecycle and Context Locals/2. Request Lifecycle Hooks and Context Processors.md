# Day 03 - Module 2: Request Lifecycle Hooks & Context Processors

Welcome to **Module 2** of Day 03! Now that we understand Flask's context architecture, let's explore how to intercept and automate code execution across the entire **Request Lifecycle**.

---

## 1. Complete Request Lifecycle Execution Pipeline

When an HTTP request arrives at your Flask application, it moves sequentially through several stages:

```
                          +-----------------------------------+
                          |      Incoming HTTP Request        |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Push App & Request Contexts       |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Execute `@app.before_request`     |
                          | (If returns response -> Short   |
                          |  circuit directly to after_req)   |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Execute Matched View Function     |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Execute `@app.after_request`      |
                          | (Modifies Response Object)        |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Execute `@app.teardown_request`   |
                          | (Clean up DB connections/sockets) |
                          +-----------------+-----------------+
                                            |
                                            v
                          +-----------------+-----------------+
                          | Send Response & Pop Contexts      |
                          +-----------------------------------+
```

---

## 2. The 3 Core Lifecycle Hook Decorators

### 1. `@app.before_request`
Executes before every request view function.
*   If it returns `None`, execution continues normally to the next hook or view function.
*   **Request Short-Circuiting**: If `@app.before_request` returns a response object (e.g., `return jsonify({"error": "Unauthorized"}), 401`), Flask **skips the view function entirely** and jumps directly to `@app.after_request`!

```python
import time
from flask import request, g, jsonify

@app.before_request
def start_timer_and_authenticate():
    g.start_time = time.time()
    
    # Example: Protect admin routes
    if request.path.startswith('/admin'):
        api_key = request.headers.get('X-API-KEY')
        if api_key != 'super-secret-key':
            # Short-circuits request!
            return jsonify({"error": "Unauthorized access"}), 401
```

---

### 2. `@app.after_request`
Executes after the view function returns successfully.
*   Must accept a `Response` object as a parameter and **must return a Response object**.
*   **Important**: `@app.after_request` is **skipped** if an unhandled exception occurs during request execution!

```python
@app.after_request
def add_security_headers(response):
    response.headers['X-Content-Type-Options'] = 'nosniff'
    response.headers['X-Frame-Options'] = 'DENY'
    return response
```

---

### 3. `@app.teardown_request`
Executes after the request completes and response is sent.
*   Accepts an optional `exception` parameter (`None` if request succeeded, or an `Exception` object if an error was raised).
*   **Guaranteed Execution**: `@app.teardown_request` **always executes**, even if your view function crashes with an unhandled exception! This makes it the safest place to close database connections or release locks.

```python
@app.teardown_request
def close_database(exception=None):
    if exception:
        print(f"Request failed with error: {exception}")
        
    db = g.pop('db_connection', None)
    if db is not None:
        db.close()
        print("Database connection closed safely.")
```

## 3. Global Template Context Processors (`@app.context_processor`)

In Jinja2 templates, you often need global variables (e.g., current year, site name, or support email). Instead of passing these variables in every `render_template()` call, use **`@app.context_processor`**:

```python
from datetime import datetime
from flask import Flask, render_template

app = Flask(__name__)

@app.context_processor
def inject_global_template_vars():
    """Injects key-value pairs automatically into ALL Jinja2 templates across the app."""
    return {
        'current_year': datetime.now().year,
        'site_title': 'Enterprise Flask Platform',
        'support_email': 'support@example.com'
    }
```

Now, every template in your app can reference these variables directly:

```html
<footer>
    <p>&copy; {{ current_year }} {{ site_title }}. Need help? Contact {{ support_email }}</p>
</footer>
```
