## 1. Template Inheritance Architecture

Template inheritance allows you to build a master skeleton layout (`base.html`) containing common UI headers, navigation bars, sidebars, and footers, while defining `{% block %}` regions for child templates to fill in.

```
+-------------------------------------------------------------+
| base.html (Master Skeleton)                                 |
| +---------------------------------------------------------+ |
| | Navbar & Global Header                                  | |
| +---------------------------------------------------------+ |
| | {% block content %}                                     | |
| |   (Child template content injected here)                | |
| | {% endblock %}                                          | |
| +---------------------------------------------------------+ |
| | Footer & Global Scripts                                 | |
| +---------------------------------------------------------+ |
+-------------------------------------------------------------+
```

---

### 1. Base Layout (`templates/base.html`)

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>{% block title %}Enterprise Platform{% endblock %}</title>
    <!-- Bind static CSS file -->
    <link rel="stylesheet" href="{{ url_for('static', filename='css/main.css') }}">
    {% block styles %}{% endblock %}
</head>
<body>
    <header>
        <nav>
            <a href="{{ url_for('index') }}">Home</a>
        </nav>
    </header>

    <main class="container">
        <!-- Child content injected here -->
        {% block content %}{% endblock %}
    </main>

    <footer>
        <p>&copy; 2026 Enterprise Platform. All rights reserved.</p>
    </footer>

    {% block scripts %}{% endblock %}
</body>
</html>
```

---

### 2. Child Template (`templates/dashboard.html`)

```html
{% extends "base.html" %}

{% block title %}Dashboard - Enterprise Platform{% endblock %}

{% block content %}
    <h1>User Analytics Dashboard</h1>
    <p>Welcome back, {{ user.username }}!</p>
{% endblock %}

{% block scripts %}
    {{ super() }} <!-- Preserves any parent script tags in base.html -->
    <script src="{{ url_for('static', filename='js/dashboard.js') }}"></script>
{% endblock %}
```

> **What does `super()` do?** By default, defining `{% block scripts %}` in a child template overrides the parent block. Calling `{{ super() }}` keeps the parent block's default content and appends your new child script tags below it!

## 2. Reusable UI Components with Jinja2 Macros

**Macros** are like Python functions inside your HTML templates. They accept parameters and return reusable HTML snippets (e.g. form inputs, user badges, alert banners, modal dialogs).

### 1. Defining Macros (`templates/macros.html`)

```jinja2
{% macro render_badge(status) %}
    {% if status == 'active' %}
        <span class="badge badge-success">Active</span>
    {% elif status == 'pending' %}
        <span class="badge badge-warning">Pending Approval</span>
    {% else %}
        <span class="badge badge-danger">Disabled</span>
    {% endif %}
{% endmacro %}

{% macro render_input(name, label, value='', type='text') %}
    <div class="form-group">
        <label for="{{ name }}">{{ label }}</label>
        <input type="{{ type }}" id="{{ name }}" name="{{ name }}" value="{{ value }}" class="form-control">
    </div>
{% endmacro %}
```

### 2. Importing & Using Macros in Templates

```html
{% from "macros.html" import render_badge, render_input %}

<form method="POST">
    {{ render_input('email', 'Email Address', type='email') }}
    {{ render_input('password', 'Account Password', type='password') }}
    <button type="submit">Login</button>
</form>

<p>User Status: {{ render_badge(user.status) }}</p>
```

## 3. Template Includes (`{% include %}`) vs. Macros

Flask templates support two modularization techniques: `{% include %}` and `{% macro %}`.

### 1. Includes (`{% include %}`)
Embeds an external static HTML fragment file directly in-place:

```html
<!-- Injects contents of templates/partials/navbar.html directly -->
{% include "partials/navbar.html" %}

<!-- Injects banner, or ignores silently if file is missing -->
{% include "partials/announcement_banner.html" ignore missing %}
```

### 2. Macros (`{% macro %}`)
A reusable HTML function defined inside a template file that accepts custom parameters:

```html
{% from "macros.html" import render_badge %}

<!-- Invoking macro like a Python function -->
{{ render_badge('pro') }}
```

#### ⚖️ Includes vs. Macros Detailed Comparison:

| Feature | `{% include %}` | `{% macro %}` |
| :--- | :--- | :--- |
| **Concept** | Copy-pastes external HTML fragment file | Reusable HTML function accepting arguments |
| **Parameters** | Cannot accept arguments directly (uses active template variables) | Accepts explicit parameters (e.g. `label`, `status`, `type`) |
| **Best Used For** | Static UI blocks (Navbar, Footer, Sidebar, Announcement Banner) | Parametric components (User Badges, Form Inputs, Card Lists, Pagination) |
| **Advantage** | Keeps main template clean by splitting code into subfiles | High reusability; renders dynamic UI variants based on arguments |
| **Disadvantage** | Implicit scope coupling (relies on variables set in parent template) | Must be explicitly imported (`{% from "file" import macro %}`) |
