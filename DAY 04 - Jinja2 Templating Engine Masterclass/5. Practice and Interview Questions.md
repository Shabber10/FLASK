# Day 04: Practice & Technical Interview Questions

### Q1: How does Jinja2 compile templates under the hood and why does this boost performance?
**Answer**:
Jinja2 compiles HTML template strings into Python Abstract Syntax Trees (AST) and then into native Python bytecode. Once compiled, the bytecode is cached in memory. Subsequent `render_template()` calls execute cached Python bytecode directly in the Python Virtual Machine, bypassing redundant parsing and string manipulation.

### Q2: What is `super()` in Jinja2 template inheritance and when would you use it?
**Answer**:
`super()` calls the content of a parent block within a child template overriding that block. It allows child templates to append or prepend additional content to a block without completely erasing the parent block's default markup.

```jinja2
{% block scripts %}
    {{ super() }} <!-- Preserves jQuery/Bootstrap scripts from base.html -->
    <script src="{{ url_for('static', filename='js/page_custom.js') }}"></script>
{% endblock %}
```

### Q3: How does Jinja2 protect applications against Cross-Site Scripting (XSS)?
**Answer**:
Flask configures Jinja2 to automatically escape special HTML characters (`<`, `>`, `&`, `"`, `'`) rendered within `{{ ... }}` expressions into their safe HTML entity equivalents (`&lt;`, `&gt;`, `&amp;`, `&#34;`, `&#39;`). This prevents injected `<script>` tags from executing in the user's browser.

---

### Q4: Explain the risk of using the `|safe` filter in Jinja2 templates.
**Answer**:
The `|safe` filter disables Jinja2's automatic HTML escaping for a variable, instructing Jinja2 to output raw HTML string bytes. If `|safe` is applied to untrusted user inputs (such as comments or profile bios), attackers can inject malicious JavaScript payloads, triggering XSS attacks.

### Q5: What is the difference between a Jinja2 Macro and a Jinja2 Include (`{% include %}`)?
**Answer**:
- **Macro**: A functional, parametric component defined with `{% macro name(params) %}`. It accepts arguments, maintains local variable scopes, and generates customized HTML output upon invocation.
- **Include**: A static insertion statement (`{% include "header.html" %}`) that reads another template file and embeds its raw contents in-place, sharing the parent template's global context.

### Q6: How do you register a custom filter in Flask? Show both decorator and direct assignment syntax.
**Answer**:

```python
# 1. Decorator Syntax
@app.template_filter('uppercase_reverse')
def rev_upper(s):
    return s[::-1].upper()

# 2. Direct Assignment Syntax
def rev_upper(s):
    return s[::-1].upper()

app.jinja_env.filters['uppercase_reverse'] = rev_upper
```

### Q7: What are Jinja2 Tests and how do they differ from Filters?
**Answer**:
- **Filters** (`{{ var|filter_name }}`) transform or format variable values for display output.
- **Tests** (`{% if var is test_name %}`) evaluate conditional expressions returning Boolean `True` or `False`. Custom tests are registered using `@app.template_test('test_name')`.

---

### Q8: What does the `loop.cycle()` method do inside a Jinja2 `for` loop?
**Answer**:
`loop.cycle('val1', 'val2', ...)` alternates returning one of the provided values on each iteration of a loop. It is commonly used to dynamically assign alternating CSS class names (such as row-even and row-odd) for table row zebra striping.

---

### Q9: How can you control leading and trailing whitespace around Jinja2 control tags?
**Answer**:
Add minus signs `-` inside tag delimiters: `{%-` strips whitespace preceding the tag, and `-%}` strips whitespace following the tag.

```jinja2
<div>
    {%- if user -%}
        <span>{{ user.name }}</span>
    %- endif -%}
</div>
```

---

### Q10: How do you pass data from Python into Jinja2 templates safely without using global variables?
**Answer**:
Pass variables as keyword arguments directly into `render_template()`:

```python
return render_template('profile.html', user=user_object, stats=user_stats)
```

Inside `profile.html`, `user` and `stats` are accessible within template expressions.
