# Day 04: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from absolute templating concepts up to Jinja2 AST compilation and XSS security.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is Jinja2 and why does Flask use it?
**Answer**:
Jinja2 is a fast, expressive, and secure HTML templating engine for Python. Flask uses it to dynamically combine HTML template files with Python data (variables, loops, and conditions) to generate dynamic web pages.

---

### Q2: What is the difference between `{{ ... }}` and `{% ... %}` in Jinja2?
**Answer**:
*   `{{ ... }}`: Used for **Output Expressions** to print dynamic values to the HTML page (e.g., `<h1>{{ username }}</h1>`).
*   `{% ... %}`: Used for **Control Logic Statements** such as `if` conditions, `for` loops, and template blocks (e.g., `{% if user %} ... {% endif %}`).

---

### Q3: What is Template Inheritance and why is it useful?
**Answer**:
Template Inheritance allows you to create a master base layout file (`base.html`) containing shared UI components (headers, navigation bars, footers) and define overridable `{% block %}` regions. Child templates inherit from `base.html` using `{% extends %}` and plug in their unique page content without repeating global HTML markup.

---

### Q4: How do comments work in Jinja2 templates?
**Answer**:
Jinja2 comments use `{# ... #}`. Unlike HTML comments (`<!-- ... -->`), Jinja2 comments are stripped completely on the server before the HTML is sent to the client browser, keeping internal developer notes private.

---

### Q5: How do you pass variables from Python into a Jinja2 template?
**Answer**:
Pass them as keyword arguments into `render_template()`:
```python
return render_template('index.html', username='Alice', items=[1, 2, 3])
```

## 🟡 Level 2: Intermediate Questions

### Q6: What is a Jinja2 Filter and how do you apply one?
**Answer**:
A Filter transforms or formats a variable's output before rendering. It is applied using the pipe `|` operator inside expressions:
```jinja2
<p>Name: {{ user.name|title }}</p>
<p>Total: {{ price|currency }}</p>
```

---

### Q7: What does the `loop.cycle()` method do inside a Jinja2 `for` loop?
**Answer**:
`loop.cycle('val1', 'val2', ...)` alternates returning one of the provided values on each iteration of a loop. It is commonly used to dynamically assign alternating CSS class names (such as `row-even` and `row-odd`) for table row zebra striping.

---

### Q8: What is the difference between a Jinja2 Macro and an Include (`{% include %}`)?
**Answer**:
*   **Macro**: A functional, parametric component defined with `{% macro name(params) %}`. It accepts arguments and generates customized HTML output upon invocation.
*   **Include**: A static insertion statement (`{% include "header.html" %}`) that embeds the raw content of another template file in-place, sharing the active template's context.

---

### Q9: How do you register a custom filter in Flask? Show both decorator and direct assignment syntax.
**Answer**:

```python
# 1. Decorator Syntax
@app.template_filter('uppercase_reverse')
def rev_upper(s):
    return s[::-1].upper()

# 2. Direct Assignment Syntax
def rev_upper(s):
    return s[::-1].upper()

app.jinja_env.filters['uppercase_reverse'] = rev_upper
```

---

### Q10: How do you bind static CSS and JavaScript files in Flask templates safely?
**Answer**:
Use `url_for('static', filename='...')`:
```html
<link rel="stylesheet" href="{{ url_for('static', filename='css/style.css') }}">
<script src="{{ url_for('static', filename='js/app.js') }}"></script>
```

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: How does Jinja2 compile templates under the hood and why does this boost performance?
**Answer**:
Jinja2 compiles HTML template strings into Python Abstract Syntax Trees (AST) and then into native Python bytecode. Once compiled, the bytecode is cached in memory. Subsequent `render_template()` calls execute cached Python bytecode directly in the Python Virtual Machine, bypassing redundant parsing and string manipulation.

---

### Q12: What is `super()` in Jinja2 template inheritance and when would you use it?
**Answer**:
`super()` calls the content of a parent block within a child template overriding that block. It allows child templates to append or prepend additional content to a block without completely erasing the parent block's default markup.

```jinja2
{% block scripts %}
    {{ super() }} <!-- Preserves jQuery/Bootstrap scripts from base.html -->
    <script src="{{ url_for('static', filename='js/page_custom.js') }}"></script>
{% endblock %}
```

---

### Q13: How does Jinja2 protect applications against Cross-Site Scripting (XSS)?
**Answer**:
Flask configures Jinja2 to automatically escape special HTML characters (`<`, `>`, `&`, `"`, `'`) rendered within `{{ ... }}` expressions into their safe HTML entity equivalents (`&lt;`, `&gt;`, `&amp;`, `&#34;`, `&#39;`). This prevents injected `<script>` tags from executing in the user's browser.

---

### Q14: Explain the security risk of using the `|safe` filter in Jinja2 templates.
**Answer**:
The `|safe` filter disables Jinja2's automatic HTML escaping for a variable, instructing Jinja2 to output raw HTML string bytes. If `|safe` is applied to untrusted user inputs (such as comments or profile bios), attackers can inject malicious JavaScript payloads, triggering XSS attacks.

---

### Q15: What are Jinja2 Tests and how do they differ from Filters?
**Answer**:
*   **Filters** (`{{ var|filter_name }}`) transform or format variable values for display output.
*   **Tests** (`{% if var is test_name %}`) evaluate conditional expressions returning Boolean `True` or `False`. Custom tests are registered using `@app.template_test('test_name')`.
