## 1. Triggering Tasks (`.delay` vs `.apply_async`)

Celery provides two methods for queueing tasks from Flask route handlers:

1.  **`.delay(*args, **kwargs)`**: The shorthand method for queuing a task immediately:
    ```python
    task = send_welcome_email_task.delay("user@company.com", "Alice")
    ```
2.  **`.apply_async(args, kwargs, countdown=60, eta=...)`**: Provides advanced scheduling controls:
    ```python
    # Run task in 60 seconds
    task = send_welcome_email_task.apply_async(
        args=["user@company.com", "Alice"],
        countdown=60
    )
    ```

Both methods return an **`AsyncResult`** object containing a unique `task.id` UUID string!

## 2. Returning HTTP `202 Accepted` Status Code

When a client triggers a background task, respond immediately with **`HTTP 202 Accepted`** and return the `task_id` so the client can poll for completion:

```python
from flask import request, jsonify

@app.route('/api/v1/jobs/export-csv', methods=['POST'])
def export_csv_job():
    user_id = request.json.get('user_id')
    
    # 1. Queue background task asynchronously
    task = generate_csv_report_task.delay(user_id)
    
    # 2. Return HTTP 202 Accepted + task_id
    return jsonify({
        "status": "accepted",
        "message": "CSV Report generation queued successfully.",
        "task_id": task.id,
        "status_url": f"/api/v1/jobs/{task.id}"
    }), 202
```

## 3. Polling Task Status (`AsyncResult`)

Celery tracks tasks through 5 standard lifecycle states:

```
┌─────────┐      ┌─────────┐      ┌─────────┐
│ PENDING │ ───> │ STARTED │ ───> │ SUCCESS │
└─────────┘      └─────────┘      └─────────┘
                      │                ▲
                      ▼                │
                 ┌─────────┐           │
                 │ RETRY   │ ──────────┘
                 └─────────┘
```

Clients poll task status by passing the `task_id` into **`celery_app.AsyncResult(task_id)`**:

```python
from celery.result import AsyncResult

@app.route('/api/v1/jobs/<task_id>', methods=['GET'])
def check_job_status(task_id):
    # Query Redis Result Backend for task status
    result = AsyncResult(task_id, app=celery_app)
    
    response = {
        "task_id": task_id,
        "state": result.state,
    }
    
    if result.state == 'PENDING':
        response["message"] = "Task is waiting in queue..."
    elif result.state == 'SUCCESS':
        response["message"] = "Task complete!"
        response["result"] = result.result  # Access task return value
    elif result.state == 'FAILURE':
        response["message"] = "Task failed!"
        response["error"] = str(result.info)
        
    return jsonify(response), 200
```

## 4. Automatic Task Retries (`self.retry`)

If a background task fails due to an external network glitch (e.g. SMTP email server down), instruct Celery to retry automatically with exponential backoff:

```python
@celery_app.task(bind=True, max_retries=3)
def send_email_with_retry(self, recipient):
    try:
        # Code connecting to SMTP server...
        smtp_send_email(recipient)
    except Exception as exc:
        print(f"⚠️ Network error. Retrying task in 10s... (Attempt {self.request.retries + 1}/3)")
        # Retry task after 10 seconds
        raise self.retry(exc=exc, countdown=10)
```
