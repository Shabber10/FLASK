## 1. RBAC Permissions Matrix

Enterprise applications divide user capabilities into distinct Roles:

| Role | Accessible Endpoints | Permissions |
| :--- | :--- | :--- |
| **`User`** | `/dashboard`, `/profile` | Read/Write personal account data |
| **`Editor`** | `/dashboard`, `/articles/edit` | Manage platform content |
| **`Admin`** | `/dashboard`, `/admin/settings`, `/admin/users` | Full administrative control |

## 2. Why `functools.wraps` is MANDATORY for Flask Decorators

When writing custom Python decorators for Flask route functions, you **MUST** decorate your wrapper function with **`@wraps(f)`** from Python's standard `functools` module:

```python
from functools import wraps

# BAD (Without @wraps): Overwrites function __name__ to 'wrapper', causing route endpoint collision errors in Flask!
def bad_decorator(f):
    def wrapper(*args, **kwargs):
        return f(*args, **kwargs)
    return wrapper

# GOOD (With @wraps): Preserves original function metadata (__name__, __doc__)!
def good_decorator(f):
    @wraps(f)
    def wrapper(*args, **kwargs):
        return f(*args, **kwargs)
    return wrapper
```

## 3. Authoring Custom RBAC Route Decorators

### A. `@admin_required` Decorator
Create a decorator restricting access exclusively to users with the `Admin` role:

```python
from functools import wraps
from flask import abort
from flask_login import current_user

def admin_required(f):
    """Decorator ensuring current_user is authenticated AND has 'Admin' role."""
    @wraps(f)
    def decorated_function(*args, **kwargs):
        if not current_user.is_authenticated:
            abort(401)  # 401 Unauthorized (Not logged in)
            
        if getattr(current_user, 'role', None) != 'Admin':
            abort(403)  # 403 Forbidden (Logged in, but insufficient permission)
            
        return f(*args, **kwargs)
    return decorated_function
```

---

### B. Dynamic `@role_required(*allowed_roles)` Decorator
Create a flexible decorator accepting multiple allowed role strings:

```python
def role_required(*allowed_roles):
    """Decorator allowing access to users matching any specified role."""
    def decorator(f):
        @wraps(f)
        def decorated_function(*args, **kwargs):
            if not current_user.is_authenticated:
                abort(401)
                
            if current_user.role not in allowed_roles:
                abort(403)
                
            return f(*args, **kwargs)
        return decorated_function
    return decorator
```

### Usage in Flask Route Handlers:
```python
@app.route('/admin/settings')
@login_required
@admin_required  # Admin only!
def admin_settings():
    return "Secret Admin Settings"

@app.route('/content/editor')
@login_required
@role_required('Editor', 'Admin')  # Editor OR Admin allowed!
def editor_portal():
    return "Content Editor Portal"
```

## 4. HTTP `401 Unauthorized` vs. `403 Forbidden`

Understanding the exact difference is crucial for API design and technical interviews:

*   **`HTTP 401 Unauthorized`**: The client has not presented valid authentication credentials.
    > *"I don't know who you are. Please log in first."*
*   **`HTTP 403 Forbidden`**: The client is authenticated, but lacks sufficient permissions for the requested resource.
    > *"I know who you are (User #42), but you are not allowed to access Admin settings!"*

## 5. Template-Level Role Checks in Jinja2

Hide or show navigation links in HTML templates based on the active user's role:

```html
{% if current_user.is_authenticated %}
    <p>Welcome, {{ current_user.username }} ({{ current_user.role }})</p>
    
    {% if current_user.role == 'Admin' %}
        <a class="btn-admin" href="{{ url_for('admin_settings') }}">Admin Panel</a>
    {% endif %}
    
    <a href="{{ url_for('logout') }}">Logout</a>
{% else %}
    <a href="{{ url_for('login') }}">Login</a>
{% endif %}
```
