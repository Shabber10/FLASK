## 1. Authentication vs. Authorization in Plain English

People often confuse these two concepts, but they serve completely different purposes:

*   **Authentication (AuthN)**: *"Who are you?"*
    > Proving your identity by entering your username and password.
    > *Example*: Logging into your account.
*   **Authorization (AuthZ)**: *"What are you allowed to do?"*
    > Checking whether your user account has permission to access a specific feature or page.
    > *Example*: A regular user trying to access the `/admin/settings` page gets blocked because they lack Admin authorization!

## 2. The Plaintext Password Crime

> 🚨 **GOLDEN SECURITY RULE**: NEVER, EVER store plaintext passwords in a database!
> If your database contains a table where column `password` = `"secret123"`, any database leak will immediately expose every user's real password!

## 3. What is a One-Way Cryptographic Hash?

A **Cryptographic Hash Function** is a mathematical formula that takes any text input (like `"my_password123"`) and turns it into a fixed-length string of scrambled characters (the **Hash**):

```
"my_password123"  ──[ PBKDF2 / Bcrypt / Scrypt ]──>  "pbkdf2:sha256:260000$8x9A...$7b2f..."
```

### Key Properties of Hashes:
1.  **One-Way Only**: You can easily compute the hash from the password, but it is mathematically impossible to reverse the hash back into the original password!
2.  **Deterministic**: The same password always produces the exact same hash.
3.  **Salted**: Modern hash functions add random bytes (called **Salt**) to every password before hashing. Even if two users choose the exact same password (`"123456"`), their resulting hashes will be completely different!

## 4. What is Flask-Login?

**Flask-Login** is the standard Flask extension for managing user login sessions. It handles:
*   Storing logged-in user IDs inside session cookies.
*   Providing the **`current_user`** proxy variable in templates and Python routes.
*   Protecting private routes using the **`@login_required`** decorator.
*   Logging users in (`login_user(user)`) and out (`logout_user()`).

---

## 5. What is Role-Based Access Control (RBAC)?

**Role-Based Access Control (RBAC)** is a security model where access permissions are assigned to specific **Roles** (e.g. `Admin`, `Editor`, `User`), and roles are assigned to users:

```
[ User: Alice ] ────> Role: Admin   ────> Can access /admin/settings, /delete-user
[ User: Bob ]   ────> Role: User    ────> Can access /profile, /orders
```

We enforce RBAC in Flask using **Custom Route Decorators** like `@role_required('Admin')`!
