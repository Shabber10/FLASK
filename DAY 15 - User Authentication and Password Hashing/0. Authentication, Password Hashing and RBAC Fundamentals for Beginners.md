## 1. Authentication vs. Authorization in Plain English

*   **Authentication (AuthN)**: *"Who are you?"*
    > Proving your identity by entering your username and password.
    > *Example*: Logging into your account.
*   **Authorization (AuthZ)**: *"What are you allowed to do?"*
    > Checking whether your user account has permission to access a specific feature or page.
    > *Example*: A regular user trying to access the `/admin/settings` page gets blocked because they lack Admin authorization!

## 2. The Plaintext Password Crime & Cryptographic Hashes

> 🚨 **GOLDEN SECURITY RULE**: NEVER, EVER store plaintext passwords in a database!

A **Cryptographic Hash Function** turns any text input (like `"my_password123"`) into an irreversible scrambled string:

```
"my_password123"  ──[ PBKDF2 / Bcrypt / Scrypt ]──>  "scrypt:32768:8:1$vK9...$8d3f..."
```

### Key Properties of Hashes:
1.  **One-Way Only**: Mathematically impossible to reverse back into the original password!
2.  **Deterministic**: The same password always produces the exact same hash.
3.  **Salted**: Random salt bytes are appended to prevent rainbow table attacks.

## 3. What is Tokenization? (Class Notes Core Concept)

**Tokenization** is the process of converting data (email, user ID, etc.) into a **secure signed string** called a **token**.

*   The token can safely be sent in **URLs**, **emails**, or **forms**.
*   Later, the server can verify and decode the token using the secret key **without storing anything in the database**!

```
Original Data  ──>  abc@gmail.com
Converted to   ──>  ImFiY0BnbWFpbC5jb20i.Ze1F4g.QJ1g23sdFsd
```

---

## 4. Inside the Token (The 3 Parts)

Think of a token like a **sealed envelope 📩**:

```
ImFiY0BnbWFpbC5jb20i  .  Ze1F4g  .  QJ1g23sdFsd
      ▲                     ▲             ▲
   1. DATA (Payload)    2. TIME      3. SIGNATURE
```

| Part | Component | Example | Plain-English Role |
| :---: | :--- | :--- | :--- |
| **1️⃣** | **DATA (Payload)** | `ImFiY0BnbWFpbC5jb20i` | Base64-encoded original data (e.g. `abc@gmail.com`). Tells **what you want to store**. |
| **2️⃣** | **TIMESTAMP** | `Ze1F4g` | Epoch timestamp of when the token was created. Used to **check expiration**. |
| **3️⃣** | **SIGNATURE** | `QJ1g23sdFsd` | Cryptographic signature created using your `SECRET_KEY`. Ensures **data is tamper-proof**. |

### 🔹 Simple Formula:
$$\text{TOKEN} = \text{DATA} + \text{TIMESTAMP} + \text{SIGNATURE}$$

> 🛡️ **Tamper Defense**: If a malicious user changes `abc@gmail.com` to `admin@gmail.com` in the first part, the signature will no longer match and the server immediately rejects the token (`BadSignature` error)!

## 5. What is `itsdangerous` & `URLSafeTimedSerializer`?

**`itsdangerous`** is the standard Python security library (created by the Pallets team) used in Flask to generate and verify secure tokens.

### Common Uses:
1.  **Email Verification Links** (`https://app.com/verify/<token>`)
2.  **Password Reset Links** (`https://app.com/reset-password/<token>`)
3.  **OTP Verification Workflows**
4.  **Session Cookies & CSRF Protection**

### 🛠️ Key Methods:
*   **`URLSafeTimedSerializer(secret_key, salt)`**: Initializes the serializer with a secret key and namespace salt.
*   **`serializer.dumps(data)`**: **Encodes** data into a URL-safe signed token string.
*   **`serializer.loads(token, max_age=300)`**: **Decodes** the token, verifies the signature, and checks that the token is younger than `max_age` seconds (e.g. 300s = 5 minutes).
    *   Throws **`SignatureExpired`** if the token is older than `max_age`.
    *   Throws **`BadSignature`** if the token was altered or forged.

## 6. Real-World Example: Email Verification Link in Flask

```python
from flask import Flask, request
from itsdangerous import URLSafeTimedSerializer, SignatureExpired, BadSignature

app = Flask(__name__)
SECRET_KEY = "supersecretkey123"
serializer = URLSafeTimedSerializer(SECRET_KEY, salt="email-confirm")

# 1. User registers -> Generate token and send link
@app.route("/send_verification", methods=["POST"])
def send_verification():
    email = request.form["email"]
    # Tokenize email
    token = serializer.dumps(email)
    verification_link = f"http://127.0.0.1:5000/verify/{token}"
    return f"Click link to verify: <a href='{verification_link}'>{verification_link}</a>"

# 2. User clicks verification link -> Validate token & expiry
@app.route("/verify/<token>")
def verify(token):
    try:
        # max_age=300 enforces 5-minute expiration
        email = serializer.loads(token, max_age=300)
        return f"✅ Email verified successfully for: {email}"
    except SignatureExpired:
        return "❌ Verification link expired (older than 5 minutes)"
    except BadSignature:
        return "❌ Invalid or tampered verification link"
```

## 7. Numeric 6-Digit OTP Email Verification (`random` + `smtplib`)

When using a 6-digit numeric OTP instead of a URL token:

```python
import random
import smtplib
from email.mime.text import MIMEText
from flask import Flask, request

app = Flask(__name__)
otp_storage = {}  # In-memory dictionary: {email: otp_code}

SENDER_EMAIL = "yourgmail@gmail.com"
SENDER_PASSWORD = "your_16_digit_app_password"

def send_email_otp(receiver, otp):
    msg = MIMEText(f"Your OTP Code is: {otp}\nValid for 2 minutes.")
    msg["Subject"] = "Your Verification Code"
    msg["From"] = SENDER_EMAIL
    msg["To"] = receiver
    
    with smtplib.SMTP("smtp.gmail.com", 587) as server:
        server.starttls()
        server.login(SENDER_EMAIL, SENDER_PASSWORD)
        server.send_message(msg)

@app.route("/send_otp", methods=["POST"])
def send_otp():
    email = request.form['email']
    otp = random.randint(100000, 999999)  # 6-digit random code
    otp_storage[email] = str(otp)
    send_email_otp(email, otp)
    return "OTP Sent to your email!"

@app.route("/verify_otp", methods=["POST"])
def verify_otp():
    email = request.form['email']
    otp_entered = request.form['otp_entered']
    if email in otp_storage and otp_storage[email] == otp_entered:
        return f"✅ OTP Verified Successfully for {email}"
    return "❌ Invalid OTP! Please try again."
```
