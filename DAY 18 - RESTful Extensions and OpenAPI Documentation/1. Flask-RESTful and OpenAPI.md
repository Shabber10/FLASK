## 1. Defining Class-Based `Resource` Classes

In `Flask-RESTful`, you create a resource by inheriting from `flask_restful.Resource`. Inside the class, define methods matching HTTP verbs (`get`, `post`, `put`, `delete`):

```python
from flask import Flask
from flask_restful import Api, Resource, abort

app = Flask(__name__)
api = Api(app)  # Connect Flask-RESTful API manager

# In-Memory items database
items_db = {
    1: {"id": 1, "name": "Wireless Mouse", "price": 29.99},
    2: {"id": 2, "name": "Mechanical Keyboard", "price": 89.99}
}

class ItemResource(Resource):
    """Class-Based Resource handling single Item operations."""
    
    def get(self, item_id):
        """GET /items/<id> -> Fetch single item."""
        if item_id not in items_db:
            abort(404, message=f"Item #{item_id} not found.")
        return items_db[item_id], 200

```python
    def delete(self, item_id):
        """DELETE /items/<id> -> Remove single item."""
        if item_id in items_db:
            del items_db[item_id]
            return "", 204
        abort(404, message=f"Item #{item_id} not found.")
```

#### ⚖️ Function-Based View Routes vs Class-Based REST Resources (`MethodView`)

| Architectural Feature | Function-Based Routes (`@app.route()`) | Class-Based REST Resources (`MethodView`) |
| :--- | :--- | :--- |
| **Code Organization** | Scattered functions across multiple decorators | Grouped logically inside 1 class per resource |
| **HTTP Verb Handling** | Repetitive `if request.method == 'POST':` branching | Separate dedicated class methods (`get`, `post`, `delete`) |
| **Inheritance & Reusability** | Cannot use OOP inheritance across routes | Can inherit shared logic from base `Resource` classes |
| **OpenAPI Generation** | Hard to generate Swagger documentation automatically | Effortless automatic OpenAPI 3.0 specification generation |

## 2. Registering Resources (`api.add_resource`)

Register `Resource` classes onto your `Api` manager instance using **`api.add_resource()`**:

```python
# Bind ItemResource to URL pattern /items/<int:item_id>
api.add_resource(ItemResource, '/items/<int:item_id>')
```

## 3. Request Parsing (`reqparse.RequestParser`)

Flask-RESTful includes `reqparse` to validate incoming form and JSON body arguments:

```python
from flask_restful import reqparse

item_parser = reqparse.RequestParser()
item_parser.add_argument('name', type=str, required=True, help="Name is required.")
item_parser.add_argument('price', type=float, required=True, help="Price must be a float.")

class ItemListResource(Resource):
    def post(self):
        # Parse and validate incoming arguments
        args = item_parser.parse_args()
        new_id = len(items_db) + 1
        items_db[new_id] = {"id": new_id, "name": args['name'], "price": args['price']}
        return items_db[new_id], 201

api.add_resource(ItemListResource, '/items')
```

## 4. Output Field Marshalling (`@marshal_with`)

Flask-RESTful provides `@marshal_with` to filter and format outgoing dictionary fields:

```python
from flask_restful import fields, marshal_with

# Define output field filtering dictionary
resource_fields = {
    'id': fields.Integer,
    'name': fields.String,
    'price': fields.Float
}

class FormattedItemResource(Resource):
    @marshal_with(resource_fields)
    def get(self, item_id):
        return items_db.get(item_id)  # Automatically formatted using resource_fields!
```
