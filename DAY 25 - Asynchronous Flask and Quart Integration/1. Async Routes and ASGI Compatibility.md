## 1. Native `async def` Routes in Flask 2.0+

Install `asgiref` (required by Flask to execute async routes):

```bash
pip install asgiref httpx
```

Define async routes using standard Python `async def` syntax:

```python
import asyncio
import httpx
from flask import Flask, jsonify

app = Flask(__name__)

# Concurrent Async Helper Function
async def fetch_weather_api(city_name):
    async with httpx.AsyncClient() as client:
        # Non-blocking HTTP GET request!
        response = await client.get(f"https://api.weather.com/v1/{city_name}")
        return response.json()

# Native Async Route in Flask 2.0+
```python
@app.route('/api/v1/weather/<city>')
async def get_weather(city):
    weather_data = await fetch_weather_api(city)
    return jsonify({"city": city, "weather": weather_data})
```

#### ⚖️ Synchronous WSGI Architecture vs Asynchronous ASGI Architecture

| Architectural Characteristic | Traditional WSGI Server (`gunicorn`) | Asynchronous ASGI Server (`uvicorn` / `hypercorn`) |
| :--- | :--- | :--- |
| **Concurrency Model** | 1 OS Thread per active HTTP request | **1 `asyncio` Event Loop driving 10,000+ requests** |
| **I/O Wait Behavior** | 🛑 Thread blocks during database / HTTP calls | ✅ Event loop yields CPU to serve other connections |
| **Native WebSockets** | ❌ Requires custom worker extensions | ✅ Built-in native support |
| **Response Streaming** | Synchronous chunked encoding | Async Generator `yield` streaming |
| **Concurrency Ceiling** | Limited by OS thread RAM overhead (~100-500) | Scalable to thousands of concurrent connections |

## 2. High-Concurrency Parallel Fetching (`asyncio.gather`)

When your API must aggregate data from multiple independent microservices (e.g. Weather API, Stock API, User Profile API), execute them **concurrently in parallel** using **`asyncio.gather()`**:

```python
@app.route('/api/v1/dashboard-summary')
async def get_dashboard():
    # ⚠️ Sequential execution would take 1s + 1s + 1s = 3.0 seconds!
    # ✅ Parallel asyncio.gather takes 1.05 seconds total!
    user_task = fetch_user_profile(42)
    stats_task = fetch_analytics_stats()
    news_task = fetch_breaking_news()

    user, stats, news = await asyncio.gather(user_task, stats_task, news_task)

    return jsonify({
        "user": user,
        "stats": stats,
        "news": news
    })
```

## 3. The Blocking I/O Trap ⚠️

> ⚠️ **CRITICAL ASYNC WARNING**: Inside an `async def` route function, calling blocking synchronous functions (like `time.sleep()`, synchronous `requests.get()`, or standard blocking SQLAlchemy DB calls) will **FREEZE THE ENTIRE EVENT LOOP**!

```python
# ❌ INCORRECT (Freezes the async event loop for all users!)
@app.route('/bad-async')
async def bad_route():
    time.sleep(5)  # Blocking synchronous sleep!
    return jsonify({"status": "blocked"})

# ✅ CORRECT (Non-blocking async sleep)
@app.route('/good-async')
async def good_route():
    await asyncio.sleep(5)  # Non-blocking async sleep!
    return jsonify({"status": "unblocked"})
```

If you must call a blocking CPU-bound or synchronous function inside an async route, run it inside a thread pool using **`asyncio.to_thread()`**:

```python
# Offload blocking synchronous function to background thread pool
result = await asyncio.to_thread(blocking_sqlalchemy_query_function, user_id)
```

## 4. Deploying Flask as an ASGI App (`WsgiToAsgi`)

To serve Flask using high-performance ASGI servers (like **Uvicorn** or **Hypercorn**), wrap your Flask app with `asgiref.wsgi.WsgiToAsgi`:

```python
# asgi_app.py
from asgiref.wsgi import WsgiToAsgi
from app_factory import create_app

flask_app = create_app()

# Convert WSGI Flask app into an ASGI compatible application
asgi_app = WsgiToAsgi(flask_app)
```

Run with Uvicorn:
```bash
uvicorn asgi_app:asgi_app --host 0.0.0.0 --port 5000 --workers 4
```
