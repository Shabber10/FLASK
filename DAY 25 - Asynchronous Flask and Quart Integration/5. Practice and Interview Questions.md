# Day 25: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from `async`/`await` basics up to native Flask 2.0+ async routes, `asyncio.gather()` parallel execution, Quart framework migration, and ASGI Uvicorn deployments.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is the difference between Synchronous and Asynchronous execution?
**Answer**:
*   **Synchronous**: Execution flows sequentially. A thread blocks and waits for I/O operations (like network calls) to complete before moving to the next line of code.
*   **Asynchronous**: Execution uses an event loop. When a task pauses to wait for I/O (`await`), the CPU immediately switches to process other incoming requests.

---

### Q2: What is the difference between WSGI and ASGI?
**Answer**:
*   **WSGI**: Synchronous 1-thread-per-request web server gateway interface used by classic Flask.
*   **ASGI**: Asynchronous event-loop driven interface supporting high-concurrency `async`/`await` I/O, WebSockets, and HTTP streaming.

---

### Q3: What library powers `async def` routes in Flask 2.0+ under the hood?
**Answer**:
`asgiref` (specifically `asgiref.sync.async_to_sync`).

---

### Q4: What is Quart?
**Answer**:
Quart is an ASGI-native Python web framework designed as an async-first 100% API-compatible clone of Flask, allowing developers to migrate Flask apps to full ASGI performance easily.

---

### Q5: What does the `await` keyword do in Python?
**Answer**:
`await` pauses the execution of an `async def` coroutine function until the awaited task/future completes, returning control back to the event loop to process other tasks.

---

## 🟡 Level 2: Intermediate Questions

### Q6: How do you run multiple asynchronous HTTP calls concurrently in parallel?
**Answer**:
Use `asyncio.gather(*tasks)`:

```python
results = await asyncio.gather(
    fetch_service_a(),
    fetch_service_b(),
    fetch_service_c()
)
```

---

### Q7: What major pitfall occurs if you call `time.sleep(5)` inside a Flask `async def` route?
**Answer**:
`time.sleep(5)` is a blocking synchronous function. Calling it inside an `async def` route will **freeze the entire `asyncio` event loop**, blocking all other concurrent users from being served until the 5 seconds expire!

---

### Q8: How should you handle blocking synchronous functions inside an `async def` route?
**Answer**:
Offload blocking calls to a background thread pool using `asyncio.to_thread()`:

```python
result = await asyncio.to_thread(blocking_function, arg1)
```

---

### Q9: What is the main difference between reading request JSON in Flask vs Quart?
**Answer**:
*   In Flask: `payload = request.get_json()` (Synchronous method).
*   In Quart: `payload = await request.get_json()` (Asynchronous coroutine method).

---

### Q10: How do you wrap a Flask WSGI app to run on Uvicorn ASGI server?
**Answer**:
Wrap it with `asgiref.wsgi.WsgiToAsgi`:

```python
from asgiref.wsgi import WsgiToAsgi
asgi_app = WsgiToAsgi(flask_app)
```

---

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: Why does native `async def` in Flask 2.0+ not provide true ASGI concurrency unless deployed on an ASGI server or Quart?
**Answer**:
When Flask runs under standard WSGI (like Gunicorn WSGI workers), each request still occupies 1 WSGI thread. Flask uses `asgiref` to run the `async def` route on a temporary event loop inside that thread, but it does NOT allow that WSGI thread to accept new HTTP connections while waiting. True full-server concurrency requires Quart or wrapping Flask with `WsgiToAsgi` on Uvicorn/Hypercorn.

---

### Q12: How do you implement Server-Sent Events (SSE) streaming responses in Quart?
**Answer**:
Return an `async generator` function yielding formatted SSE data strings in a Quart `Response` with `content_type='text/event-stream'`:

```python
async def event_stream():
    while True:
        await asyncio.sleep(1)
        yield f"data: {get_time()}\n\n"

@app.route('/stream')
async def stream():
    return Response(event_stream(), content_type='text/event-stream')
```

---

### Q13: What is the difference between CPU-bound tasks and I/O-bound tasks in async architectures?
**Answer**:
*   **I/O-bound tasks**: (Network API calls, database queries, disk reads) Benefit enormously from `asyncio` because the CPU spends time waiting.
*   **CPU-bound tasks**: (Image processing, machine learning inference, heavy math) Do NOT benefit from `asyncio` because they require 100% CPU core utilization. CPU-bound tasks should be offloaded to Celery workers or `ProcessPoolExecutor`.

---

### Q14: How does FastAPI compare to Quart for enterprise microservices?
**Answer**:
*   **Quart**: Best when migrating existing Flask applications, blueprints, and templates to ASGI with zero code rewrite.
*   **FastAPI**: Best for greenfield REST APIs requiring automatic OpenAPI schema generation, Pydantic type validation, and dependency injection.

---

### Q15: How can you handle database connection pooling when using `async` routes in Flask/Quart?
**Answer**:
Traditional SQLAlchemy engines use synchronous blocking socket drivers (`psycopg2`). For async routes, use **Async SQLAlchemy** (`sqlalchemy.ext.asyncio`) with async drivers (`asyncpg` for PostgreSQL or `aiosqlite` for SQLite) to prevent database queries from blocking the event loop.
