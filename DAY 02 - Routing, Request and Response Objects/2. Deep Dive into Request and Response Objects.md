# Day 02 - Module 2: Deep Dive into Request & Response Objects

Welcome to **Module 2** of Day 02! Now that we know how Flask routes URLs, let's explore how to inspect incoming request data (`request`) and build customized outgoing responses (`response`).

---

## 1. The `request` Object Architecture

When a browser sends an HTTP request, Flask encapsulates all incoming data into a global `request` proxy object:

```
                           +-------------------------------+
                           |    Incoming HTTP Request      |
                           +---------------+---------------+
                                           |
         +------------------+--------------+--------------+-------------------+
         |                  |                             |                   |
         v                  v                             v                   v
 +---------------+  +---------------+             +---------------+   +---------------+
 | request.args  |  | request.form  |             | request.json  |   | request.files |
 | (Query String)|  | (POST Form)   |             | (Parsed JSON) |   | (FileStorage) |
 +---------------+  +---------------+             +---------------+   +---------------+
```

---

### 1. URL Query Parameters (`request.args`)
`request.args` parses the query parameters from the URL (`?search=flask&page=2&tag=web&tag=python`):

```python
from flask import request

# 1. Fetch single value with default fallback and type conversion
search_query = request.args.get('search', default='', type=str)
page_number = request.args.get('page', default=1, type=int)

# 2. Fetch multi-value lists (for keys repeated in query string like ?tag=web&tag=python)
tags = request.args.getlist('tag')  # Returns ['web', 'python']
```

> **Why `getlist()`?** `request.args` is an `ImmutableMultiDict`. Standard dictionary lookup `request.args['tag']` returns only the *first* value. Use `.getlist('tag')` to get *all* values!

---

### 2. Form Submissions (`request.form`)
Parses data submitted via standard HTML forms (`application/x-www-form-urlencoded`):

```python
username = request.form.get('username')
password = request.form.get('password')
```

---

### 3. JSON Payloads (`request.json` / `get_json()`)
Parses JSON payloads sent by modern web apps or mobile APIs (`application/json`):

```python
# Returns parsed Python dictionary or raises HTTP 400 Bad Request if JSON is invalid
data = request.get_json()

# Safe parsing: Returns None instead of crashing if JSON is invalid
data = request.get_json(silent=True)
```

---

### 4. Client Metadata & Headers
*   `request.headers`: Case-insensitive dictionary of HTTP headers (`request.headers.get('Authorization')`).
*   `request.remote_addr`: Client's IP address (`"127.0.0.1"`).
*   `request.user_agent.string`: Browser and operating system info.
*   `request.is_secure`: `True` if connected via encrypted HTTPS.

## 2. Flexible Flask Response Formats

Flask view functions can return several valid response formats:

```python
# Format 1: Plain HTML / String (Defaults to 200 OK, text/html)
return "<h1>Success</h1>"

# Format 2: Dictionary / List (Flask automatically converts to JSON, application/json)
return {"status": "success", "user_id": 42}, 200

# Format 3: Explicit Response Tuple (Body, Status Code, Headers)
return "Created", 201, {"X-Custom-Header": "Flask-Masterclass"}
```

---

## 3. Explicit Response Control with `make_response()`

When you need total control over HTTP status codes, custom response headers, or setting secure cookies, wrap your output with **`make_response()`**:

```python
from flask import Flask, make_response, jsonify

app = Flask(__name__)

@app.route('/api/login', methods=['POST'])
def login():
    data = {"message": "User authenticated successfully"}
    
    # 1. Wrap JSON response with 200 OK status
    response = make_response(jsonify(data), 200)
    
    # 2. Attach custom HTTP headers
    response.headers['X-Server-Region'] = 'US-East-1'
    response.headers['Cache-Control'] = 'no-cache, no-store, must-revalidate'
    
    # 3. Set a Secure HTTP-Only Cookie
    response.set_cookie(
        key='session_token',
        value='secure_xyz_token_9988',
        max_age=3600,       # Cookie expires in 1 hour (in seconds)
        httponly=True,      # Protects against XSS attacks (JS cannot read cookie)
        secure=True,        # Requires encrypted HTTPS connection
        samesite='Lax'      # Protects against CSRF attacks
    )
    
    return response
```

## 4. Redirects (`redirect()`) & Aborting Requests (`abort()`)

### 1. HTTP Redirections (`redirect()`)
Sends an HTTP redirection status code (usually `302 Found` temporary or `301 Moved Permanently`) instructing the client browser to immediately request another URL:

```python
from flask import redirect, url_for

@app.route('/admin')
def admin():
    return "Admin Dashboard"

@app.route('/user/<name>')
def user(name):
    # Conditional Redirection: Redirect to admin if username is 'admin'
    if name == 'admin':
        return redirect(url_for('admin'))
    return f"Welcome, {name}"

@app.route('/hello/<name>')
def hello(name):
    # Forwarding request parameters dynamically via url_for
    return redirect(url_for('user', name=name))
```

### 2. Aborting Requests (`abort()`)
Immediately halts view execution and raises an `HTTPException` error page:

```python
from flask import abort

@app.route('/admin')
def admin_panel():
    is_admin = False
    if not is_admin:
        # Immediately stops code execution and returns 403 Forbidden
        abort(403, description="Access restricted to site administrators.")
```
