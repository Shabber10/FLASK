## 1. What is URL Routing?

When you open a browser and visit a website like Amazon or YouTube, you navigate to different addresses:
*   `http://127.0.0.1:5000/` (Home page)
*   `http://127.0.0.1:5000/course` (Course list)
*   `http://127.0.0.1:5000/user/shabber` (User profile page)

**URL Routing** is the mechanism in Flask that listens to the address path requested by the client browser and directs it to the matching Python view function.

```
Incoming Request: GET /course
         │
         ▼
+─────────────────────────────────+
|      Flask Routing Engine       |
+─────────────────────────────────+
         │
         ▼
Matches: @app.route('/course')
         │
         ▼
Executes: def courses(): return render_template('courses.html')
```

> 🏬 **Analogy**: Routing is like a **directory board in a shopping mall**. When a customer asks for "Shoes", the directory directs them to Room 102. When they ask for "Food", it directs them to Room 305.

## 2. Four Main Ways Clients Send Data to Flask

When a user interacts with a website (searching, logging in, uploading, or sending API requests), their browser or client app passes data to the backend Flask server in 4 primary ways:

```
                               DATA TRANSMISSION WAYS
                                         │
       ┌──────────────────┬──────────────┴───────────────┬──────────────────┐
       ▼                  ▼                              ▼                  ▼
1. Path Parameters  2. Query Parameters           3. Form Data        4. JSON Data
  (/user/Jani/22)     (/search?q=flask&page=2)      (POST Form)        (API Body)
```

| Method | Example URL / Format | How Flask Accesses It | Primary Purpose |
| :--- | :--- | :--- | :--- |
| **Path Parameter** | `/student/Jani/22` | Function args: `def user(name, age)` | Identifier inside the URL path. |
| **Query Parameter** | `/search?q=flask&page=2` | `request.args.get('q')` | Search, filtering, sorting, pagination. |
| **Form Data** | `username=Jani&email=jani@gmail.com` | `request.form.get('username')` | HTML form submissions (`POST`). |
| **JSON Data** | `{"name": "Jani", "course": "Python"}` | `request.get_json()` / `request.json.get()` | REST APIs, AJAX, mobile apps (`POST/PUT`). |

## 3. HTTP Methods (Verbs) & Real-Life Analogies

Every HTTP request includes an HTTP verb that tells Flask what action to take:

| HTTP Method | Purpose | Data Location | Flask Access | Real-Life Analogy |
| :--- | :--- | :--- | :--- | :--- |
| **GET** | Retrieve / Read data | URL query string | `request.args.get()` | Viewing your profile on a social site |
| **POST** | Create new data | Request body (Form / JSON) | `request.form` / `request.get_json()` | Signing up for a new account |
| **PUT** | Update existing data | JSON body | `request.json.get()` | Editing your existing profile information |
| **DELETE** | Remove data | URL parameter or body | Path parameter / `request.json` | Deleting your account or deleting a user |

## 4. In-Memory (RAM) Storage vs. Database Storage in Flask

When you build early prototypes in Flask without a database (like MySQL or PostgreSQL), data is stored in Python in-memory data structures (e.g. lists `users = [...]` or dicts):

```python
users = [
    {'id': 1, "name": "ramu", "age": 23},
    {'id': 2, "name": "harish", "age": 19}
]
```

### 🧠 How In-Memory (RAM) Storage Behaves

1.  **Stored in System RAM**: The `users` list resides strictly in the **RAM (Random Access Memory)** of your machine running the Python process.
2.  **State Persistence during Server Lifetime**: As long as the server is running, `POST`, `PUT`, and `DELETE` requests modify the `users` list in RAM.
3.  **Data Loss on Server Restart**: If you stop or restart the Flask server, RAM is completely cleared, and `users` resets back to its initial hardcoded state!
4.  **State Mutation Gotcha (Why `updated_data` becomes `[]`)**:
    *   If you send `DELETE /deleteuser/1`, `ramu` is removed from the list.
    *   If you send `DELETE /deleteuser/2`, `harish` is removed.
    *   If you send `DELETE /deleteuser/1` again, the list is now empty (`[]`), so Flask returns:
        `{"message": "user id 1 is not found..."}` or `{"updated_data": []}`.

### 💾 Comparison Table: RAM vs. Database

| Property | In-Memory Storage (RAM) | Database Storage (MySQL / SQLite) |
| :--- | :--- | :--- |
| **Persistence** | Temporary ❌ (Lost on restart) | Permanent ✅ (Persisted on hard disk) |
| **Speed** | Ultra-Fast ⚡ | Extremely Fast with Indexing |
| **Recovery** | Cannot recover deleted items ❌ | Backup and recovery supported ✅ |
| **Best Used For** | Learning, unit tests, quick prototyping | Production Enterprise Web Apps |

> 💡 **Interview Tip**:  
> *Q: Where is data stored in Flask if no database is connected?*  
> *A: "Data is stored in-memory in RAM, which means it is volatile and temporary, and will be reset whenever the Flask process restarts."*
