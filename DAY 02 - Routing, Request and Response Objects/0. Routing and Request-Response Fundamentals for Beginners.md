## 1. What is URL Routing?

When you open a browser and visit a website like Amazon or YouTube, you don't stay on just one page. You navigate to different addresses:
*   `https://website.com/` (Home page)
*   `https://website.com/about` (About Us page)
*   `https://website.com/user/shabber` (User profile page)

**URL Routing** is the mechanism in Flask that listens to the address (path) requested by the user's browser and directs it to the matching Python function.

```
Incoming Request: GET /about
         │
         ▼
+─────────────────────────────────+
|      Flask Routing Engine       |
+─────────────────────────────────+
         │
         ▼
Matches: @app.route('/about')
         │
         ▼
Executes: def about_page(): return "About Us"
```

> **Analogy**: Routing is like a **directory board in a shopping mall**. When a customer asks for "Shoes", the board directs them to Room 102. When they ask for "Food", it directs them to Room 305.

## 2. Three Ways Clients Send Data to Servers

When a user interacts with a website (searching, logging in, or uploading a photo), their browser passes data to the backend Python server. Data can be sent in 3 main ways:

```
                              DATA TRANSMISSION WAYS
                                        │
      ┌─────────────────────────────────┼─────────────────────────────────┐
      ▼                                 ▼                                 ▼
1. Path Parameters              2. Query Parameters             3. Request Body Payload
(e.g., /user/42)                (e.g., /search?q=flask)         (Form submit / JSON)
```

### 1. Path Parameters (Part of the URL path)
Used to identify a specific item or resource directly inside the URL.
*   **Example URL**: `http://127.0.0.1:5000/user/42`
*   **Use Case**: Fetching user #42 or product #105.

### 2. Query Parameters (Search string after `?`)
Used to filter, sort, or paginate data without changing the core URL path.
*   **Example URL**: `http://127.0.0.1:5000/search?q=flask&page=2`
*   **Notice**: Starts with a `?`, and multiple values are separated by `&`.
*   **Use Case**: Search engines, product filters, page numbers.

### 3. Request Body Payload (Hidden inside the request)
Used when sending large, sensitive, or complex data to the server.
*   **Form Data**: Submitting HTML forms (e.g., username & password on login).
*   **JSON Data**: Mobile apps or modern APIs sending structured data (`{"username": "shabber"}`).
*   **Use Case**: Login forms, sign-up forms, credit card payments.

## 3. HTTP Verbs (Methods): Asking the Server to Take Action

Every HTTP request includes a **Verb** (Method) that tells the server what kind of action the client wants to perform:

| HTTP Verb | Real-World Meaning | Primary Purpose | Real-World Example |
| :--- | :--- | :--- | :--- |
| **GET** | *"Give me data!"* | Read / Fetch data | Reading an article on Wikipedia |
| **POST** | *"Create new data!"* | Create a new record | Submitting a new user registration form |
| **PUT** | *"Replace data completely!"* | Full update | Replacing your entire profile details |
| **PATCH** | *"Update partial data!"* | Minor update | Changing only your profile picture |
| **DELETE** | *"Remove data!"* | Delete a record | Deleting a post or closing an account |

## 4. What are HTTP Headers & Cookies?

An HTTP transaction isn't just raw text—it includes metadata attached to requests and responses.

### 1. HTTP Headers
Headers are key-value pairs sent alongside requests and responses that contain metadata.
*   `User-Agent`: Tells the server what browser/OS the client is using (e.g., Chrome on Windows).
*   `Content-Type`: Tells the server what kind of data is being sent (e.g., `application/json` or `text/html`).
*   `Authorization`: Carries secret security tokens to verify logged-in users.

### 2. HTTP Cookies
Browsers are inherently "forgetful" (stateless)—every time you click a link, the server treats you as a brand new stranger!

**Cookies** solve this problem:
*   A **Cookie** is a small text file saved by the browser on your computer.
*   When a user logs in, the server sends back a cookie containing a unique session ID (`session=xyz123`).
*   On every subsequent click, the browser automatically sends that cookie back to the server, so the server remembers: *"Ah, this is Shabber!"*.
