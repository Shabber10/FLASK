## 1. Dynamic Routing & Built-in URL Converters

**Dynamic routing** allows you to pass variables directly inside the URL path, rather than in query strings or post bodies.

### Syntax:
`@app.route('/route/<converter:variable_name>')`

### 🧠 Flask Built-in URL Converters

| Converter | What it Accepts / Matches | Allows Slash (`/`) | Example URL | Converted Data Type |
| :--- | :--- | :--- | :--- | :--- |
| **`string`** | Default text (no slashes) | ❌ No | `/user/jani` | `'jani'` (string) |
| **`int`** | Whole positive integers only | ❌ No | `/square/5` | `5` (int) |
| **`float`** | Floating-point decimal numbers | ❌ No | `/half/8.4` | `8.4` (float) |
| **`path`** | Text **including** forward slashes | ✅ Yes | `/file/images/photo.jpg` | `'images/photo.jpg'` (string) |
| **`uuid`** | Standard 36-char UUID strings | ❌ No | `/item/123e4567-e89b...` | `uuid.UUID` object |

---

### Code Examples for Each Built-in Converter

```python
from flask import Flask

app = Flask(__name__)

# 1. string (Default)
@app.route('/user/<string:name>')
def user(name):
    return f"Hello {name}, welcome to Flask!"

# 2. int (Integer only)
@app.route('/sum/<int:a>/<int:b>')
def sum_numbers(a, b):
    # 'a' and 'b' are automatically converted to integers!
    return f"The sum is: {a + b}"

# 3. float (Decimal numbers)
@app.route('/half/<float:value>')
def half(value):
    return f"Half of {value} is {value / 2}"

# 4. path (Allows slashes)
@app.route('/file/<path:filename>')
def show_file(filename):
    return f"File path is: {filename}"
```

## 2. Dynamic Parameters vs. Query Parameters

| Feature | Query Parameters | Dynamic Path Parameters |
| :--- | :--- | :--- |
| **URL Example** | `/student?name=Jani&age=22` | `/student/Jani/22` |
| **Position in URL** | Appended after `?` | Inside the URL path |
| **Flask Access Method** | `request.args.get('name')` | Function arguments `def student(name, age)` |
| **Best Used For** | Searching, filtering, optional flags | Resource identification (e.g. user ID, product slug) |

## 3. Custom URL Converters

You can create custom URL converters by subclassing `BaseConverter` from `werkzeug.routing`.

### Example: Custom Even Number Converter
```python
from flask import Flask
from werkzeug.routing import BaseConverter

class EvenNumberConverter(BaseConverter):
    def to_python(self, value):
        val = int(value)
        if val % 2 != 0:
            raise ValueError()  # Raises 404 Not Found if number is odd!
        return val

app = Flask(__name__)
# Register converter on url_map
app.url_map.converters['even'] = EvenNumberConverter

@app.route('/even/<even:num>')
def show_even(num):
    return f"Even number verified: {num}"
```
*   Visiting `/even/4` → `Even number verified: 4`
*   Visiting `/even/3` → `404 Not Found` (Rejected by custom converter!)

## 4. Navigation & Redirection: `redirect()` vs `url_for()`

When building routes, you often need to navigate users from one route to another.

### 1. `redirect()`
Tells the browser to immediately navigate to another URL string path.
```python
from flask import redirect

@app.route('/student')
def student():
    return redirect("/course")  # Navigates browser to /course route path
```

### 2. `url_for()`
Generates the URL of a route based on its **Python function name**, not the hardcoded URL string path.
```python
from flask import url_for

# url_for('home') -> generates '/'
# url_for('courses') -> generates '/course'
```

---

## 5. Why `redirect(url_for('function_name'))` is Recommended (Best Practice)

In Flask development, combining `redirect()` and `url_for()` is the industry standard:

```python
return redirect(url_for('function_name'))
```

### ⚖️ Comparison Table: Hardcoded Path vs `redirect(url_for(...))`

| Feature | `redirect('/some-path')` | `redirect(url_for('function_name'))` |
| :--- | :--- | :--- |
| **Hardcoded Path** | ❌ Yes – prone to broken links if route changes | ✅ No – targets function name |
| **Maintenance** | ❌ Must search and update path in 20+ files | ✅ **Update in just ONE place** (the `@app.route` decorator) |
| **Refactoring** | ❌ Fragile | ✅ Refactoring proof |
| **Dynamic Parameters** | ❌ Requires manual string concatenation | ✅ Passes kwargs easily: `url_for('user', name='Jani')` |

### 🔍 Code Proof: Single Place Update Advantage

```python
from flask import Flask, redirect, url_for

app = Flask(__name__)

@app.route('/dashboard-v1')
def dashboard():
    return "Welcome to Dashboard!"

@app.route('/home')
def home():
    # Recommended approach: uses function name 'dashboard'
    return redirect(url_for('dashboard'))
```

If you change the route decorator tomorrow from `/dashboard-v1` to `/user-dashboard-v2`:
```python
@app.route('/user-dashboard-v2')
def dashboard():
    return "Welcome to Dashboard!"
```
✅ **You don't need to change `url_for('dashboard')` anywhere else in your code!** It automatically generates `/user-dashboard-v2`.
