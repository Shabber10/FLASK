## 1. The Perils of Plaintext Password Storage

Storing user passwords in plaintext inside a database is catastrophic. If a database leak occurs (SQL injection or unauthorized backups), all user accounts are compromised immediately across every service where users reuse passwords.

### Why Simple Hashing (e.g. Raw MD5 or SHA-1) Fails
1. **Rainbow Table Attacks**: Pre-computed tables of hashes for millions of common passwords instantly reverse unsalted hashes.
2. **Speed Hazard**: Modern GPUs can compute billions of raw SHA-1 or MD5 hashes per second, making brute-force cracking trivial.

To protect passwords, applications must use **Salted, Key-Stretching Hash Functions** (PBKDF2, Bcrypt, Argon2).

---

## 2. Cryptographic Salt & Key Stretching

```
[ Plaintext Password ] + [ Unique Cryptographic Salt ]
                           |
                           v
              [ PBKDF2 Key Stretching Loop ] (100,000+ Iterations)
                           |
                           v
               [ Secure Hash String Stored in DB ]
```

- **Salt**: A random sequence of bytes generated per password. Prevents Rainbow Table attacks and ensures identical passwords produce completely different hash strings.
- **Key Stretching**: Deliberately slows down the hashing process by executing thousands of iterations, making GPU brute-force attacks computationally infeasible.

## 3. Werkzeug Security Utilities

Flask leverages Werkzeug's `security` module for password management:

```python
from werkzeug.security import generate_password_hash, check_password_hash

# 1. Generating a Password Hash
raw_password = "UserSecretPassword123!"
hashed_pw = generate_password_hash(raw_password, method='pbkdf2:sha256', salt_length=16)

# Output format: method$salt$hash_digest
# Example: "pbkdf2:sha256:600000$a1b2c3d4$e9f8g7..."

# 2. Verifying a Password
is_valid = check_password_hash(hashed_pw, "UserSecretPassword123!") # Returns True
is_invalid = check_password_hash(hashed_pw, "WrongPassword")         # Returns False
```

## 4. Preventing Timing Side-Channel Attacks

Comparing string hashes using standard equality operator `if hash_a == hash_b:` is vulnerable to **Timing Side-Channel Attacks**. 

Standard string comparisons terminate immediately at the first non-matching character. Attackers measure microsecond execution latency differences to deduce characters of secret tokens one byte at a time!

Werkzeug's `check_password_hash()` internally uses `hmac.compare_digest()`, executing a **constant-time string comparison** regardless of where or whether characters match.
