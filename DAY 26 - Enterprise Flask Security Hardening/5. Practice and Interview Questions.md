# Day 26: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from web security basics up to HTTP security headers, Content Security Policies (CSP), input sanitization, and automated static security analysis.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What are HTTP Security Headers?
**Answer**:
HTTP Security Headers are special instructions returned by a web server in response headers that command browsers to enable built-in security features, restricting malicious activities like XSS, Clickjacking, and MIME sniffing.

---

### Q2: What is Content Security Policy (CSP)?
**Answer**:
Content Security Policy (CSP) is an HTTP header (`Content-Security-Policy`) that specifies a whitelist of trusted domain sources from which browsers are permitted to load scripts, stylesheets, images, and fonts. It prevents unauthorized injected scripts from executing.

---

### Q3: What is Cross-Site Scripting (XSS)?
**Answer**:
XSS is a vulnerability where an attacker injects malicious JavaScript code into a web page viewed by other users. When executed in a victim's browser, the script can steal session cookies, access local storage, or perform unauthorized actions.

---

### Q4: What is SQL Injection (SQLi)?
**Answer**:
SQL Injection is a attack where an attacker injects raw SQL code snippets into input fields (like login forms). If concatenated directly into SQL queries, the malicious input alters the query logic to bypass authentication or steal database data.

---

### Q5: What is `Flask-Talisman`?
**Answer**:
`Flask-Talisman` is a Flask extension that automatically hardens web application security by injecting standard HTTP security headers (CSP, HSTS, X-Frame-Options) into every HTTP response.

---

## 🟡 Level 2: Intermediate Questions

### Q6: What is HSTS (`Strict-Transport-Security`) and why is it important?
**Answer**:
HSTS is an HTTP security header that instructs browsers to communicate with your website **exclusively over encrypted HTTPS connections** for a specified duration (e.g. 1 year), protecting users against Man-in-the-Middle eavesdropping and SSL stripping attacks.

---

### Q7: What is Clickjacking and how does `X-Frame-Options: DENY` prevent it?
**Answer**:
Clickjacking tricks users into clicking links on a invisible malicious site overlaid on top of a legitimate site loaded inside a transparent `<iframe>`. Setting `X-Frame-Options: DENY` forbids browsers from rendering your web page inside an `<iframe>` tag anywhere on the internet.

---

### Q8: Why is the Jinja2 `|safe` filter dangerous when rendering user input?
**Answer**:
The `|safe` filter explicitly disables Jinja2's automatic HTML escaping. If applied to untrusted user input, any injected `<script>` tags will render as raw executable code, triggering an XSS attack.

---

### Q9: What does `session_cookie_http_only=True` accomplish in Flask?
**Answer**:
It sets the `HttpOnly` flag on session cookies, preventing client-side JavaScript (e.g. `document.cookie`) from accessing or reading the session cookie. This mitigates cookie theft if an XSS vulnerability exists.

---

### Q10: How does `bleach.clean()` differ from standard HTML escaping (`html.escape()`)?
**Answer**:
*   `html.escape()`: Escapes **ALL** HTML tags into harmless plain text entity strings (`<` -> `&lt;`).
*   `bleach.clean()`: Selectively allows safe formatting tags (like `<b>`, `<i>`, `<a>`) while stripping dangerous tags (like `<script>` and `<iframe>`) and inline event handlers (`onclick=`).

---

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: How do CSP Nonces resolve the inline script restriction without using `'unsafe-inline'`?
**Answer**:
CSP Nonces generate a unique cryptographic one-time random string on the server per request. The server sends this nonce in the `Content-Security-Policy` header (`script-src 'nonce-rAnd0m123'`) and attaches it to trusted inline Jinja2 script tags (`<script nonce="{{ csp_nonce() }}">`). Browsers execute inline scripts ONLY if their nonce attribute matches the HTTP header, blocking injected inline XSS scripts.

---

### Q12: How does SQLAlchemy ORM eliminate SQL Injection risks by design?
**Answer**:
SQLAlchemy ORM separates SQL statement structures from user parameter values. It passes user input as bound parameter placeholders to database drivers (`SELECT * FROM users WHERE name = ?`), ensuring input values are treated purely as data literals rather than executable SQL logic.

---

### Q13: What is Subresource Integrity (SRI) and why should it be used for CDN scripts?
**Answer**:
Subresource Integrity (SRI) is a security feature allowing browsers to verify that scripts fetched from third-party CDNs (e.g. `https://cdn.jsdelivr.net/...`) have not been tampered with. It compares a cryptographic hash (`integrity="sha384-..."`) of the fetched file against an expected hash value.

---

### Q14: How does `Bandit` perform static security analysis on Python code?
**Answer**:
`Bandit` parses Python source code into Abstract Syntax Trees (AST) and scans for common security vulnerabilities, such as hardcoded passwords, use of weak ciphers (MD5), un-parameterized SQL queries, and un-sanitized subprocess calls.

---

### Q15: What is the difference between `SameSite=Strict` and `SameSite=Lax` cookie attributes?
**Answer**:
*   `SameSite=Strict`: Cookies are NEVER sent in cross-site requests (e.g. following a link from external site). Provides maximum CSRF protection.
*   `SameSite=Lax`: Cookies are withheld on cross-site subrequests (like images or frames) but sent when a user navigates to the origin site via top-level link clicks.
