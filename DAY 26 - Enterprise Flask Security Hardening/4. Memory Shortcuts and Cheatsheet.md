## 🔤 Security Hardening Terminology Decoder

| Term | Meaning | Real-World Example |
| :--- | :--- | :--- |
| **Security Headers** | HTTP response headers instructing browsers to enable security features. | Injected by `Flask-Talisman` |
| **CSP** | Content Security Policy (HTTP header whitelisting allowed script/style domains). | `Content-Security-Policy: default-src 'self'` |
| **HSTS** | Strict-Transport-Security (Forces browsers to use HTTPS connections only). | `max-age=31536000; includeSubDomains` |
| **`X-Frame-Options`** | Prevents Clickjacking by forbidding iframe embedding of web pages. | `X-Frame-Options: DENY` |
| **`nosniff`** | Header blocking browsers from sniffing and executing disguised MIME types. | `X-Content-Type-Options: nosniff` |
| **`Flask-Talisman`** | Flask extension automating security header injection and CSP policies. | `Talisman(app, content_security_policy=csp)` |
| **SQLi** | SQL Injection (Hacker injecting malicious SQL commands via inputs). | Prevented by ORM parameterized queries |
| **XSS** | Cross-Site Scripting (Hacker injecting malicious JavaScript into web pages). | Prevented by Jinja2 auto-escaping & CSP |
| **`Bleach`** | Python library sanitizing raw HTML input before database storage. | `bleach.clean(html_text, tags=['b', 'i'])` |
| **`Bandit`** | Static security analysis tool scanning Python code for vulnerabilities. | `bandit -r .` |

## 🧠 Memory Mnemonics

### 1. HTTP Security Headers (`H-E-A-D-E-R-S`)
Remember **H-E-A-D-E-R-S** for security header enforcement:
- **H** -> **HSTS Encryption** (`Strict-Transport-Security`)
- **E** -> **Enforce CSP Policies** (`Content-Security-Policy`)
- **A** -> **Anti-Clickjacking** (`X-Frame-Options: DENY`)
- **D** -> **Deny MIME Sniffing** (`X-Content-Type-Options: nosniff`)
- **E** -> **Enable HttpOnly Cookies** (`session_cookie_http_only=True`)
- **R** -> **Restrict Referrers** (`Referrer-Policy: strict-origin`)
- **S** -> **Secure Session Cookie Flags**

---

### 2. Input Sanitization Defenses (`S-E-C-U-R-E`)
Remember **S-E-C-U-R-E** for input handling:
- **S** -> **Sanitize Raw HTML Input** (`bleach.clean()`)
- **E** -> **Escape Jinja2 Output by Default** (`{{ variable }}`)
- **A** -> **Avoid Raw `|safe` Filter on Untrusted Input**
- **U** -> **Use Parameterized SQL Queries** (SQLAlchemy ORM)
- **R** -> **Restructure CSP Directives** (`script-src 'self'`)
- **E** -> **Execute Bandit Audits** (`bandit -r .`)

## ⚡ Quick-Reference Code Snippets

### 1. Flask-Talisman Setup & CSP Directives
```python
from flask_talisman import Talisman

csp = {
    'default-src': "'self'",
    'script-src': ["'self'", 'https://cdn.jsdelivr.net'],
    'style-src': ["'self'", 'https://fonts.googleapis.com'],
    'object-src': "'none'"
}

talisman = Talisman(
    app,
    content_security_policy=csp,
    force_https=False,              # Set True in Production!
    session_cookie_http_only=True,
    frame_options='DENY'
)
```

### 2. Jinja2 CSP Nonce Injection
```html
<!-- Jinja2 template accessing Talisman csp_nonce() -->
<script nonce="{{ csp_nonce() }}">
    console.log("Trusted inline script!");
</script>
```

### 3. HTML Input Sanitization with Bleach
```python
import bleach

clean_html = bleach.clean(
    user_input,
    tags=['b', 'i', 'u', 'strong', 'a'],
    attributes={'a': ['href']},
    strip=True
)
```
