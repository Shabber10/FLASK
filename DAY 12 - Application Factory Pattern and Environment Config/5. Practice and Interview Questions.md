# Day 12: Practice & Technical Interview Questions

This question bank is divided into **3 progression levels**, starting from factory pattern basics up to 12-Factor App methodology and multi-environment configuration security.

---

## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is the Application Factory Pattern in Flask?
**Answer**:
The Application Factory Pattern is an architectural design pattern where Flask application instances are created dynamically inside a function (typically named `create_app()`), rather than being instantiated globally at import time (`app = Flask(__name__)`).

---

### Q2: Why is putting `app = Flask(__name__)` globally at the top of a file problematic in large projects?
**Answer**:
Global app instantiation causes **Circular Import** errors when sub-modules (like blueprints or route handlers) attempt to import `app` from the main file while the main file is simultaneously trying to import those sub-modules.

---

### Q3: What is an Environment Configuration in web development?
**Answer**:
An Environment Configuration is a set of configuration settings (like `DEBUG`, `SECRET_KEY`, or `SQLALCHEMY_DATABASE_URI`) tailored for a specific development phase (`Development`, `Testing`, `Staging`, `Production`).

---

### Q4: What is a `.env` file and why should it be added to `.gitignore`?
**Answer**:
A `.env` file stores local environment variables (such as secret keys, database passwords, and API credentials). It MUST be added to `.gitignore` to prevent confidential production passwords from being accidentally committed into public or shared Git source repositories.

---

### Q5: How do you load a Python configuration class into a Flask app?
**Answer**:
Pass the class or string object path to `app.config.from_object()`:
```python
app.config.from_object(DevelopmentConfig)
```

---

## 🟡 Level 2: Intermediate Questions

### Q6: How does the Deferred Extension Binding pattern (`db.init_app(app)`) work?
**Answer**:
In deferred extension binding, extension objects (like `db = SQLAlchemy()`) are instantiated globally unattached to any application. Inside `create_app()`, calling `db.init_app(app)` binds the extension instance to the active Flask application object. This completely decouples extensions from global app instances.

---

### Q7: Why is `sqlite:///:memory:` ideal for a `TestingConfig` class?
**Answer**:
`sqlite:///:memory:` creates an in-memory database in RAM. It executes queries blazingly fast and is completely destroyed when the application context terminates, ensuring that every unit test suite runs against a completely clean database.

---

### Q8: How does `python-dotenv` integrate with Flask CLI commands?
**Answer**:
When `python-dotenv` is installed, running `flask run` or any `flask` CLI command automatically loads environment variables defined in `.env` and `.flaskenv` into `os.environ` before initializing the application.

---

### Q9: How can you dynamically select a configuration class based on an environment variable?
**Answer**:
Map string names to Config classes inside `create_app()`:

```python
config_map = {
    'dev': DevelopmentConfig,
    'test': TestingConfig,
    'prod': ProductionConfig
}
env = os.environ.get('FLASK_CONFIG', 'dev')
app.config.from_object(config_map.get(env, DevelopmentConfig))
```

---

### Q10: What is the difference between `DEBUG = True` and `TESTING = True`?
**Answer**:
*   `DEBUG = True`: Enables the Werkzeug interactive browser debugger and auto-reloader for local development.
*   `TESTING = True`: Disables error logging and enables Flask's test client error propagation so automated unit test frameworks (like `pytest`) can capture exceptions accurately.

---

## 🔴 Level 3: Advanced & Enterprise Questions

### Q11: How does the Application Factory Pattern support concurrent application instances in WSGI servers or test runners?
**Answer**:
Because `create_app()` returns a new `Flask` instance each time it is invoked, WSGI servers or test runners can instantiate multiple independent copies of the application concurrently with different configuration parameters in the same Python process without state leakage.

---

### Q12: How does the Application Factory Pattern align with the 12-Factor App methodology (III. Config)?
**Answer**:
The 12-Factor App methodology mandates strict separation of config from code. The Application Factory pattern satisfies this by reading all environment-specific variables (`DATABASE_URL`, `SECRET_KEY`) from system environment variables (`os.environ`) at runtime, allowing the exact same codebase to run across Dev, Staging, and Prod without code changes.

---

### Q13: What happens if an extension method requires `app` during global instantiation?
**Answer**:
Legacy extensions that do not support `.init_app()` cannot be used cleanly with the factory pattern. Modern Flask extensions follow the standard extension API specification requiring an unattached `__init__()` and an `init_app(app)` method.

---

### Q14: How do you handle `current_app` inside blueprint view functions when using an Application Factory?
**Answer**:
Instead of importing global `app`, import `current_app` from `flask`. `current_app` is a context local proxy pointing to the active Flask application handling the current HTTP request context.

---

### Q15: How should production `SECRET_KEY` settings be generated and secured?
**Answer**:
Production secret keys should be generated using cryptographically secure random bytes (e.g. `python -c "import secrets; print(secrets.token_hex(32))"`), stored in secret manager services (like AWS Secrets Manager, HashiCorp Vault, or GCP Secret Manager), and injected into the container's environment variables at runtime.
