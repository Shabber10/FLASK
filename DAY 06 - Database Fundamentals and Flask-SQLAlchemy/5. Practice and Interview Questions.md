## 🟢 Level 1: Absolute Beginner Questions

### Q1: What is `mysql-connector-python` and why is it needed in Flask applications?
**Answer**:
`mysql-connector-python` is the official Python database driver provided by Oracle. It acts as a bridge allowing Python and Flask apps to connect to a MySQL server, execute SQL statements, and retrieve query results over network port 3306.

---

### Q2: Why must you call `conn.commit()` after executing an `INSERT`, `UPDATE`, or `DELETE` query?
**Answer**:
`mysql-connector-python` runs inside transaction mode by default. Executing an `INSERT`, `UPDATE`, or `DELETE` stages changes in temporary memory. Calling `conn.commit()` permanently writes those changes to the MySQL database disk. If `conn.commit()` is not called, all changes are discarded when the connection closes!

---

### Q3: What is the difference between `cursor.fetchall()` and `cursor.fetchone()`?
**Answer**:
*   `cursor.fetchall()`: Retrieves **all** remaining matching rows from the query result set as a Python list.
*   `cursor.fetchone()`: Retrieves the **next single row** from the query result set (or `None` if no rows match).

## 🟡 Level 2: Intermediate Questions

### Q4: Why is `cursor = conn.cursor(dictionary=True)` recommended when building Flask web apps?
**Answer**:
By default, a standard cursor returns rows as tuples `(1, 'Alice', 'alice@example.com')`. Setting `dictionary=True` causes the cursor to return rows as Python dictionaries `{'id': 1, 'first_name': 'Alice', 'email': 'alice@example.com'}`. This allows Flask developers to access fields by column name (`row['email']`) and pass data seamlessly to Jinja2 HTML templates!

---

### Q5: Explain how `%s` placeholders prevent SQL Injection attacks.
**Answer**:
When using `%s` placeholders (e.g. `cursor.execute("SELECT * FROM users WHERE name = %s", (user_input,))`), `mysql-connector-python` sends the SQL template and user inputs to MySQL separately. The database engine escapes and treats `user_input` purely as a literal string value, preventing attackers from injecting malicious SQL command fragments (e.g., `' OR '1'='1`).

## 🔴 Level 3: Advanced & Enterprise Questions

### Q6: What is Connection Pooling in `mysql-connector-python`, and why is it essential in high-traffic Flask apps?
**Answer**:
Opening a new TCP database connection on every HTTP request creates latency and exhausts MySQL server resources under heavy load. A **Connection Pool** (`mysql.connector.pooling.MySQLConnectionPool`) maintains a reusable pool of open connections in memory. Flask workers request a connection from the pool, execute queries, and return the connection to the pool when finished, drastically increasing throughput.

---

### Q7: How do you handle database errors and transaction rollbacks using `mysql.connector.Error`?
**Answer**:

```python
import mysql.connector

def safe_db_transaction():
    conn = None
    try:
        conn = get_db_connection()
        cursor = conn.cursor()
        cursor.execute("UPDATE accounts SET balance = balance - 100 WHERE id = 1")
        cursor.execute("UPDATE accounts SET balance = balance + 100 WHERE id = 2")
        conn.commit() # Commit atomic transaction
    except mysql.connector.Error as err:
        if conn:
            conn.rollback() # Revert all changes if any error occurs!
        print(f"Transaction failed and rolled back: {err}")
    finally:
        if conn and conn.is_connected():
            cursor.close()
            conn.close()
```
