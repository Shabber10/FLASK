# Day 08: Relationships & Cascade Operations

Welcome to **Day 08** of the 30-Day Enterprise Flask Masterclass! Today, we explore relationship mappings in SQLAlchemy: One-to-Many, Many-to-Many association tables, Foreign Key constraints, `backref` vs `back_populates`, and cascade delete behavior.

## 1. Relational Mapping Patterns

SQLAlchemy models mirror relational database foreign keys through Python object references:

```
+-------------------+                      +-------------------+
|      Author       |  1                N  |       Post        |
|  - id (PK)        | <------------------- |  - id (PK)        |
|  - name           |                      |  - author_id (FK) |
|  - posts (rel)    |                      |  - title          |
+-------------------+                      +-------------------+
```

---

## 2. One-to-Many & One-to-One Mappings

### One-to-Many Relationship
Declare a `db.ForeignKey` on the child model and a `db.relationship` on the parent model:

```python
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()

class Author(db.Model):
    __tablename__ = 'authors'
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(100), nullable=False)
    
    # One-to-Many: Author has multiple posts
    # 'backref' automatically adds an `.author` attribute to Post instances
    posts = db.relationship('Post', backref='author', lazy=True)

class Post(db.Model):
    __tablename__ = 'posts'
    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(200), nullable=False)
    author_id = db.Column(db.Integer, db.ForeignKey('authors.id'), nullable=False)
```

### One-to-One Relationship
Add `uselist=False` to the parent relationship:

```python
class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    # One-to-One: Each user has exactly one UserProfile instance
    profile = db.relationship('UserProfile', backref='user', uselist=False)

class UserProfile(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    bio = db.Column(db.Text)
    user_id = db.Column(db.Integer, db.ForeignKey('user.id'), unique=True)
```

## 3. Many-to-Many Relationships

Many-to-Many relationships require a third table: the **Junction / Association Table**.

```python
# Association Table linking Posts and Tags
post_tags = db.Table('post_tags',
    db.Column('post_id', db.Integer, db.ForeignKey('posts.id'), primary_key=True),
    db.Column('tag_id', db.Integer, db.ForeignKey('tags.id'), primary_key=True)
)

class Post(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(200), nullable=False)
    
    # Many-to-Many relationship pointing to Tag via 'secondary' parameter
    tags = db.relationship('Tag', secondary=post_tags, backref=db.backref('posts', lazy='select'))

class Tag(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(50), unique=True, nullable=False)
```

## 4. Understanding Cascade Operations

Cascade settings instruct SQLAlchemy how to propagate operations (saves, updates, deletions) from parent models to child entities.

```python
class Post(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    # Cascade: If Post is deleted or a Comment is removed from post.comments list, delete the Comment from DB
    comments = db.relationship('Comment', backref='post', cascade='all, delete-orphan')

class Comment(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    body = db.Column(db.Text, nullable=False)
    post_id = db.Column(db.Integer, db.ForeignKey('post.id', ondelete='CASCADE'), nullable=False)
```

### Cascade Options Matrix

| Cascade Setting | Description |
| :--- | :--- |
| `save-update` (default) | Automatically attaches new child objects added to a relationship to the active `db.session`. |
| `merge` | Propagates `db.session.merge()` calls from parent to children. |
| `delete` | When parent is passed to `db.session.delete(parent)`, automatically issue SQL `DELETE` for all children. |
| `delete-orphan` | Automatically deletes a child entity from DB when it is removed from the parent's collection list (e.g. `post.comments.remove(c1)`). |
| `all` | Short-hand for `save-update, merge, refresh-expire, expunge, delete`. |

## 5. `backref` vs. `back_populates`

- **`backref`**: Declares reciprocal relationship automatically on the target model in a single string line (legacy/convenient).
- **`back_populates`**: Explicitly requires declaring `db.relationship` on **both** models, explicitly pointing to each other (SQLAlchemy 2.0 recommended for type hints and clarity).

```python
# Modern back_populates Example
class Parent(db.Model):
    children = db.relationship('Child', back_populates='parent')

class Child(db.Model):
    parent = db.relationship('Parent', back_populates='children')
```
