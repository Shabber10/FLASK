## 1. One-to-Many & One-to-One Mappings

### One-to-Many Relationship
Declare `db.ForeignKey` on the child model and `db.relationship` on the parent model:

```python
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()

class Author(db.Model):
    __tablename__ = 'authors'
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(100), nullable=False)
    
    # One-to-Many: Author has multiple posts
    # 'backref' automatically adds an '.author' attribute to Post instances
    posts = db.relationship('Post', backref='author', lazy=True)

class Post(db.Model):
    __tablename__ = 'posts'
    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(200), nullable=False)
    author_id = db.Column(db.Integer, db.ForeignKey('authors.id'), nullable=False)
```

---

### One-to-One Relationship
To restrict a One-to-Many relationship so that a parent holds at most **one** child instance, add `uselist=False` to `db.relationship` and `unique=True` to `db.ForeignKey`:

```python
class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    # uselist=False instructs SQLAlchemy to treat user.profile as a single object, not a list
    profile = db.relationship('UserProfile', backref='user', uselist=False)

class UserProfile(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    bio = db.Column(db.Text)
    user_id = db.Column(db.Integer, db.ForeignKey('user.id'), unique=True, nullable=False)
```

## 2. Many-to-Many Relationships

Many-to-Many relationships require a third table: the **Junction / Association Table**:

```python
# Association Table linking Posts and Tags
post_tags = db.Table('post_tags',
    db.Column('post_id', db.Integer, db.ForeignKey('posts.id', ondelete='CASCADE'), primary_key=True),
    db.Column('tag_id', db.Integer, db.ForeignKey('tags.id', ondelete='CASCADE'), primary_key=True)
)

class Post(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(200), nullable=False)
    
    # Point to Tag model using 'secondary=post_tags' parameter
    tags = db.relationship('Tag', secondary=post_tags, backref=db.backref('posts', lazy='dynamic'))

class Tag(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(50), unique=True, nullable=False)
```

## 3. Understanding Cascade Operations

Cascade settings instruct SQLAlchemy how to propagate operations (`add`, `delete`, `update`) from parent models down to child records.

```python
class Post(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    # Cascade: If Post is deleted OR a Comment is removed from post.comments list, delete Comment from DB!
    comments = db.relationship('Comment', backref='post', cascade='all, delete-orphan')

class Comment(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    body = db.Column(db.Text, nullable=False)
    post_id = db.Column(db.Integer, db.ForeignKey('posts.id', ondelete='CASCADE'), nullable=False)
```

### Cascade Options Matrix

| Cascade Option | Description |
| :--- | :--- |
| `save-update` (Default) | Automatically stages new child objects attached to parent in active `db.session`. |
| `merge` | Propagates `db.session.merge()` calls from parent to children. |
| `delete` | Automatically issues SQL `DELETE` for children when `db.session.delete(parent)` is called. |
| `delete-orphan` | Automatically deletes child record from DB when removed from parent list (e.g. `post.comments.remove(c1)`). |
| `all` | Short-hand for `save-update, merge, refresh-expire, expunge, delete`. |

## 4. `backref` vs. `back_populates`

SQLAlchemy provides two ways to declare bidirectional relationships between models:

#### ⚖️ `backref` vs `back_populates` Comparison Table

| Feature | `backref` (Legacy Shortcut) | `back_populates` (SQLAlchemy 2.0 Standard) |
| :--- | :--- | :--- |
| **Declaration** | Declared on 1 model only; dynamically injects reverse attribute on target | Explicitly declared on **BOTH** models pointing to each other by name |
| **Type Checking** | Limited static type analysis & IDE autocomplete for reverse attribute | Full IDE autocomplete & static type hints on both models |
| **Clarity** | Concise 1-liner, but implicitly creates hidden attributes | Explicit self-documenting code showing exact inverse attributes |
| **SQLAlchemy Standard** | Legacy (1.x shortcut) | **Best Practice (2.0+ Standard)** |

```python
# Modern SQLAlchemy 2.0 Standard: back_populates Example
class Parent(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    # Points explicitly to 'parent' attribute on Child
    children = db.relationship('Child', back_populates='parent')

class Child(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    parent_id = db.Column(db.Integer, db.ForeignKey('parent.id'))
    # Points explicitly to 'children' attribute on Parent
    parent = db.relationship('Parent', back_populates='children')
```
