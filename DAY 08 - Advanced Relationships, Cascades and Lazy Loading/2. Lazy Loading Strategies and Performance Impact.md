# Day 08 - Module 2: Lazy Loading Strategies & Performance Tuning

Welcome to **Module 2** of Day 08! Now that we know how to define relationships, let's learn how SQLAlchemy loads connected data into memory and how to eliminate the **N+1 Query Problem** using Eager Loading!

---

## 1. The N+1 Query Problem Deep Dive

The **N+1 Query Problem** occurs when an application fetches $N$ parent records in 1 initial query, and then accesses a lazily-loaded relationship attribute on each parent inside a loop, triggering $N$ secondary database queries:

```python
# Query 1: Fetch 100 Posts
posts = db.session.execute(db.select(Post).limit(100)).scalars().all()

for post in posts:
    # Triggers 1 SEPARATE SELECT query per post to fetch author! (100 extra queries!)
    print(post.author.name)

# Total DB Queries Executed: 1 + 100 = 101 queries!
```

If your web page has 1,000 active users per minute, 101 queries per request will crush your database server!

---

## 2. SQLAlchemy Loading Strategies Matrix

Configure relationship loading behavior globally via `lazy=STRATEGY` on `db.relationship`, or override per-query using `options()`.

| Loading Strategy | Generated SQL Pattern | Best Use Case |
| :--- | :--- | :--- |
| `lazy='select'` (Default) | Emits secondary `SELECT` on attribute access | Single object lookups where relationship is rarely accessed. |
| `lazy='joined'` | Performs SQL `LEFT OUTER JOIN` in primary query | One-to-One or Many-to-One scalar relationships. |
| `lazy='subquery'` | Issues 2nd `SELECT` using subquery of parent IDs | Legacy collections (Can produce poor performance on large datasets). |
| `lazy='selectin'` | Issues 2nd `SELECT` using `WHERE parent_id IN (...)` | **One-to-Many collections (Best overall performance!)** |
| `lazy='dynamic'` | Returns a `Query` object instead of loading collection | Huge collections (10,000+ items) requiring filtering/paging. |

---

## 3. Explicit Eager Loading (`selectinload` & `joinedload`)

Override relationship loading defaults per-query using `sqlalchemy.orm` options:

```python
from sqlalchemy.orm import selectinload, joinedload

# 1. Eager Load Collection using selectinload (2 SQL queries total for 100 posts)
stmt = db.select(Post).options(selectinload(Post.comments)).limit(100)
posts = db.session.execute(stmt).scalars().all()

for p in posts:
    # Fast: Comments already pre-loaded into memory!
    print(len(p.comments))

# 2. Eager Load Scalar Relationship using joinedload (1 SQL JOIN query total)
stmt = db.select(Post).options(joinedload(Post.author)).where(Post.id == 1)
post = db.session.execute(stmt).scalar_one()
```

## 4. Dynamic Loading for Massive Collections (`lazy='dynamic'`)

When a relationship contains thousands of records (e.g. `user.followers`), loading all items into a Python list exhausts RAM memory. `lazy='dynamic'` returns a query statement object instead of a list:

```python
class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    # Returns query object instead of list
    posts = db.relationship('Post', lazy='dynamic')

# Filter and paginate directly on the relationship attribute!
user = db.session.get(User, 1)
recent_posts = user.posts.filter(Post.views > 1000).order_by(Post.created_at.desc()).limit(5).all()
```
