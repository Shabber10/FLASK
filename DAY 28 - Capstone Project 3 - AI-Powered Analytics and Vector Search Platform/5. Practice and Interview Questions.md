# Day 28: Practice & Technical Interview Questions

---

### Q1: What is Retrieval-Augmented Generation (RAG) and why is it preferred over fine-tuning LLMs for domain knowledge?
**Answer**:
RAG grounds LLM responses by retrieving relevant document context from a vector database before generating answers. 

RAG is preferred over fine-tuning because:
1. **Dynamic Updates**: Knowledge base documents can be added/updated instantly without retraining expensive model weights.
2. **Eliminates Hallucinations**: Gives the LLM verifiable source context to cite.
3. **Data Security**: Enforces document-level permissions during retrieval.

---

### Q2: What are Vector Embeddings and how is text represented mathematically?
**Answer**:
Vector embeddings are dense floating-point arrays (e.g. 1536 dimensions) produced by neural network embedding models. They map text into a high-dimensional vector space where semantically similar concepts are positioned near each other regardless of exact keyword matches.

---

### Q3: How do Cosine Similarity and Euclidean Distance differ for vector search?
**Answer**:
- **Cosine Similarity**: Measures the cosine of the angle between two vectors, focusing strictly on direction rather than magnitude. Preferred for text embeddings normalized to unit length.
- **Euclidean Distance (L2)**: Measures the straight-line spatial distance between vector endpoints. Sensitive to vector magnitude differences.

### Q4: How do you implement real-time token streaming in Flask using Server-Sent Events (SSE)?
**Answer**:
Use `Response(stream_with_context(generator()), mimetype='text/event-stream')`. The generator yields text chunks formatted in SSE protocol syntax: `f"data: {chunk}\n\n"`.

---

### Q5: What does the `X-Accel-Buffering: no` header do when serving streaming Flask responses behind Nginx?
**Answer**:
By default, Nginx buffers upstream proxy responses until a full buffer (4KB) is filled before sending data to the client. Setting `X-Accel-Buffering: no` instructs Nginx to bypass proxy buffering and flush streaming SSE chunks immediately to the browser client.

---

### Q6: What is HNSW (Hierarchical Navigable Small World) indexing in vector databases?
**Answer**:
HNSW is a graph-based indexing algorithm used by vector databases (`pgvector`, Qdrant, ChromaDB) to perform Approximate Nearest Neighbor (ANN) search. It organizes vectors into multi-layer skip-graph structures, reducing vector search time complexity from $O(N)$ brute-force calculation down to $O(\log N)$.

---

### Q7: Why is `stream_with_context()` required when streaming Flask responses?
**Answer**:
Standard generator functions executed inside `Response()` run outside Flask's WSGI application context. Wrapping the generator in `stream_with_context(gen())` ensures Flask's `g`, `request`, and database session proxies remain accessible while streaming chunks.

---

### Q8: What is Document Chunking in RAG pipelines and why is overlap important?
**Answer**:
Large documents must be split into smaller text chunks (e.g. 500 tokens) because embedding models and LLM context windows have maximum token limits. 

Adding an **overlap** (e.g. 50 tokens) between consecutive chunks ensures semantic context across sentence or paragraph boundaries is not severed.

---

### Q9: How does `pgvector` store vector embeddings inside PostgreSQL tables?
**Answer**:
`pgvector` adds a `vector(n)` data type to PostgreSQL:

```sql
CREATE TABLE document_chunks (
    id SERIAL PRIMARY KEY,
    content TEXT,
    embedding vector(1536)
);
```

Queries use `<=>` for cosine distance: `ORDER BY embedding <=> query_vector LIMIT 5`.

---

### Q10: How do you handle long-running background embedding generation tasks for large document uploads?
**Answer**:
Large document uploads should accept the file synchronously and return `202 Accepted` immediately, offloading document chunking and vector embedding generation to an asynchronous **Celery worker task**.
