# Day 28: RAG Pipelines, Vector DBs & Streaming AI Responses

In this section, we examine Retrieval-Augmented Generation (RAG) architecture, document chunking, prompt grounding, and streaming responses with Server-Sent Events (SSE).

## 1. Retrieval-Augmented Generation (RAG) Architecture

Large Language Models (LLMs) suffer from hallucinations and lack access to private enterprise documents. **RAG** grounds LLM responses by retrieving relevant document context from a vector database before generating the answer:

```
[ User Query: "What is our company's refund policy?" ]
                           |
                           v
              Generate Query Vector Embedding
                           |
                           v
        Search Vector DB via Cosine Similarity
                           |
                           v
     Retrieved Relevant Context Chunk:
     "Customers may request full refunds within 30 days..."
                           |
                           v
               Construct Grounded LLM Prompt:
               "Context: Customer refunds within 30 days.
                Question: What is our refund policy?"
                           |
                           v
                    LLM (OpenAI / Gemini)
                           |
                           v
          Streaming Answer -> Browser UI (SSE)
```

## 2. Streaming LLM Responses in Flask (Server-Sent Events)

Waiting 5-10 seconds for an LLM to generate a complete response causes high user latency. 

Flask supports real-time token-by-token streaming responses using **Server-Sent Events (SSE)** via `Response(stream_generator(), mimetype='text/event-stream')`:

```python
import time
from flask import Flask, Response, request, stream_with_context

app = Flask(__name__)

def generate_llm_stream(prompt):
    """Generator function yielding text chunks as they arrive from LLM."""
    tokens = ["Retrieving ", "context...", " According ", "to ", "our ", "policy, ", "refunds ", "are ", "valid ", "for ", "30 ", "days."]
    for token in tokens:
        time.sleep(0.1) # Simulate streaming network latency from OpenAI
        # Format as SSE event stream (data: <payload>\n\n)
        yield f"data: {token}\n\n"

@app.route('/api/chat/stream', methods=['POST'])
def chat_stream():
    prompt = request.json.get('prompt', '')
    # Wrap generator in stream_with_context to keep Flask request context open!
    return Response(
        stream_with_context(generate_llm_stream(prompt)),
        mimetype='text/event-stream',
        headers={
            'Cache-Control': 'no-cache',
            'X-Accel-Buffering': 'no' # Prevents Nginx from buffering SSE streams!
        }
    )
```

---

## 3. Nginx Buffering Prevention (`X-Accel-Buffering`)

When serving Server-Sent Events (SSE) behind Nginx, Nginx's default proxy response buffer intercepts token chunks until the buffer is full (usually 4KB), breaking real-time token streaming.

Set header `X-Accel-Buffering: no` in the Flask `Response` object to force Nginx to flush streaming SSE data immediately!
